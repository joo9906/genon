# onprem/docs — 문서 색인

`onprem/` 관련 문서가 어디에 있고 **무엇이 정본인지** 한 곳에서 본다.

## 배치 규칙 — 문서를 새로 쓸 때 어디에 두나

| 성격 | 위치 | 이유 |
|---|---|---|
| 그 디렉토리를 열었을 때 **처음 읽어야 할 것** | 해당 디렉토리의 `README.md` | 배포 단위·도구 폴더의 진입 문서. 자리를 옮기면 못 찾는다 |
| 한 기능의 **설계 심화** (구조·데이터 흐름·결정 근거) | `onprem/docs/<SFR>_*.md` | 길고, 코드보다 천천히 바뀌고, 여러 디렉토리에 걸친다 |
| **개발 규칙**(가이드 조항, 영역별 계약) | `genos-project/docs/GENOS_RULES.md` | 저장소 전체의 규칙 원본. 여기 복사하지 않는다 |
| 저장소 전체의 작업 지침 | 루트 `CLAUDE.md` | 어느 디렉토리를 고칠지 판단하는 진입 문서 |

**중복 금지.** 같은 사실을 두 곳에 적으면 한쪽이 낡는다. 배포·환경변수·운영 규약은
`onprem/README.md` 가 정본이고, 이 폴더의 문서는 거기를 **참조**한다.

## 이 폴더의 문서

| 문서 | 다루는 것 |
|---|---|
| [SFR-006_architecture.md](SFR-006_architecture.md) | 템플릿 채우기 **설계·흐름의 정본** — 두 영역(02/03) 배치, 모듈 지도(계층), 세 가지 흐름(대화 한 턴 / 다운로드 / 화면 편집), 채울 자리 인식, 서식 명세, 본문 블록, 글다듬이, 상태 저장, 오류 코드, 검증, 가드레일 설계, 알려진 공백 |
| [hwpx_library_adoption.md](hwpx_library_adoption.md) | **python-hwpx 도입 판단과 적용 범위** — `hwpx-genon` 대조 결과(무엇을 남기고 무엇을 가져왔나), 거기서 나온 결함 둘(파트 XML 선언·누름틀 안내문), 개봉 안전 게이트·넘침 측정·eval 교차검증의 설계 근거. **006 은 pip 의존이 아니라 벤더 사본이고 재개봉 검사는 포기했다**(2026-08-10) — 그 판단의 근거가 §6·§4-2 에 있다. 006·FAQ·eval 에 걸친다 |

`onprem/README.md` 의 SFR-006 절은 **배포·운영에 필요한 것만** 담고(환경변수·엔드포인트
표·배포 전제) 설계 근거는 위 문서를 가리킨다. 같은 사실을 두 곳에 적지 않는다.

## 이 폴더 밖의 문서 — 먼저 읽어야 할 순서

1. **루트 `CLAUDE.md`** — 저장소 구성, 우선순위(`onprem/` > `SFR-0xx/` > `genos-project/source/`),
   SFR-006 설계 결정 요약, 남은 일
2. **`genos-project/docs/GENOS_RULES.md`** — GenOS 개발가이드 강제 규칙 (영역별 시그니처,
   오류 코드 체계, 코드 서빙 배포 계약). **수정하려면 개발가이드 원문을 근거로 든다**
3. **`onprem/README.md`** — 배포 단위 3개, 옮기는 순서, 환경변수, 로깅 규약, 코드서빙 실행
4. **`onprem/eval/README.md`** — 평가지표 MCP 서버 (배포 단위 아님)
5. **`onprem/test/README.md`** — 배포 계약 점검 스크립트 (배포 단위 아님)

기능별 원본 개발 사본의 문서는 `SFR-018/README.md` 에 있다.
