## 1. 한 눈에 보기

관리자가 hwpx 양식을 올려 두면, 사용자는 **대화만으로** 그 양식을 채운 초안을 받는다.

```
관리자                사용자
  │                    │
  │ 양식 등록           │ "제목은 8월 실적 보고고, 담당자는 왕주영이야"
  ▼                    ▼
[템플릿 볼륨] ────→ [대화 (02)] ──값 누적──→ [Redis 세션]
                        │                        │
                        │ 매 턴 현황표+미리보기    │
                        ▼                        ▼
                     채팅 화면            [다운로드 (03)] ──→ 초안.hwpx
```

핵심 성질 넷:

| 성질 | 뜻 |
|---|---|
| **판정은 코드가 한다** | LLM 은 "발화에서 값 뽑기" 까지만. 무엇이 채워졌는지, 무엇을 받아들일지는 전부 결정적 코드가 정한다 |
| **부분 초안 허용** | 다 못 채워도 파일을 받을 수 있다. 빈 항목은 `제목:` 상태로 남고, 무엇이 비었는지 응답 헤더로 알린다 |
| **서식은 LLM 이 만지지 않는다** | 글자 크기·폰트 id·`itemCnt` 는 한 글자만 틀려도 한/글이 문서를 못 연다. 전부 코드가 계산한다 |
| **침묵 처리 금지** | 기각·실패·상한 초과는 반드시 사용자 답변과 로그 양쪽에 건수가 남는다 |

## 2. 배치 — 두 개의 GenOS 영역

GenOS 는 기능을 **영역(area)** 으로 나눈다. SFR-006 은 두 영역에 걸쳐 있고, 둘은 **다른
pod 에서 돈다.**

```
┌─────────────────────────────┐        ┌─────────────────────────────┐
│  영역 02 — 워크플로우 pod     │        │  영역 03 — 코드 서빙 pod      │
│                             │        │                             │
│  run_chat.run(data)         │        │  FastAPI  main.py           │
│  · 대화로 값 수집             │        │  · 다운로드 버튼이 부른다      │
│  · async generator          │        │  · 템플릿 등록/삭제(관리자)     │
│  · token… → result 1회       │        │  · 미리보기·직접 편집          │
└──────────┬──────────────────┘        └──────────┬──────────────────┘
           │                                      │
           └──────────┬───────────────────────────┘
                      ▼
        ┌──────────────────────────────┐
        │  공유 인프라                   │
        │  · Redis  (세션 + 템플릿 색인)  │
        │  · 볼륨   (템플릿 hwpx 파일)    │
        └──────────────────────────────┘
```

**두 pod 가 반드시 같은 `REDIS_URL` 과 같은 템플릿 볼륨을 봐야 한다.** 대화가 모은 값을
다운로드가 읽는 유일한 통로가 Redis 세션이기 때문이다.

> **왜 전역 dict 가 아니라 Redis 인가**
> GenOS 는 워크플로우 단계에 이전 대화를 자동으로 넣어 주지 않는다(`genos_state.session_id`
> 만 준다). 참고용으로 받은 실제 운영 코드(`genos_files/bridge.py`)는 전역 dict 로 세션을
> 들고 있는데, **레플리카가 2개면 그 순간 깨진다** — 다음 턴이 다른 pod 로 가면 값이 없다.
> 규칙 문서 D.2 가 금지한 패턴이고, 우리는 Redis 로 뺐다.

## 3. 모듈 지도

**계층이 셋이다.** 위층은 아래층을 알지만 아래층은 위층을 모른다.

```
┌── 진입 계층 ──────────────────────────────────────────────────────┐
│  run_chat.py       대화 한 턴 (02) — GenOS 계약(run/generator)      │
│  main.py           HTTP 라우팅 (03) — 요청↔응답 변환만              │
└───────────────────────────────────────────────────────────────────┘
        │                                    │
┌── 조립 계층 ──────────────────────────────────────────────────────┐
│  chat_state.py     한 턴의 상태 전이 (읽기·병합·미리보기)            │
│  chat_reply.py     채팅 답변 문구 조립                              │
│  session_view.py   세션+색인 → 화면 payload, 저장                   │
│  document.py       ★ 문서 조립 파이프라인 (채우기→서식→블록)         │
│  template_store.py 템플릿 볼륨 입출력 + 경로 검증                    │
│  api_errors.py     ApiError 예외 → HTTP 응답                       │
└───────────────────────────────────────────────────────────────────┘
        │
┌── 도메인 계층 (GenOS·HTTP·Config 를 모른다) ───────────────────────┐
│  hwpx_fields.py    채울 자리 찾기·값 쓰기  ← hwpx 판정의 정본        │
│  hwpx_style.py     서식 명세 → charPr                              │
│  hwpx_blocks.py    본문 블록 문단 복제                              │
│  hwpx_markdown.py  미리보기 렌더링                                  │
│  field_judge.py    LLM 응답 검증 (화이트리스트)                      │
└───────────────────────────────────────────────────────────────────┘
        │
┌── 인프라 계층 ────────────────────────────────────────────────────┐
│  session_store.py  Redis 세션      template_index.py  Redis 색인    │
│  redis_client.py   연결 공유       llm.py   Gateway 호출            │
│  logging_utils.py / error_codes.py                                   │
└───────────────────────────────────────────────────────────────────┘
```

### 이 배치에서 지켜지는 규칙

- **`hwpx_fields.py` 가 hwpx 판정의 정본이다.** "무엇이 본문인가"(`section_order`),
  "이 문단이 직접 가진 텍스트는 무엇인가"(`own_nodes`), "중괄호 슬롯인가"(`slot_occurrences`)
  를 다른 모듈이 다시 구현하지 않는다. 두 벌이 되면 **채우는 자리와 서식 거는 자리가
  어긋난다.**
- **도메인 계층은 `Config` 를 읽지 않는다.** 배포 스위치(`SLOT_FIELDS`, `BODY_BLOCKS` …)는
  조립 계층인 `document.py` 가 한 번만 읽는다. 그래서 도메인 함수는 인자만으로 재현된다.
- **오류는 `ApiError` 하나로 올라간다.** 예전에는 헬퍼마다 `(값, 오류응답)` 튜플을 돌려주고
  호출부가 `if error: return error` 를 적었는데, 엔드포인트 12개 × 헬퍼 8개라 같은 3줄이
  열다섯 군데 반복됐다. 문제는 길이가 아니라 **빠뜨려도 조용하다는 것**이다 — 한 번
  빠뜨리면 `None` 을 들고 진행해 엉뚱한 자리에서 500 이 난다. 예외는 그 실수를 불가능하게
  만든다.

## 4. 흐름 ① 대화 한 턴

`run_chat.run(data)` 하나가 아래를 전부 한다. **async generator 라서 중간에 `return` 으로
빠져나갈 수 없고**, 어떤 경우에도 마지막에 `result` 를 한 번 내보내야 한다(가이드 5.2).

```
사용자 발화
   │
 ┌─┴─ 1. 입력 정규화 ─────────────────────────────────────────────┐
 │    data 가 문자열로 올 수도 있다 (018 과 동일 패턴)              │
 │    question / overrideConfig.vars / genos_state.session_id     │
 └─┬──────────────────────────────────────────────────────────────┘
   │
 ┌─┴─ 2. 세션 로드 + 템플릿 확정 ──────────────────────────────────┐
 │    template_id = 이번 턴 변수 > 세션 저장값                      │
 │    chat_state.load_context()  → 파일 읽기 + 색인(캐시)          │
 │    chat_state.restore_state() → 값·블록을 지금 템플릿에 맞게 거름 │
 └─┬──────────────────────────────────────────────────────────────┘
   │
 ┌─┴─ 3. LLM 추출 ────────────────────────────────────────────────┐
 │    프롬프트 = 항목 목록 + 지금까지 값 + 본문 서식 목록            │
 │               + 현재 본문 블록(번호) + 발화                      │
 │    응답     = {updates, clears, blocks, block_clears}          │
 └─┬──────────────────────────────────────────────────────────────┘
   │
 ┌─┴─ 4. 코드가 판정 (field_judge) ────────────────────────────────┐
 │    · 항목명이 템플릿에 있는가?          없으면 기각 + 건수 노출    │
 │    · 빈 값은?                          기각 (지움은 clears 로만) │
 │    · updates·clears 에 같은 항목?      수정 채택 + 로그          │
 │    · 블록 style_ref 가 목록에 있는가?   없으면 기본 서식 + 사유    │
 │    · block_clears 번호가 범위 안인가?   벗어나면 기각            │
 └─┬──────────────────────────────────────────────────────────────┘
   │
 ┌─┴─ 5. 상태 병합 + 세션 저장 ────────────────────────────────────┐
 │    merge_values()  값 갱신·삭제                                 │
 │    merge_blocks()  ★ 삭제 먼저, 추가 나중                       │
 │    save_session()  값 + 원본 + 블록을 **한꺼번에**               │
 └─┬──────────────────────────────────────────────────────────────┘
   │
 ┌─┴─ 6. 판정·미리보기·답변 ───────────────────────────────────────┐
 │    missing_field_names()  ← /status 와 **같은 함수**            │
 │    render_filled()        ← /preview 와 **같은 함수**           │
 │    compose_status_reply() 현황표 + 다음 질문                     │
 └─┬──────────────────────────────────────────────────────────────┘
   │
 └─→ token 스트리밍(32자 청크) → result 1회
```

> 예전에는 3단계와 5단계(상태 병합) 사이에 **글다듬이(톤)** 단계가 있었다 — 사용자
> 발화별로 값·본문을 LLM 으로 다시 쓰는 opt-in 기능. 2026-08-12 에 없앴다(§10 참고,
> 코드는 `archive/sfr006-tone` 브랜치) — 006 이 채우는 템플릿은 관리자가 정한 고정
> 톤으로 채우면 되는 성격이라 필요가 없었다.

### 왜 이 순서인가 — 실제로 물렸던 것들

**5단계에서 삭제가 추가보다 먼저인 이유.** `block_clears` 의 번호는 **LLM 이 이번 턴에 본
목록**(= 추가 이전 상태) 기준이다. 추가를 먼저 하면 번호가 밀려 방금 넣은 문단이 지워진다.

**세션 저장이 값·원본·블록을 한꺼번에 받는 이유.** 세션은 Redis 키 하나에 통째로
저장된다(병합이 아니라 **덮어쓰기**). 값만 저장하면 본문 블록이 전부 사라진다. 그래서
`session_view.save_state()` 는 컨텍스트를 통으로 받아 빠뜨리는 실수를 구조적으로 막는다.

### 출력 — 이벤트 두 종류

| 이벤트 | 언제 | 내용 |
|---|---|---|
| `token` | 답변 조립 후 여러 번 | 32자 청크. `sio_server.emit` 뒤에 반드시 `await asyncio.sleep(0)` |
| `result` | **정확히 마지막 1회** | 아래 구조화 데이터 |

`result.data` 의 주요 키:

```jsonc
{
  "text": "…채팅에 보이는 전체 답변…",
  "template_id": "주간보고", "session_id": "…",

  // 항목 값
  "field_values":   {"제 목": "8월 실적 보고"},
  "field_values_raw": {"제 목": "8월 실적 보고"},   // 화면 직접 편집 전 원본
  "fields_filled":  ["제 목"], "fields_missing": ["담당자"],
  "ready_for_download": false,
  "fields_updated": ["제 목"], "fields_cleared": [], "fields_rejected": ["없는항목"],

  // 본문 블록 (템플릿 항목 밖)
  "blocks": [{"text": "1. 추진 배경", "style_ref": "제 목", "raw_text": ""}],
  "blocks_added": 1, "blocks_removed": 0,
  "block_styles": ["제 목", "주요 내용"],          // 화면 선택지

  // 미리보기
  "template_markdown": "…채우기 전 양식…",         // 색인에 이미 있어 추가 파싱 없음
  "document_markdown": "…지금 값으로 채운 문서…",   // 매 턴 갱신, UI 문서 창이 그린다

  "error": null
}
```

> **`await asyncio.sleep(0)` 을 왜 매 emit 뒤에 넣나**
> 양보하지 않고 emit 을 몰아치면 WebSocket 쓰기가 버퍼에 쌓여 **UI 가 마지막에 한꺼번에
> 받는다** (가이드 5.2·D.4 "스트리밍이 일괄 반환되는 원인"). 실제 운영 bridge 코드도 매
> emit 뒤에 이걸 넣는다. 청크 단위로 보내는 것도 같은 이유다 — 글자 하나씩 보내면
> 현황표 한 장이 emit 수백 회가 되고, 양보 횟수가 늘어 오히려 느려진다.

## 5. 흐름 ② 다운로드

사용자가 **다운로드 버튼**을 누르면 코드 서빙의 `POST /generate` 가 불린다.

```
POST /generate {template_id, session_id, format}
   │
   ├─ 1. 세션에서 값·블록 로드 (요청에 직접 준 값이 있으면 덮어쓴다)
   ├─ 2. 템플릿 파일 읽기            template_store.read()
   ├─ 3. 블록 서식 화이트리스트 검증   _resolve_blocks()
   │
   ├─ 4. ★ document.build()  ─────────────────────────────────────┐
   │        ① apply_styles()    슬롯을 전용 run 으로 떼고 charPr   │
   │           (텍스트는 그대로 — 채우면 {…} 가 사라진다)          │
   │        ② fill_template()   슬롯·누름틀·{{token}} 채우기       │
   │           + 슬롯 표기 제거 (값이 없어도)                      │
   │        ③ append_blocks()   본문 블록 문단 복제·삽입           │
   │   ────────────────────────────────────────────────────────────┘
   │
   ├─ 6. 헤더에 부분 초안 정보 실어 바이너리 응답
   └─ 7. **성공했을 때만** 세션 종료
```

### 순서 ①→②→③ 에 근거가 있다

**③ 이 ② 뒤인 이유가 핵심이다.** 본문 블록은 템플릿 문단을 `deepcopy` 해서 서식을
물려받는다. 서식 적용 **전에** 복제하면 명세(`{16pt, 고딕}`)가 반영되기 *전* 모양을
물려받아, 사용자가 화면에서 본 제목 서식과 다른 문단이 나온다.

이 순서는 **`document.py` 에 단 한 벌만 있다.** 예전에는 세 곳(코드 서빙 / 미리보기 /
점검 스크립트)이 각자 같은 순서를 적고 있었고, 점검 스크립트가 자기가 검증하려는 순서를
스스로 복제하는 상태였다 — 운영 순서가 바뀌어도 점검은 통과했다.

### 단계마다 실패를 다루는 규율이 다르다

| 단계 | 실패하면 | 왜 |
|---|---|---|
| 채우기 | **오류로 올린다** (400) | 문서를 못 만든 것이다 |
| 서식 | **삼킨다** + 경고 로그 | 부가 기능이다. 글자 크기 하나 때문에 초안 전체를 못 받게 하지 않는다 |
| 본문 블록 | **오류로 올린다** (400) | 사용자가 직접 쓴 본문이다. 조용히 빠뜨린 문서를 주면 빠진 줄 모르고 제출한다 |
| ~~PDF 변환~~ | **2026-08-14 에 없어졌다** (산출은 hwpx 하나) | `archive/sfr006-pdf` |

마지막 항목은 코드 구조로 보장된다 — `_finalize()` 가 예외를 던지면 그 아래
`end_session()` 에 **도달하지 않는다.** 예전에는 `(응답, 오류)` 튜플과 `if error: return`
으로 이 순서를 지켰는데, 지금은 예외가 강제한다.

## 6. 흐름 ③ 화면에서 직접 편집

대화를 거치지 않는 편집 경로도 함께 제공한다. **대체재가 아니라 보완재다** — 한 항목만
고칠 때는 대화가 빠르고, 여러 항목을 훑어 고칠 때는 화면 폼이 낫다. 어느 쪽을 노출할지는
**UI 가 정하고**, 백엔드는 하나라 전환에 재배포가 필요 없다.

| 엔드포인트 | 하는 일 | 특이점 |
|---|---|---|
| `PATCH /values` | 항목 값 갱신 | **빈 문자열 = 지움**. 조용히 무시하면 사용자는 지웠다고 믿은 값을 그대로 받는다 |
| `DELETE /values` | 항목 값 비우기 | 세션 값만 지운다. 템플릿에 원래 적힌 값은 남으므로 `still_filled_in_template` 로 알린다 |
| `PUT /blocks` | 본문 목록 **통째 교체** | 부분 갱신이 아니다 (아래 참고) |

**`PUT /blocks` 가 왜 통째 교체인가.** 블록은 순서가 의미를 갖는 목록이다. 부분 갱신을
하려면 화면과 서버가 같은 인덱스를 공유해야 하고, 한 번만 어긋나도 **다른 문단이
지워진다.** 화면이 가진 목록을 그대로 보내면 그 문제가 원천적으로 없다. 빈 배열이면 전부
삭제.

세 경로 모두:

- 판정은 **코드가 화이트리스트로** 한다 (대화 경로와 같은 규율).
- 응답은 `GET /preview` 와 **같은 payload**(`session_view.compose_view`)를 쓴다. 편집 직후
  화면과 미리보기가 다른 계산을 하면 사용자가 보는 상태가 갈린다.
- 저장 실패는 **오류로 올린다**(500). 화면에는 반영됐는데 저장이 안 된 상태를 성공으로
  보이게 하지 않는다.
- `preview: false` 로 마크다운 생성을 생략할 수 있다 (연속 편집 중 가벼운 저장).

> 이 엔드포인트들은 관리자 토큰 대상이 아니라 **`session_id` 만 알면 호출된다**
> (`/status`·`/preview`·`/generate` 도 같다). 사내 폐쇄망 전제이며, 외부 노출 계획이
> 생기면 세션 소유자 검증이 별도 과제다.

## 7. 채울 자리를 찾는 방법

`hwpx_fields.py` 가 세 방식을 지원한다. **한 문서에 섞여 있어도 된다.**

| 방식 | 생김새 | 언제 쓰이나 |
|---|---|---|
| **슬롯** (기본) | 본문에 그냥 텍스트로 `제 목 : {'제목', 16pt, 맑은 고딕, 볼드}` | **현장 템플릿의 실제 방식** |
| 누름틀 (CLICK_HERE) | 한/글에서 필드를 심은 것 | 관리자가 필드를 심어 올린 경우 |
| 레거시 `{{token}}` | `부서: {{dept}}` | 프로토타입 호환 |

`GET /fields` 의 `source` 로 (`slot` / `field`) 어느 방식인지 확인할 수 있다.
`TEMPLATE_FILL_SLOT_FIELDS=0` 이면 슬롯을 무시하고 누름틀만 쓴다.

### 슬롯 문법 — 채울 자리는 중괄호 **안**뿐이다

```
{'항목명'[, 크기][, 글꼴][, 굵게]}
```

- **첫 인자는 따옴표 필수**다. 그 문자열이 곧 항목명이자 "여기에 무엇을 쓰라"는 LLM
  안내문(`FieldSpec.guide`)이다. 따옴표가 없으면 채울 자리가 아니다 (§8 참고).
  항목명 안에는 따옴표를 넣을 수 없다 — 닫는 자리를 알 수 없어진다.
- 뒤 인자는 **0~3개, 순서 자유**다. 토큰을 생김새로 판정한다: `16pt`·`16`·`16포인트`는
  크기, `볼드`·`굵게`·`bold`는 굵게(`보통`·`normal`은 굵게 **해제**), `기울임`·`밑줄`은
  그대로, 남은 첫 토큰이 글꼴. 위치를 고정하면 가운데를 건너뛸 때 `{'제목', , 고딕}` 처럼
  빈 자리를 남겨야 하고, 관리자가 순서를 틀리면 없는 글꼴을 걸게 된다.
- **지정하지 않은 인자는 건드리지 않는다.** `{'작성자'}` 는 그 자리 run 의 `charPrIDRef`
  를 그대로 물려받는다 — 서식을 지어내지 않는 것이 원칙이다.
- 구분자는 `,` `/` `·` `|`. 구분자 없이 공백만 쓰면(`{'제목' 16pt 굵게}`) 공백으로 나뉘므로
  **여러 낱말 글꼴(`맑은 고딕`)은 반드시 쉼표로 끊는다.**
- 한 문단에 여러 개가 올 수 있다 (`담당자 : {'소속'} {'성명'}`). 라벨 방식의 "문단당 1개"
  제약이 없다.
- 자리 표시어(`글씨크기`·`폰트`·`볼드여부`·`크기`·`스타일`)는 삼킨다 — 이 문서의 문법
  설명을 그대로 복사해 붙인 템플릿이 실제로 들어오고, 그러면 '폰트' 라는 없는 글꼴을 건다.
- 한/글 자동 고침이 `'제목'` 을 `‘제목’` 으로 바꿔 저장하므로 **굽은 따옴표도 받고**,
  편집 중 한쪽만 바뀐 `‘제목'` 도 열어 준다. 관리자가 눈으로 구분할 수 없는 차이로 항목이
  통째로 사라지는 편이 훨씬 나쁘다. 다만 짝이 다른 종류(`‘제목"`)면 슬롯으로 보지 않는다.
- 누름틀이 있는 문단은 건너뛴다 — 같은 문단을 두 경로가 고치면 값이 이중으로 들어가고
  run 을 쪼개는 도중 begin/end 사이 구조가 흐트러진다. `{{token}}` 구간은 **같은 길이의
  공백으로 가려** offset 을 보존한 채 제외한다.

### 값을 쓰는 방식

```
템플릿:  제 목 : {'제목', 16pt, HY헤드라인M, 볼드}
결과:    제 목 : 2026년 상반기 실적 보고
```

- **중괄호 밖은 손대지 않는다.** `제 목 : ` 의 들여쓰기·줄맞춤 공백까지 원문 그대로
  남는다. 라벨 방식은 `항목명: 값` 으로 줄을 재조립하느라 이 공백을 잃었고 `prefix` 를
  따로 보존해야 했다 — 자리를 중괄호로 명시하니 그 문제가 아예 생기지 않는다.
- **값이 없어도 `{…}` 표기는 지운다.** 작성 지시문이라 산출물에 남으면 안 된다.
  부분 초안이어도 마찬가지고, 중괄호 밖 라벨은 어차피 남으므로 한/글에서 이어 쓸 자리는
  그대로 보인다.
- LLM 이 값에 항목명을 다시 붙여 보내도(`제목: 실적 보고`) 코드가 떼어낸다 —
  프롬프트 지시만으로 보장하지 않는다.
- 슬롯마다 **전용 run 으로 쪼갠다.** 서식 인자가 그 슬롯에만 걸려야 하기 때문이다.
  문단 전체에 걸면 중괄호 밖 라벨까지 같이 커지고, 한 문단에 슬롯이 둘이면 뒤엣것이
  앞엣것을 덮는다.

### 파싱에서 실제로 물렸던 세 가지

**① 표는 문단 안에 문단이 중첩된다.**

```
hp:p → hp:run → hp:tbl → hp:tr → hp:tc → hp:subList → hp:p → hp:run → hp:t
```

`para.iter()` 를 그대로 쓰면 **표 전체 텍스트가 한 문단 텍스트로 이어져** 슬롯 인식과
문단 서식이 함께 깨진다. 그래서 `own_nodes(para, tag)` 로 **문단이 직접 소유한 노드만**
모아 판정한다. 이 판정은 `hwpx_fields` 가 정본이고 `hwpx_style`·`hwpx_blocks`·
`hwpx_markdown` 이 같은 함수를 쓴다.

**② lxml 프록시는 붙들고 있어야 유효하다.**

`{id(elem): 위치}` 맵을 만들 때 순회 결과를 리스트로 살려 두지 않으면 프록시가 회수되고
**id 가 재사용돼 엉뚱한 노드를 가리킨다.** 실제로 항목 순서가 뒤섞이는 버그로 드러났다.

**③ 슬롯은 run 경계를 걸친다.**

한/글은 한 낱말도 여러 run 으로 쪼개 저장한다. `{'구` + `분', 14pt}` 처럼 갈리면 뒤쪽
run 은 새 조각을 하나도 받지 못하는데, 그때 **손대지 않고 넘어가면 옛 글자가 그대로 남아**
`구분 : 정기분', 14pt}` 처럼 문서에 두 번 적힌다. 그래서 `rewrite_slots` 는 글자를 가진
run 을 **전부 먼저 등록**해 두고, 조각이 없는 run 은 비운다.

`hp:t` 와 `hp:ctrl`·`hp:secPr` 이 **한 run 에 섞여 있으면** 쪼갤 수 없다 — 복제하면 구역
정의나 누름틀이 함께 복제되기 때문이다. 이때는 완성된 한 줄을 첫 노드에 넣고 나머지를
비운다. 텍스트는 정확하지만 슬롯별 서식은 그 run 전체에 걸리고, 호출부가 그 사실을 로그로
남긴다.

### 항목 스키마 — `FieldSpec`

```python
FieldSpec(
    name="제목",           # 항목명 = 따옴표 안 문자열 (문서 등장 순서로 dedup)
    guide="제목",          # 슬롯은 항목명과 같다 / 누름틀은 stringParam 안내문
    field_type="SLOT",     # SLOT | CLICK_HERE
    occurrences=1,         # 같은 이름이 몇 군데 나오나 (머리말+서명란 등)
    filled=False,          # 슬롯은 **언제나 False** (아래 참고)
    current_value="",      # 그 값
    source="slot",         # slot | field
)
```

같은 이름이 여러 자리에 있으면 한 항목으로 묶이고 값도 모든 자리에 함께 들어간다.
누름틀과 슬롯에 같은 이름이 있으면 누름틀 쪽을 대표로 본다.

**채워짐 판정도 코드가 결정적으로** 한다 — 슬롯은 **언제나 미입력**이다. 채우고 나면
`{…}` 자체가 사라지므로, 문서에 슬롯이 남아 있다는 것이 곧 아직 안 채웠다는 뜻이다
(스캔 대상은 언제나 템플릿 원본이고, 완성 문서를 다시 스캔하는 경로는 없다).
누름틀은 begin~end 텍스트가 비어 있지 않고 안내문과 다르면 채워진 것.

## 8. 서식 인자 적용

`hwpx_style.py` 가 슬롯의 서식 인자(`{'제목', 16pt, 함초롬, 볼드}`)를 실제 hwpx 서식으로
바꾼다. **LLM 호출이 없다** — 인자는 정규식으로 읽고 XML 조작은 전부 코드가 한다.
글자 크기·폰트 id·`itemCnt` 는 한 글자만 틀려도 한/글이 문서를 열지 못하는 값이고 LLM
출력은 매번 다르다. 결정적으로 처리할 수 있는 일에 비결정 도구를 쓰지 않는다.

**이 단계가 채우기보다 먼저 돈다** (§5). 슬롯은 값을 채우면 `{…}` 가 사라지므로, 여기서
슬롯 텍스트를 전용 run 으로 떼어내고 그 run 에 `charPr` 을 걸어 둔 다음 채우기가 그 run
안 글자만 갈아 끼운다. 순서를 되돌리면 서식이 통째로 유실된다.

```
Contents/section0.xml   <hp:run charPrIDRef="3"><hp:t>제 목 : 실적 보고</hp:t></hp:run>
Contents/header.xml     <hh:charPr id="3" height="1600">   ← 1pt = 100
                          <hh:fontRef hangul="1" latin="1" …/>
                          <hh:bold/>
                        <hh:font id="1" face="HY헤드라인M"/>
```

- 크기 단위는 **1/100 pt** (16pt → `"1600"`)
- 굵게·기울임·밑줄은 속성이 아니라 **자식 요소의 존재**로 표현된다
- `charProperties`/`fontface` 의 `itemCnt`/`fontCnt` 를 **반드시 다시 센다.** 틀리면
  한/글이 문서를 못 연다
- 폰트 목록은 **언어(lang)별로 따로** 있다. 한글만 바꾸면 라틴 문자가 옛 폰트로 남는다
- 같은 (base, spec) 조합은 `charPr` 을 재사용한다 — 항목이 많아도 목록이 무한히 늘지 않게

표기는 관대하게 읽는다: `{'제목', 볼드체, 16pt}`, `{'제목', 맑은 고딕, 11pt}`,
`{'제목', 글꼴: 함초롬바탕, 크기: 11pt}`, `{'제목' 함초롬돋움 16pt 굵게}` 모두 인식한다.

서식은 **슬롯 run 에만** 건다 (`STYLE_SCOPE` 기본 `slot`). `paragraph` 로 바꾸면 슬롯이
놓인 문단 전체에 걸리는데, 그건 서식을 지정한 슬롯이 그 문단에 **하나뿐일 때만** 뜻이
통한다 — 둘 이상이면 서로 덮어쓰므로 코드가 그 문단만 슬롯 범위로 떨어뜨린다.

### 따옴표 없는 `{…}` 는 채울 자리도, 서식도 아니다

현장 템플릿(`data/파워.hwpx`)에는 이런 것들이 있었다:

```
담당자 : {소속} {성명}
배포일 : {YYYY.MM.DD. (요일)}
```

**값 안내이지 서식이 아니다.** 슬롯 방식에서는 따옴표가 그 경계를 대신하므로 판정이
간단하다 — 따옴표가 없으면 그냥 본문 글자다. 문서에 **원문 그대로 남기고**, 등록 시
`bare_braces` 경고로만 노출한다. 지워 버리면 값 안내로 쓰던 문구가 조용히 사라지고,
등록을 거부하면 본문에 중괄호를 쓴 정상 문서를 막는다. 오타인지 의도인지는 사람만 안다.

> 라벨 방식일 때는 이 구분을 **글꼴 어휘 사전으로 추측**해야 했다(`require_evidence` —
> 크기·효과·글꼴 어휘 중 하나는 있어야 서식으로 인정). 그래도 첫 토큰을 폰트로 채택해
> '소속'·'YYYY.MM.DD.' 를 **없는 글꼴로 문서에 거는** 사고가 났다. 그 판정은 이제 따옴표
> 경계가 없는 **누름틀 안내문 경로에만** 남아 있다 (`parse_style_spec`).

## 9. 본문 블록 — 항목을 다 채운 뒤

**문제:** 템플릿 항목은 **개수가 고정**이다. 다 채우고 나면 "그 아래에 추진 배경과 기대
효과도 넣어 달라" 를 처리할 자리가 없다.

**해법:** `hwpx_blocks.py` 가 **템플릿 문단을 통째로 복제해서** 문서 뒤에 이어 붙인다.

```
템플릿                              결과
─────────────────────            ─────────────────────
[표] 문서명 / 보고자               [표] 문서명 / 보고자
제 목 : {고딕,16pt}                제 목 : 상반기 실적 보고
여백: (5pt)                        (빈 줄)
주요 내용: {명조,11pt}             주요 내용: 핵심 요약
                              ┌→  1. 추진 배경          ← "제 목" 문단 복제
                              │   전사 차원의…          ← "주요 내용" 문단 복제
                              └   2. 기대 효과          ← "제 목" 문단 복제
```

### 왜 명세를 다시 해석하지 않고 복제하는가

명세(`{16pt, 고딕}`)를 파싱해 문단을 처음부터 조립하면 **글자 서식(charPr)만 재현되고
문단 서식(paraPr — 여백·줄간격·정렬·들여쓰기)은 재현되지 않는다.** 이 패키지에는 paraPr 을
만드는 코드가 아예 없고, 만든다면 `itemCnt` 하나만 틀려도 한/글이 문서를 못 여는 부류의
위험이 새로 생긴다.

문단을 `deepcopy` 하면 `paraPrIDRef`·`charPrIDRef` 가 통째로 따라온다. 파서가 모르는
속성까지 보존되고, **새로 만드는 서식 정의가 0개**라 `header.xml` 을 아예 건드리지 않는다.
그래서 이 경로는 문서를 깨뜨릴 수 없다.

### 복제할 때 버리는 것 — 안전장치의 핵심

**`hp:t` 만 허용하는 화이트리스트**로 텍스트가 아닌 것을 전부 버린다.

| 버리는 것 | 안 버리면 |
|---|---|
| `hp:secPr` 를 담은 run | 구역 정의가 복제돼 문서 구조가 깨진다 |
| `hp:ctrl` (누름틀) | 필드가 복제된다 |
| `hp:tbl` (표) | **표가 통째로 복제된다** |
| 그림·도형 등 | 예상 못 한 개체가 늘어난다 |
| `hp:linesegarray` | 줄 배치 캐시. 글자 수가 달라졌으니 방해만 된다 |

> **이 방어가 실제로 필요하다.** 현장 템플릿(`data/파워.hwpx`)의 **첫 문단이 `hp:secPr`
> 와 `제 목 :` 슬롯을 한 문단에 담고 있다.** 그 문단을 서식 원본으로 쓰면 구역 정의가
> 딸려온다. 블랙리스트가 아니라 화이트리스트인 이유는 모르는 제어 요소가 새로 나와도
> 자동으로 걸러지게 하기 위해서다.

### 서식 원본(`style_ref`) 고르는 규칙

- 후보는 **최상위 문단만.** 표 셀 안 슬롯은 제외한다 — 셀 폭 기준으로 잡힌 문단 모양을
  본문에 붙이면 어긋난다. (표 안 슬롯은 **채울 항목으로는 그대로 인식**된다.)
- 목록은 `GET /fields`·`/preview` 의 `block_styles`, 대화 결과의 `block_styles` 로 나간다.
- 이름을 못 찾으면 **내용을 버리지 않고** 기본 서식으로 넣고 사유를 남긴다. 서식 이름
  오타 때문에 사용자가 쓴 본문을 지우는 편이 더 나쁘다.
- 기본 서식 고르는 순서: ① 항목이 아닌, 글자가 있는 문단 → ② 마지막 항목 문단.
  **빈 문단을 우선하지 않는 이유**: 현장 템플릿의 빈 줄은 `여백: (5pt)` 처럼 간격용이라
  그 서식을 물려받으면 본문이 5pt 로 나온다.

### 그 밖의 규칙

- 삽입 위치 기본값은 **문서 끝**. 서명란처럼 마지막에 고정돼야 하는 문단이 있으면
  `TEMPLATE_FILL_BLOCK_ANCHOR=<항목명>` 으로 그 문단 **바로 뒤**로 옮긴다.
- 블록 텍스트의 **줄바꿈은 문단 분리**다. `<hp:t>` 안의 `\n` 은 한/글에서 줄바꿈이 아니라
  그냥 글자라, 한 문단에 몰아넣으면 한 줄로 붙는다.
- **내용에는 화이트리스트가 없다** (애초에 템플릿에 없는 내용을 쓰는 기능이다).
  개수(`MAX_BLOCKS`, 기본 100)·길이(`MAX_BLOCK_CHARS`, 기본 4000) 상한으로만 막는다.
  **서식 이름에만** 화이트리스트를 건다.
- 블록은 `ready_for_download` 에 관여하지 않는다 — 항목이 아니라 **덤**이라 0개여도
  문서는 완성이다.
- `TEMPLATE_FILL_BODY_BLOCKS=0` 으로 끈다.

## 11. 상태 저장

### 11.1 세션 (`session_store.py`) — Redis

```jsonc
// 키: template_fill:session:{session_id}
{
  "version": 2,
  "template_id": "주간보고",
  "values":     {"제 목": "8월 실적 보고"},        // 문서에 들어갈 값
  "raw_values": {"제 목": "8월 실적 보고"},        // 화면 직접 편집 전 원본 (§10 삭제 전엔 톤 적용 전 원본이었다)
  "blocks": [{"text": "1. 추진 배경", "style_ref": "제 목", "raw_text": ""}],
  "updated_at": 1754… 
}
```

- **생명주기:** 턴마다 갱신 → 문서 생성 성공 시 즉시 삭제. 버려진 세션은 Redis 네이티브
  만료(`SET … EX`, 기본 24h)가 회수한다. 청소 데몬이 필요 없다.
- **`raw_values` 를 따로 두는 이유:** 매 턴 누적 값을 다시 변환하면 문체가 중첩된다.
- **블록의 원본은 `BodyBlock.raw_text` 안에 둔다.** 블록은 목록이라 값처럼 별도 dict 로
  두면 인덱스가 어긋난다.
- **옛 버전 세션도 버리지 않는다.** `version` 이 올라가도 없는 키는 기본값으로 흡수한다 —
  버리면 배포 시점에 진행 중이던 대화가 전부 초기화된다.
- 로그에는 값이 아니라 **개수만** 남긴다 (3.8절).

### 11.2 템플릿 색인 (`template_index.py`) — Redis

템플릿은 관리자가 올려두면 바뀌지 않는 입력인데, 예전에는 `/fields`·`/status`·**대화의 매
턴**·`/generate` 가 각각 zip 을 풀고 XML 을 처음부터 다시 파싱했다.

```jsonc
// 키: template_fill:index:{template_id}
{
  "schema_version": 4,          // 파서 규칙이 바뀌면 올린다 (슬롯 전환으로 3→4)
  "slot_fields": true,          // 설정이 바뀌면 항목 목록 자체가 달라진다
  "body_blocks": true,
  "content_hash": "a1b2…",      // 파일이 교체되면 자동 miss
  "fields": [ … ], "block_styles": ["제 목", "주요 내용"],
  "markdown": "…", "table_count": 1, "truncated": false
}
```

- **무효화는 키가 아니라 값 대조로** 한다. 해시를 키에 넣으면 삭제할 때 옛 해시를 알아야
  해서 `DELETE /templates/{id}` 가 지울 수 없는 잔여 키를 남긴다.
- ⚠️ **슬롯 인식 규칙이나 `FieldSpec` 을 고치면 `SCHEMA_VERSION` 을 올려야 한다.**
  안 올리면 새 코드가 옛 판정을 읽는다.
- **캐시는 성능 장치일 뿐이다.** Redis 가 죽어도 직접 파싱으로 degrade 한다 (세션 저장
  실패와 다르다 — 그쪽은 값 유실이라 오류로 올린다).
- `GET /templates` 는 **캐시에 있는 것만** 상세를 붙인다. 목록 한 번이 전체 파싱이 되지
  않게 하기 위해서다. 없으면 `indexed: false` 로 정직하게 표시한다.

### 12.1 LLM (GenOS Gateway)

```
{GENOS_URL}[/api/gateway]/rep/serving/{LLM_SERVING_ID}/v1/chat/completions
```

**URL 조립은 `llm.py` 의 `_chat_url()` 한 곳에서만 한다.** `/api/gateway` prefix 를 코드가

- 결과는 **`LlmResult(content, error_type, is_transport_error)` 값 객체**로 반환한다.
  전역 오류 상태를 두면 asyncio 레이스가 난다.
- 응답 스키마(`choices[0].message.content`)를 검증하며 꺼낸다.

## 13. 오류 코드

형식은 `{영역코드}-{공통오류코드}`. 공통 코드는 `00020001`(통신) / `00020002`(실행) /
`00020003`(입력·상태) **세 개뿐**이며 새로 만들지 않는다.

### 영역 02 — 대화 (`data["error"]` 객체로 반환)

| 상수 | 코드 | 재시도 | 언제 |
|---|---|---|---|
| `ERR_CHAT_UPSTREAM_TIMEOUT` | `02-00020001` | ✅ | LLM 통신 실패·timeout |
| `ERR_CHAT_UPSTREAM_EXECUTION` | `02-00020002` | ✅ | LLM 응답이 왔지만 쓸 수 없음 |
| `ERR_CHAT_TEMPLATE_NOT_FOUND` | `02-00020003` | ❌ | 템플릿 파일 없음 |
| `ERR_CHAT_TEMPLATE_INVALID` | `02-00020003` | ❌ | hwpx 파싱 실패 |
| `ERR_CHAT_NO_FIELDS` | `02-00020003` | ❌ | 채울 항목이 하나도 없음 |
| `ERR_CHAT_INTERNAL` | `02-00020003` | ❌ | 세션 저장 실패 등 |

### 영역 03 — 코드 서빙 (HTTP 응답)

| 상수 | 코드 | HTTP | 언제 |
|---|---|---|---|
| `ERR_API_INPUT` | `03-00020003` | 400 | 형식·상한 위반 |
| `ERR_API_ADMIN_FORBIDDEN` | `03-00020003` | 403 | 관리자 토큰 불일치 |
| `ERR_API_TEMPLATE_NOT_FOUND` | `03-00020003` | 404 | 템플릿 없음 |
| `ERR_API_SESSION_NOT_FOUND` | `03-00020003` | 404 | 세션에 값이 없음 |
| `ERR_API_TEMPLATE_EXISTS` | `03-00020003` | 409 | 같은 이름 템플릿 존재 |
| `ERR_API_INTERNAL` | `03-00020002` | 500 | 생성·저장 실패 |
| `ERR_API_PDF_FAILED` | `03-00020002` | 500 | PDF 변환 시도 실패 |
| `ERR_API_PDF_UNAVAILABLE` | `03-00020003` | 501 | PDF 변환 수단 없음 |

**영역코드를 섞지 않는다.** 대화 경로가 `template_store`(03 코드로 올린다)를 쓸 때는
`chat_state.load_context()` 가 02 코드로 **바꿔서** 다시 던진다. 섞이면 운영에서 어느
단계가 실패했는지 구분이 안 된다.

사용자 노출 예외(`TemplateError`, `SessionStoreError`, `PdfConvertError` …)의 메시지는
**해당 파일 안에서 작성한 고정 한국어 안내문만** 담는다. 예외 원문·stack trace 는 응답에
넣지 않고 `error_type`(예외 클래스명)으로만 분류해 로그에 남긴다.

| `check_body_blocks` | 기능 | 표·secPr 복제 방지, 서식 상속, **적용 순서**, 미리보기 일치 |
| `check_tone_policy` | 사본 대조 | MCP `lang_policy`(원본)↔018 글다듬이↔eval 톤 문구가 글자 단위로 같은지 (006 사본은 2026-08-12 삭제) |

> **픽스처를 위험하게 만들 것.** `check_body_blocks` 첫 판은 픽스처가 안전한 모양이라
> 안전장치를 꺼도 통과했다. 실제 템플릿처럼 **secPr 과 슬롯을 한 문단에** 두고 **표 run 을
> 텍스트 run 앞에** 둬야 잡힌다. 지금은 화이트리스트를 제거하면 6건, 적용 순서를 뒤집으면
> 3건이 실패하는 것을 확인했다.

**정식 유닛테스트는 아직 없다.** 제자리는 `SFR-006/template_fill/tests/` 인데, 그 사본에
슬롯 파서가 없어서(`slot_occurrences`·`rewrite_slots`·`own_nodes`·`nearest_para` 가 onprem
에만 있다) 옮기려면 파서부터 이식해야 한다.

## 15. 가드레일 — 자리만 잡아 둔 설계

입/출력 가드레일은 **나중에 플러그인으로 붙인다.** 여기서는 **어디에 꽂히고 무엇을
책임지는지**만 정의한다. **이 절의 내용은 현재 코드에 존재하지 않는다.**

`◆` 가 새로 꽂히는 가드레일이고, 그 밖은 지금 있는 코드다.

```
[영역 02 — 대화]

  사용자 발화
   │
   ◆ IG-1  입력 가드레일 ......... 프롬프트 인젝션 · 금칙 표현 · 개인정보
   ▼
  LLM 추출 (값 · 삭제 · 본문 블록)
   │
   ◆ OG-1  출력 가드레일 ......... 환각(발화에 없는 값) · 민감정보 유입
   ▼
  field_judge 화이트리스트 검증        ← 이미 있는 결정적 1차 방어선
   │
   ▼
  세션 저장 ──────────────────────────────────┐
   │                                          │
   ◆ OG-2  출력 가드레일 ......... 값 노출 범위 · 표현
   ▼                                          │
  토큰 스트리밍                                │
                                              │
[영역 03 — 코드서빙]                           │
                                              │
  화면 직접 입력 (PATCH /values, PUT /blocks)  │
   │                                          │
   ◆ IG-2  입력 가드레일 ......... 개인정보 · 길이/문자셋
   ▼                                          │
  화이트리스트 검증 ──────────────────────────┤
                                              ▼
                                     document.build()
                                              │
                                              ◆ OG-3  출력 가드레일
                                              │       최종 산출물 검수
                                              ▼
                                        다운로드 응답
```

> 예전에는 `field_judge` 화이트리스트 검증과 세션 저장 사이에 글다듬이(톤) 단계 +
> `value_guard`(사실 변형 검증)가 있었다. 2026-08-12 에 그 기능 자체를 없애면서
> 이 자리의 OG 도 함께 정리했다(§10 참고).

| 지점 | 위치 | 검사 대상 | 대표 관심사 |
|---|---|---|---|
| **IG-1** | `run_chat` 3단계 직전 | 사용자 발화 원문 | 프롬프트 인젝션, 금칙 표현, 개인정보 |
| **IG-2** | `PATCH /values`·`PUT /blocks` 검증 직전 | 화면에서 직접 입력한 값·본문 | 개인정보, 길이·문자셋 |
| **OG-1** | `field_judge.parse_updates` 전후 | LLM 이 뽑은 값·블록 | 환각, 민감정보 유입 |
| **OG-2** | 스트리밍 직전 | 사용자에게 보이는 답변 | 값 노출 범위, 표현 |
| **OG-3** | `document.build` 이후 | 채워진 문서 내용 | 최종 산출물 검수 |

**IG-1 과 OG-1 이 우선순위가 가장 높다.** LLM 을 통과하는 유일한 경로이고, 나머지 지점은
이미 결정적 코드(`field_judge`, `value_guard`)가 1차 방어선을 맡고 있다.

### 플러그인이 지켜야 할 계약

1. **판정 결과를 침묵 처리하지 않는다.** 차단·수정한 항목은 건수와 사유를 응답과 로그에
   노출한다. 조용히 지우면 사용자는 반영됐다고 믿는다.
2. **기존 결정적 검증을 대체하지 않는다.** 가드레일은 `field_judge`
   **앞뒤에 덧붙는 층**이지 그것을 치우고 들어가는 게 아니다.
3. **실패 정책을 명시적으로 고른다.** 현재 코드의 기본 규율은 "부가 기능 실패는 본 기능을
   막지 않는다"(미리보기·서식)이지만, **가드레일에는 그 규율을 그대로 적용하면 안 된다** —
   검사를 건너뛴 것을 통과로 보이게 하는 셈이다.
4. **로그에 원문을 남기지 않는다.** 허용 필드(`event`, `error_type`, `item_count` …)만 쓴다.
5. **오류 코드를 새로 만들지 않는다.** `00020001/2/3` 조합으로 `error_codes.py` 에만 추가한다.
6. **끄고 켤 수 있어야 한다.** 다른 기능과 같은 방식의 환경변수 스위치를 둔다.

### 지금 확정하지 않는 것

플러그인 인터페이스 형태(in-process / HTTP / 코드서빙 연계), 판정 엔진(규칙 / LLM Judge /
외부 서비스), 지점별 fail-open/fail-closed 정책. 폐쇄망 가용성이 확인돼야 정할 수 있다.

## 16. 알려진 공백

**실물로 확인 못 한 것**

- **실물 대화로 LLM 이 `blocks` 를 제대로 뽑는지** 못 봤다. 파이프라인과 검증 로직만
  확인했고, 프롬프트 품질은 게이트웨이가 붙어야 안다.
- **PDF 는 실제 변환기로 돌려본 적이 없다.** 호출 규약은 경계 스텁으로 검증했다.
  코드서빙 이미지에 `genon.preprocessor` 가 포함돼야 동작한다.
- **다운로드 버튼의 실제 배선**은 실물 확인이 필요하다.
- ⚠️ **슬롯 문법으로 다시 만든 실물 템플릿을 아직 못 봤다.** `data/파워.hwpx` 는 옛
  라벨 문법(`제 목 : {볼드체, HY헤드라인M, 16pt}`)이라 지금 올리면 **항목 0개**로 잡힌다.
  등록은 성공하고(`fields: []`) `bare_braces` 경고에만 나오므로, **UI 가 그 경고를 보여주지
  않으면 조용히 빈 템플릿이 배포된다.** 관리자용 재작성 안내가 필요하다.
- **표 안 슬롯·전각 콜론·run 을 걸친 슬롯은 합성 픽스처로만 검증**했다.
- **서명란·붙임이 마지막에 있는 템플릿**을 못 봤다. 그런 템플릿에서는
  `TEMPLATE_FILL_BLOCK_ANCHOR` 로 삽입 위치를 지정해야 한다.

**설계상 열어 둔 것**

- ~~`여백: (5pt)` 같은 줄이 채울 항목으로 잡힌다~~ — **슬롯 전환으로 해소됐다.** 콜론을
  근거로 삼지 않으므로 따옴표 없는 줄은 애초에 항목이 아니다. 라벨 방식이 안고 있던
  "일반 문장을 항목으로 오인" 계열 문제(20자·3단어 상한 같은 휴리스틱)가 함께 사라졌다.
- 반복 블록(`contents` 배열)은 미구현 — `SFR-006/hwpx.py` 의 `expand_repeat_block` 을
  이식하면 된다. **본문 블록과 다른 것이다**: 반복 블록은 템플릿에 미리 표시해 둔 구간을
  개수만큼 늘리는 것이고, 본문 블록은 템플릿에 없던 내용을 뒤에 이어 쓰는 것이다.
  이식할 때 `hwpx_blocks._clone_for_text` 를 재사용할 수 있다.
- 용어집(SFR-018 `genos-glossary` 1단계)은 006 에 붙어 있지 않다.

**테스트 공백**

- `onprem/` 에 정식 유닛테스트가 없다 ([14장](#14-검증) 참고). 사본
  `SFR-006/template_fill/tests` 에 슬롯 파서를 이식하는 것이 선결 과제다.
