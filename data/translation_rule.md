## 번역 구현 관련 내용
1. 입력 : 사용자 입력(text) + 사용자가 업로드한 hwpx, pdf, docx 문서. hwpx는 직접 파싱이 필요하며, pdf와 docx는 제노스 전처리기를 활용하여 파싱 예정
2. 과정 : 사용자는 업로드한 내용을 어떤 언어와 형식(문어체/구어체)로 번역할지 선택. 주어지는 용어사전을 기반으로 번역을 진행해야 하며 UI 상으로 원본과 번역본을 보여주어야 함. 반드시 구조는 같아야 하며 hwpx를 마크다운 형식으로 바꾸는 등의 방법은 사용 가능. UI 상에서 하이라이트 방식으로 어떤 단어가 용어사전의 어떤 단어를 참고하였는지 알려줄 수 있어야 함.
3. 출력 : 사용자 입력을 한국어, 영어, 중국어, 태국어, 베트남어, 러시아어로 번역한 텍스트. 문서 출력 X

4. 초안 코드 : onprem/SFR_018_translation
5. 고려 사항: pdf와 docx는 제노스 전처리기를 통해 마크다운 파싱 예정이나, hwpx는 해당 방법을 사용할 경우 표 안의 수치등이 깨져서 직접 파싱하거나 마크다운 변환 후 xml로 이중 검증을 해야하나 고려 중. 변경 사항은 파이썬의 difflib으로 구현이 되어잇는걸로 알고 있으며, ui상에서 하이라이트 할 예정이므로 반드시 고려 필요(프론트와 협의가 필요하나, 일단은 json 형식으로 {'한글': '영어'} 만들어둔 다음 프론트에서 알아서 파싱해서 반영하도록 생각 중)
6. 한국어 -> 다른 언어는 당연히 구현되어야 하며 다른 언어 -> 한국어 까지 구현이 되어야 함. 다만, 영어-러시아 처럼 한국어가 아닌 경우에는 고려 X.
7. 프롬프트는 별도 관리(onprem/prompt/SFR_018_translation에 jinja로 생성)
