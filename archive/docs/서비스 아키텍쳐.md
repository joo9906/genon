# 서비스 아키텍처

**사용자의 입력 한 번이 어디를 지나 무엇이 되어 돌아오는가** — 네 기능 전부를 입력부터
산출물까지 적는다. 설계서·아키텍처 그림을 그릴 때 이 문서만 보면 되도록 썼다.

> **이 문서의 위치.** 계약의 정본은 따로 있다 — 프론트가 보는 값은
> `onprem/docs/FRONT.md`, 등록 절차는 `onprem/ONPREM.md`, 왜 그렇게 만들었는지는
> 루트 `CLAUDE.md` 다. 이 문서는 그 셋을 **하나의 흐름으로 꿰어** 놓는다.

## 0. 한눈에

GenOS 플랫폼 위에 **네 개의 층**으로 올라간다. 층마다 등록 방법과 제약이 다르다.

```
┌──────────────────────────────────────────────────────────────────────────┐
│  사용자 (캔버스 채팅 화면 / 전용 UI)                                        │
└───────────────┬──────────────────────────────────────────────────────────┘
                │  ① 실행 버튼      ② 파일 업로드
                ▼
┌──────────────────────────────────────────────────────────────────────────┐
│  GenOS 캔버스 워크플로우            [영역 02]  스텝 9개 (파이썬 코드 조각)     │
│   · 흐름을 쥔다 · 소켓으로 token / result 를 화면에 쏜다                     │
│   · 외부 패키지는 httpx 하나. 무거운 일을 직접 하지 않는다                    │
└───┬──────────────────────────────────────────┬───────────────────────────┘
    │ HTTP (게이트웨이 경유)                     │ JSON-RPC (게이트웨이 경유)
    ▼                                          ▼
┌────────────────────────────┐   ┌────────────────────────────────────────┐
│ 코드 서빙   [영역 03]        │   │ MCP 도구      [영역 01]                 │
│ 배포 단위 4개               │   │ 파일 4개 (파일 1개 = 등록 1개)            │
│ · LLM 호출 · 프롬프트        │   │ · 결정적 판정만. LLM 을 부르지 않는다      │
│ · Redis · lxml · 파일 생성   │   │ · 표준 라이브러리만 (requirements 없음)   │
└───────────┬────────────────┘   └────────────────────────────────────────┘
            │ OpenAI 호환 HTTP
            ▼
┌────────────────────────────┐   ┌────────────────────────────────────────┐
│ LLM 게이트웨이 · MinIO(CDN)  │   │ 전처리기      [영역 05]  파일 2벌         │
│ · 용어사전 API              │   │ · 업로드 문서를 텍스트로 바꾼다            │
└────────────────────────────┘   └────────────────────────────────────────┘
```

**등록은 10번 + 캔버스 붙여넣기 9개다.**

| # | 영역 | 무엇 | 형태 |
|---|---|---|---|
| 1~4 | 03 | 템플릿 채우기 · 글다듬이 · 번역 · FAQ | 코드 서빙 (Git 저장소 하나 = 컨테이너 하나) |
| 5~8 | 01 | `genon_text_guard` · `genon_lang_policy` · `genon_glossary` · `genon_pii_audit` | MCP (소스 파일 1개) |
| 9 | 05 | `final_preprocessor.py` **또는** `smart_preprocessor.py` | 전처리기 — 적재(검색)용, **둘 중 하나만** |
| 10 | 05 | `only_me.py` | 전처리기 — **질의 시 첨부용** |
| — | 02 | 워크플로우 스텝 9개 | 캔버스에 코드를 통째로 붙여 넣는다 |

### 왜 이렇게 갈랐나 — 층마다 할 수 있는 일이 다르다

| 층 | 쓸 수 있는 것 | 그래서 맡는 일 |
|---|---|---|
| **02 워크플로우** | `httpx` 뿐. 이미지에 패키지를 못 넣는다 | 흐름·오류 분류·화면 전송 |
| **03 코드 서빙** | `requirements.txt` 가 있다 (`lxml`·`redis`) | LLM 호출·문서 파싱·파일 생성 |
| **01 MCP** | 표준 라이브러리만. `requirements.txt` 가 **없다** | 결정적 판정(구조·숫자·언어·용어) |
| **05 전처리기** | 벤더 스택 위에 얹는다 | 업로드 문서 → 텍스트 |

**층 사이에 import 가 금지다.** 그래서 같은 규칙이 여러 벌 존재한다(§9 사본 지도).

## 1. 입력은 두 갈래로 들어온다

### 갈래 A — 캔버스 워크플로우 (운영 경로)

사용자가 화면에서 실행 버튼을 누르는 경로다. **네 기능의 정상 흐름이 전부 여기다.**

```
사용자 입력
  ├─ 최상위 `question` (또는 `text`)      ← 채팅창에 친 글
  └─ overrideConfig.vars {…}              ← 드롭다운·업로드 결과
       ├─ genosUploaded                    ← 전처리기가 뱉은 문서 텍스트
       ├─ polish_doc_type / polish_tone
       ├─ translate_target_lang / _source_lang / _register
       ├─ faq_count / faq_title
       └─ template_fill_template_id
```

> **캔버스 변수는 값이 전부 문자열로 온다.** 숫자·불리언도 문자열이다.

### 갈래 B — 코드 서빙 REST 직접 호출

화면을 그릴 때(선택지 목록)와, 캔버스를 지나지 않는 업로드에 쓴다.

| 쓰임 | 경로 |
|---|---|
| 드롭다운 그리기 | `GET /policies`(톤·문서유형) · `GET /languages` · `GET /config` · `GET /templates` |
| hwpx 직접 업로드 | `POST /translate/hwpx` · `POST /faq/hwpx` · `POST /generate/upload` |
| 내려받기 폴백 | `POST /download` (018 셋) · `POST /generate` (006) |

**갈래 B 의 hwpx 업로드는 전처리기를 지나지 않는다** — 그래서 각 단위가 자기 hwpx 파서를
따로 갖는다(§9).

### 화면으로 나가는 것은 이벤트 두 가지뿐

```
token → token → token → … → result        (정상)
                             result        (오류 — 018 셋은 토큰이 한 개도 안 나간다)
```

| 이벤트 | 담는 것 |
|---|---|
| `token` | **정본 텍스트 조각.** `<mark>` 하이라이트가 **없다** |
| `result` | 최종 payload. **정확히 한 번** |

`result` 가 도착하면 화면은 흘러온 글을 지우고 **하이라이트가 입혀진 두 벌**로 갈아 끼운다.

## 2. 업로드 문서가 텍스트가 되기까지 — 전처리기 [영역 05]

**네 기능의 첨부 원문은 전부 하나다: `genosUploaded`.**

```
사용자가 파일 첨부
      │
      ▼
┌─────────────────────────────────────────────────────────────┐
│ 전처리기 (등록 10번, only_me.py)  — **질의 시 첨부용**         │
│                                                             │
│  .hwpx  → 우리 파서 (표 병합·중첩표·글상자·각주·자동번호)        │
│  그 외   → 벤더 파서 (docx·pdf·오디오 …)                      │
│                                                             │
│  청킹하지 않는다 · 조문 머리말을 붙이지 않는다                   │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
              genosUploaded = "<doc …>본문 마크다운</doc>"
                           │
                           ▼  스텝이 `_extract_uploaded_markdown` 으로 본문만 꺼낸다
                      원문 텍스트
```

### 적재용과 첨부용이 **반대**인 이유

| | 적재용 (등록 9번) | 첨부용 (등록 10번, `only_me.py`) |
|---|---|---|
| 쓰임 | RAG 검색 색인 | **네 기능의 LLM 입력** |
| 청킹 | 한다 | **안 한다** (문서 하나 = 레코드 하나) |
| 조문 머리말 | `제2장 총칙 > 제5조(목적)` 을 **본문에 넣는다** | **넣지 않는다** |
| 표 | 언제나 HTML | 손실이 있을 때만 HTML |

검색은 머리말이 **임베딩되는 문자열에 있어야** 걸린다. 그런데 네 기능은 그 텍스트를
**LLM 에 그대로 던진다** — 번역은 원문에 없던 머리말을 번역해 결과물에 싣고, FAQ 는
그것을 원문 문장으로 보고 근거 대조를 한다. 실측으로 기술협상서 한 벌이
**적재용 13,460자 / 첨부용 9,901자** 였고 차이 3,559자가 전부 검색용 장식이었다.

### 적재용은 둘 중 하나만 고른다

| | `final_preprocessor.py` | `smart_preprocessor.py` |
|---|---|---|
| 벤더 절반 | 첨부용 | 지능형 |
| **pdf** | 평문 + 문자 수 분할 — **표가 사라진다** | docling + TableFormer + OCR |
| **`.hwp`·오디오** | 네이티브 (GenosHwp SDK · Whisper) | 없다 |
| 조/항/호 위계 (pdf·docx) | 있다 | 아직 없다 |

**같은 컬렉션에 둘을 걸지 않는다** — 같은 pdf 가 등록 시점에 따라 다른 청크로 들어가고,
그 어긋남은 오류가 아니라 **검색 품질로만** 드러난다.

## 3. 기능 ①  글다듬이 — 문체에 맞게 다시 쓴다

### 3.1 입력

| 자리 | 키 | 필수 | 값 |
|---|---|---|---|
| vars | `genosUploaded` | 조건부 | 업로드 문서. **있으면 발화보다 우선** |
| 최상위 | `question` | 조건부 | 채팅에 붙여 넣은 원문 |
| vars | `polish_doc_type` | 선택 | `email` · `post` · `customer_notice` · `debt_reason` · `reviewer_opinion` |
| vars | `polish_tone` | 선택 | `polite` · `friendly` · `clear` · `objective` |

> 업로드도 발화도 없으면 `INPUT_EMPTY`. 실질 상한은 **업로드 용량**이다 —
> 긴 문서는 조각으로 나눠 끝까지 처리한다.

### 3.2 흐름

```
[02] sfr018_polish_01_policy
      │
      ├─ 원문 확보 (genosUploaded ▸ question)
      │
      └─▶ MCP  genon_lang_policy.resolve_tone(doc_type, tone)          ◀── ★MCP 1
             · 문서유형이 톤을 강제하는가(`debt_reason`·`reviewer_opinion` → objective)
             · 모르는 톤·옛 톤(`report`)이면 별칭표로 옮긴다
             · 판정 결과: tone, tone_overridden, fell_back
      │
      ▼  data{polish_source_text, tone, doc_type}
[02] sfr018_polish_02_polish   ※ 마지막 스텝
      │
      ├─▶ POST /polish/stream   (SSE)  ──────────────────────────────┐
      │                                                             │
      │   ┌─────────────────────────────────────────────────────┐   │
      │   │ [03] 글다듬이 코드 서빙                               │   │
      │   │                                                     │   │
      │   │  1. chunking  조각 분할 (6,000자)                    │   │
      │   │      · 코드펜스·여러 줄 HTML 표 **안에서 끊지 않는다** │   │
      │   │      · 조각을 (본문, 꼬리공백) 로 가른다              │   │
      │   │  2. polisher  조각 4개씩 동시 LLM 호출               │   │
      │   │  3. 순서 버퍼  머리 조각은 라이브, 뒤 조각은 모았다가  │   │
      │   │  4. rebuild   꼬리 공백을 **코드가** 되꽂는다         │   │
      │   │  5. file_store → MinIO 업로드 → download_url        │   │
      │   └─────────────────────────────────────────────────────┘   │
      │        delta … delta … done{polished_text, download_url}     │
      │                                                             │
      ├─ 흘리는 동안 ▼ 동시에 띄워 둔다 ────────────────────────────┘
      │
      ├─▶ MCP  genon_text_guard.markdown_structure_issues            ◀── ★MCP 2
      ├─▶ MCP  genon_text_guard.fact_issues                          ◀── ★MCP 3
      ├─▶ MCP  genon_text_guard.diff_changes                         ◀── ★MCP 4
      │
      ▼
   result{original_text, polished_text, download_url, notice?}
```

> **점검 호출을 먼저 띄우고 그 동안 흘린다.** 순서대로 하면 스트리밍이 순수한 연출이
> 되고 전체 시간만 늘어난다.

### 3.3 MCP 가 하는 일 — 넷 다 **결정적 판정**이다

| 도구 | 입력 | 내는 것 | 화면에 어떻게 나타나나 |
|---|---|---|---|
| `resolve_tone` | 문서유형·톤 | 확정 톤 + 강제 여부 | 프롬프트의 톤 지시문이 바뀐다 |
| `markdown_structure_issues` | 원문, 결과 | 표 행·셀·펜스·제목 **개수 지문** 대조 건수 | `notice` 한 줄 |
| `fact_issues` | 원문, 결과 | 숫자·날짜가 달라진 건수 | `notice` 한 줄 |
| `diff_changes` | 원문, 결과 | **바뀐 낱말의 좌표** + `<mark>` 사본 두 벌 | 좌우 비교의 형광 |

`diff_changes` 가 좌표를 내는 이유: 문자열만 주면 프론트가 결과에서 그 낱말을 **다시
찾아야** 하고, 같은 낱말이 두 번 나오면 어느 쪽을 칠할지 정할 수 없다.

### 3.4 검증 — 무엇이 언제 걸리나

| # | 검증 | 어디서 | 실패하면 |
|---|---|---|---|
| 1 | 입력이 비었나 / 너무 긴가 | 서빙 라우트 | `ERR_INPUT_EMPTY` / `ERR_INPUT_TOO_LONG` (**갈라 낸다** — 예전에는 20만 자가 "입력이 비었다" 로 나갔다) |
| 2 | 강제 톤을 지켰나 | MCP `resolve_tone` | 사용자가 고른 톤을 **덮고** `tone_overridden` |
| 3 | 조각이 코드펜스·표를 가르지 않았나 | 서빙 `chunking` | 애초에 그 자리에서 안 끊는다 |
| 4 | 조각이 실패했나 | 서빙 `polisher` | **그 자리에 원문을 되꽂는다.** 전량 실패만 오류 |
| 5 | 무손실인가 (흘린 것 == 정본) | 서빙 스트리밍 | `stream_diverged` → `notice` |
| 6 | 구조가 깨졌나 | MCP `markdown_structure_issues` | `notice` — **막지 않고 알린다** |
| 7 | 숫자·날짜가 달라졌나 | MCP `fact_issues` | `notice` |
| 8 | 게이트웨이가 스트리밍을 받나 | 서빙 | 못 받으면 서빙이 **그 자리에서 비스트리밍으로 되돌아간다** |

> **4·6·7 이 "막지 않고 알리는" 이유**: 자동 재시도를 하지 않는 것이 결정이다. 사용자가
> 고르지 않은 LLM 호출을 쓰면서 **결과가 나아진다는 보장이 없다.** 사실을 말하고
> 다시 할지는 사용자가 정한다.

### 3.5 출력

```json
{ "original_text": "…<mark>개발함</mark>…",
  "polished_text":  "…<mark>개발하였습니다</mark>…",
  "download_url":   "https://…/글다듬이결과.txt",
  "notice": ["표·제목 등 문서 구조가 원문과 달라진 곳이 2곳 있습니다. 결과를 확인해 주세요."] }
```

| | |
|---|---|
| **화면** | 좌우 비교 두 벌. 왼쪽 형광 = **지워진** 낱말, 오른쪽 형광 = **새로 들어온** 낱말 |
| **파일** | `글다듬이결과.txt` — UTF-8 **BOM** + **CRLF** (§8) |
| **`notice`** | 있을 때만 실린다. 건수만 말한다 — 어느 낱말인지는 문서 내용이라 싣지 않는다 |

## 4. 기능 ②  번역 — 구조를 지키며 옮긴다

### 4.1 입력

| 자리 | 키 | 필수 | 값 |
|---|---|---|---|
| vars | `translate_target_lang` | **✅** | `ko` `en` `zh` `th` `vi` `ru` |
| vars | `translate_source_lang` | 선택 | **비워도 된다** — 백엔드가 감지한다 |
| vars | `translate_register` | 선택 | `written`(문어체) · `spoken`(구어체) |
| vars | `genosUploaded` | 조건부 | 업로드 문서 |
| 최상위 | `question` | 조건부 | 붙여 넣은 원문 |

> **원문 언어는 비워 두는 편이 안전하다.** 보내면 그 값을 **정본**으로 삼되 감지와
> 대조하고, "한국어가 아닌 쌍"이면 거부한다.

### 4.2 흐름

```
[02] sfr018_translate_01_detect
      │
      ├─ 원문 확보 (genosUploaded ▸ question)
      │
      └─▶ MCP  genon_lang_policy.validate_direction(선언, 문서)        ◀── ★MCP 1
             · 문자 종류 비율로 원문 언어를 **감지**한다
             · 선언값과 대조 → DirectionVerdict
             · 규칙 §6: **원문·대상 중 하나는 반드시 한국어**
      │
      ▼  data{translate_source_text, source_lang, target_lang, register}
[02] sfr018_translate_02_translate   ※ 마지막 스텝
      │
      ├─▶ POST /translate/stream   (SSE)  ───────────────────────────┐
      │   ┌─────────────────────────────────────────────────────┐   │
      │   │ [03] 번역 코드 서빙 — 스트리밍 경로                    │   │
      │   │  stream_chunking 조각 → LLM 이 **마크다운째** 낸다     │   │
      │   │  순서 버퍼 → 문서 순서대로 흘린다                      │   │
      │   │  구조는 끝나고 **지문 대조로 알린다**(막지 않는다)      │   │
      │   └─────────────────────────────────────────────────────┘   │
      │        delta … delta … done{translated_text}                │
      │                                                             │
      ├─▶ POST /translate/finalize  (JSON) ◀── 번역이 끝나야 정해진다 ┘
      │   ┌─────────────────────────────────────────────────────┐
      │   │  glossary_store → 용어사전 적재 상태                  │
      │   │  glossary_exact → 원문·번역문 양쪽에서 용어 매칭       │
      │   │  glossary_report → 준수율 + <mark> 사본 두 벌         │
      │   │  file_store → MinIO → download_url                   │
      │   └─────────────────────────────────────────────────────┘
      │
      └─▶ MCP  genon_text_guard.numeric_issues(원문, 번역문)          ◀── ★MCP 2
      │
      ▼
   result{original_text, translated_text, download_url, notice?}
```

**비스트리밍 폴백 경로 `POST /translate/markdown` 은 그대로 남는다.** 게이트웨이가
스트리밍을 안 받는 배포에서 쓰이고, **표가 많은 문서는 그쪽이 더 안전하다**:

```
markdown_units  스켈레톤 분해
   원문 ──▶ [ 뼈대: 표 파이프 · HTML 태그 · 제목 마커 ]  ← 코드가 쥔다
        └─▶ [ 유닛: 셀·문장 텍스트만 ]                  ← LLM 에 보낸다
                  │  배치 JSON {id, t} · 15개 동시
                  ▼
        validation  스키마 검증 → 기각 항목은 단건 재호출
                  ▼
        rebuild_markdown  뼈대에 번역문을 꽂아 되조립
```

즉 **구조 보존의 주체가 경로마다 다르다** — 스켈레톤 경로는 **코드**가, 스트리밍 경로는
**프롬프트**가 쥔다. 그것이 스트리밍으로 감수한 대가이고, 감추지 않고 지문으로 알린다.

### 4.3 용어사전이 붙는 자리 — 켜지면 **넷이 함께** 켜진다

```
GenOS AI 드라이브 용어사전 API
      │  (TRANSLATE_GLOSSARY_API_URL · _DRIVE_ID · _WORKSPACE_ID)
      ▼
glossary_store  적재 (첫 호출 때)
      │
      ├─ ① 프롬프트   이 조각에 나온 용어만 "이렇게 옮겨라" 로 싣는다
      ├─ ② 준수율     번역문이 실제로 그 말을 썼는가
      ├─ ③ 원문 <mark>   사전 용어가 원문에서 쓰인 자리
      └─ ④ 번역문 <mark> 그 용어가 번역문에서 쓰인 자리
```

**셋 중 하나라도 환경변수가 비면 `not_configured` 로 넷이 통째로 꺼진다.** 코드를
고치지 않는다 — 반쪽만 켜지는 상태가 없다.

| 특기 | |
|---|---|
| **한국어 조사 폴백** | `가맹점을` 이 사전의 `가맹점` 에 걸린다. 없으면 ko→en 은 **용어가 프롬프트에 안 실리고**, en→ko 는 **준수율이 0.0** 으로 나온다 |
| **적용 언어** | 한국어·영어만. 나머지 넷은 LLM 만으로 번역한다 (`glossary_supported`) |
| **왼쪽만 형광** | "사전 용어인데 번역이 그 말을 안 썼다" 는 뜻이다 |

### 4.4 검증

| # | 검증 | 어디서 | 실패하면 |
|---|---|---|---|
| 1 | 대상 언어가 있나 | 스텝 1 | 오류 — 대상 언어를 고르라고 안내 |
| 2 | **한국어 축**(§6) | MCP `validate_direction` | **거부.** `en→ru` 같은 쌍은 아예 진행하지 않는다 |
| 3 | 선언 언어 ↔ 실제 문서 | MCP `validate_direction` | §6 이 깨질 때만 거부, 아니면 `source_mismatch` 로 보고만 |
| 4 | 배치 응답 스키마 | 서빙 `validation` | 기각 항목만 **단건으로 재호출** |
| 5 | 전량 폴백 (원문이 그대로 돌아왔나) | 스텝 2 | **오류.** 200 이고 본문도 있는데 번역이 안 된 경우다 |
| 6 | 용어사전 준수 | 서빙 `glossary_report` | `notice` — 건수만. **자동 재번역 안 한다** |
| 7 | 숫자·날짜 지문 | MCP `numeric_issues` | `notice` |
| 8 | 무손실 왕복 | 서빙 `markdown_units` | 항등 번역 시 **문자 단위로 동일**해야 한다 |

> **5 번의 위치가 중요하다.** 비스트리밍은 이 판정을 끝내고 흘렸다. 스트리밍은 흘리면서
> 가므로 **서빙이 "전량 실패에서는 한 글자도 흘리지 않는다" 를 보장**해서 성립시킨다 —
> 안 그러면 답이 나왔다가 오류로 갈아엎히는 화면이 된다.

### 4.5 출력

```json
{ "original_text":   "…<mark>가맹점</mark>…",
  "translated_text": "…<mark>merchant</mark>…",
  "download_url":    "https://…/번역결과.txt",
  "notice": ["용어사전 용어 3개가 번역문에 반영되지 않았습니다 (원문에서 형광으로 표시된 자리입니다). 다시 번역하면 반영될 수 있습니다."] }
```

## 5. 기능 ③  FAQ 생성 — 문서에서 문답을 뽑는다

### 5.1 입력

| 자리 | 키 | 필수 | 값 |
|---|---|---|---|
| vars | `genosUploaded` | **✅** | 전처리기 산출물. **이게 없으면 기능이 성립하지 않는다** |
| vars | `faq_count` | 선택 | 만들 **총 개수** (기본 상한 30) |
| vars | `faq_title` | 선택 | 내려받을 파일 이름 |

### 5.2 흐름 — **MCP 를 부르지 않는 유일한 018 기능**

```
[02] sfr018_faq_01_source
      ├─ genosUploaded 에서 원문 확보
      └─▶ GET /config          상한(max_count)을 화면·스텝이 함께 본다
      ▼
[02] sfr018_faq_02_generate   ※ 마지막 스텝
      └─▶ POST /generate/stream  (SSE)
          ┌──────────────────────────────────────────────────────────┐
          │ [03] FAQ 코드 서빙                                        │
          │                                                          │
          │  1. chunking      12,000자 조각 (최대 80조각 ≈ 96만 자)    │
          │  2. plan_quota    **총 개수를 조각에 고르게 배분**          │
          │       · 호출 수 상한 6 — 태울 조각을 표집한다              │
          │       · 앞에서부터 채우면 잘라 쓰던 시절과 같아진다         │
          │  3. 조각 6개 동시 LLM 호출                                 │
          │  4. markdown_items  **증분 파서**                         │
          │       LLM 이 `근거 → 질문 → 답변` 순으로 쓰게 해서         │
          │       검증을 **접두어 연산**으로 만든다                     │
          │  5. 항목마다 세 관문 (아래)                                │
          │  6. 통과한 항목만 프레임으로 나간다                         │
          │  7. file_store → MinIO → download_url                    │
          └──────────────────────────────────────────────────────────┘
             item_open → delta → delta → item_close → … → done
      ▼
   result{faq_items[], download_url, notice?}
```

### 5.3 검증 — **기각될 항목은 화면에 한 글자도 안 나간다**

이 설계의 요점이다. 항목이 화면에 나타났다가 사라지면 안 되므로, **검증을 통과한 뒤에야
항목을 연다.**

```
LLM 출력 스트림 ──▶ 근거가 닫힘 ──▶ ① 근거 대조 ──── 실패 ──▶ 버린다 (화면에 안 나감)
                                      │ 통과
                     질문이 닫힘 ──▶ ② 중복 판정 ──── 실패 ──▶ 버린다
                                      │ 통과
                  답변 첫 델타에서 ──▶ ③ 스키마 ────▶ item_open ▶ 화면
```

| # | 검증 | 규칙 | 왜 |
|---|---|---|---|
| ① | **근거 대조** (`evidence.py`) | n-gram(3) 으로 **문서 전체**와 대조 | 조각 경계가 문장 가운데를 지나면 오탐 기각이 난다 → 조각이 아니라 문서 전체로 본다 |
| ② | **중복** | **조각을 가로질러** 공유한다 | 같은 주제가 여러 절에 나오면 조각마다 같은 질문이 나온다. 조각별로 세면 그게 다 통과한다 |
| ③ | **스키마** | 세 필드가 다 있는가 | 답변이 끝내 안 오면 **답 없는 질문이 화면에 남는다** — 그래서 질문이 닫힐 때가 아니라 **답변 첫 델타에서** 항목을 연다 |

> **④ 산출량**은 기각이 아니라 **보고**다. `요청하신 N개 중 M개만 문서에서 근거를
> 확인했습니다.` 가 `notice` 로 나간다. 기각 건수·요청 개수는 payload 에 **오지 않는다** —
> 화면에 그릴 자리가 없는 값이고, 서버 로그(`event=faq_done`)가 답한다.

**개수와 비용을 다른 손잡이가 정한다.**

| 손잡이 | 무엇을 정하나 |
|---|---|
| `faq_count` (사용자) | **받는 개수.** 고른 숫자가 곧 받는 개수다 |
| `FAQ_MAX_CHUNK_CALLS` (배포, 6) | **몇 번 부르나** = 비용 |
| `FAQ_LLM_CONCURRENCY` (배포, 6) | **동시에 몇 개가 도나** = 대기시간 |

상한에 걸려 못 태운 구간은 `coverage_capped` → `notice` 로 알린다. **조용히 건너뛰면
안 나온 내용이 "문서에 없는 것" 으로 보인다.**

### 5.4 출력

```json
{ "faq_items": [
    { "question": "위약금은 어떻게 계산하나요?",
      "answer":   "잔여 계약기간에 비례해 산정합니다.",
      "evidence": "위약금은 잔여 계약기간에 비례하여 산정한다." } ],

  "notice": ["문서가 매우 길어 뒷부분은 FAQ 생성에서 제외했습니다."] }
```

`evidence` 는 **원문에 실제로 있는 문장**이다 — 지어낸 근거는 ① 에서 걸러진다.

## 6. 기능 ④  템플릿 채우기 (SFR-006) — 대화로 hwpx 양식을 채운다

**앞의 셋과 방향이 반대다 — 전용 UI 가 없고 채팅이 곧 화면이다.** 그래서 답변 문장
(`text`)이 필수이고, 채운 값·기각 항목·남은 항목이 **전부 그 문장 안에** 들어 있다.

### 6.1 입력

| 자리 | 키 | 필수 | 값 |
|---|---|---|---|
| vars | `template_fill_template_id` | **✅** | `GET /templates` 의 id |
| 최상위 | `question` | **✅** | 사용자 발화. **2만 자에서 잘린다** |
| vars | `genosUploaded` | 선택 | **빈 항목을 이 문서로 자동으로 채운다** |

> **문서를 `question` 에 넣지 말 것.** 발화는 2만 자에서 잘리고, 발화 자리의 문서는
> "지워 달라"·"본문에 추가해 달라" 같은 **지시로 해석될 수 있다.**

### 6.2 흐름 — **MCP 를 부르지 않는다**

```
[02] sfr006_01_context
      ├─▶ POST /chat/context    템플릿 항목 목록 확보 (hwpx 를 파싱해 슬롯 색인)
      │        슬롯 문법:  {'제목', 16pt}   ← 이름 + 값 안내(글꼴·형식)
      │
      └─▶ POST /chat/prefill    ★ 업로드 문서로 **빈 항목만** 자동 채움
               · 12,000자 조각 · 최대 20조각 · **앞 조각이 이긴다**
               · 항목이 다 차면 남은 조각을 **부르지 않는다** (비용 상한)
               · 이미 태운 문서면 다시 안 태운다 (세션 `source_doc_hashes`)
      ▼
[02] sfr006_02_extract
      └─▶ POST /chat/extract    이번 턴 발화에서 값 추출 → ParsedIntent
               (수정 · 삭제 · 본문 추가가 한 응답에 섞여 온다)
      ▼
[02] sfr006_03_commit   ※ 마지막 스텝
      └─▶ POST /chat/commit
          ┌──────────────────────────────────────────────────────┐
          │ 1. 문서분 병합 → 2. **발화분 병합** (발화가 이긴다)     │
          │ 3. session_store (Redis) 에 턴 상태 저장              │
          │ 4. chat_reply  답변 문장 조립                         │
          │ 5. hwpx_markdown  미리보기 → `text` 아래에 붙인다      │
          │ 6. 다 채웠으면 hwpx 를 굳혀 MinIO 업로드              │
          └──────────────────────────────────────────────────────┘
      ▼
   result{text, download_url, session_id, template_id}
```

### 6.3 검증

| # | 검증 | 어디서 | 실패하면 |
|---|---|---|---|
| 1 | 템플릿이 있나 | `/chat/context` | 404 → "템플릿을 고르거나 등록해 달라" |
| 2 | **항목명 화이트리스트** | `field_judge` | 템플릿에 없는 이름은 **기각**하고 그 이름을 답변에 적는다 |
| 3 | **사용자 값을 덮지 않는가** | **두 층** | ① 프롬프트에서 채워진 항목을 아예 뺀다 ② 그래도 온 값은 버리고 `conflicts` 로 센다 |
| 4 | 같은 턴에 발화와 문서가 겹치면 | 커밋 순서 | **발화가 이긴다** (문서분을 먼저, 발화분을 나중에 병합) |
| 5 | 같은 문서를 또 태우지 않나 | 세션 표식 | 표식이 없으면 매 턴 문서를 다시 태워 **사용자가 지운 값을 되살린다** |
| 6 | 슬롯 좌표가 안 밀리나 | `hwpx_fields` | 쓰기 경로는 **본문 XML 에 있는 것**을 기준으로 삼는다 (미리보기와 다른 텍스트 조립) |
| 7 | 자동 채움이 실패하면 | `doc_prefill` | **오류가 아니다.** `prefill_failed` 를 답변에 한 줄 싣는다 |

> **값의 진위는 코드가 판정하지 않는다** (요구 확정). 그래서 **채운 값을 답변에 전부
> 나열한다** — 채팅이 곧 화면이므로, 그것이 사용자가 잘못된 값을 발견해 그 자리에서
> 고칠 수 있는 유일한 수단이다.

### 6.4 출력

```json
{ "text": "제목을 『…』(으)로 채웠습니다. 남은 항목은 담당자, 배포일입니다.\n\n---\n\n**미리보기**\n\n# …",
  "download_url": null,
  "session_id": "…", "template_id": "보도자료" }
```

| | |
|---|---|
| **화면** | `text` 를 채팅 말풍선에 그대로 그린다. 미리보기가 그 안에 들어 있다 |
| **파일** | 다 채웠을 때만 `.hwpx` 링크가 온다. **`null` 이면 아직 받을 수 없다** |

## 7. MCP 도구 [영역 01] — 결정적 판정만 한다

**LLM 을 부르지 않는다.** 판정이 흔들리면 같은 문서가 실행마다 다른 결과를 내고,
그 차이가 "코드가 바뀐 건지 모델이 바뀐 건지" 구분되지 않는다.

| 파일 | 도구 | 부르는 쪽 | 성격 |
|---|---|---|---|
| `genon_lang_policy.py` | `resolve_tone` | **스텝** 다듬-1 | 톤 강제·별칭 판정 |
| | `validate_direction` | **스텝** 번역-1 | 언어 감지 + 한국어 축 집행 |
| | `list_languages`·`list_registers`·`resolve_register`·`detect_language` | 도구를 고르는 LLM | 선택지 표면 |
| `genon_text_guard.py` | `markdown_structure_issues` | **스텝** 다듬-2 | 표·펜스·제목 **개수 지문** 대조 |
| | `fact_issues` | **스텝** 다듬-2 | 숫자·날짜 대조 |
| | `numeric_issues` | **스텝** 번역-2 | 〃 |
| | `diff_changes` | **스텝** 다듬-2 | 낱말 좌표 + `<mark>` 사본 |
| `genon_glossary.py` | `glossary_lookup`·`glossary_status`·`glossary_reload` | 도구를 고르는 LLM | 용어 조회 (**번역 서빙은 자기 사본을 쓴다**) |
| `genon_pii_audit.py` | `pii_audit`·`pii_scan_text`·`pii_detectors` | **사람이 직접** | 생성 문서의 미마스킹 건수 집계 |

### MCP 등록의 제약이 설계를 정했다

| 제약 | 결과 |
|---|---|
| `requirements.txt` 가 **없다** | 표준 라이브러리만. 비표준 패키지는 파일 안에서 설치 |
| 여러 도구 파일이 **한 서버에 함께 로드될 수 있다** | 모든 최상위 심볼에 접두어 (`LP`/`TG`/`GL`/`PA`). 겹치면 나중 것이 앞엣것을 덮고, 그 실패는 "도구가 이상한 값을 낸다" 로만 드러난다 |
| **기동 훅이 없다** | 용어사전 적재를 첫 도구 호출로 미룬다 |
| 값이 없을 때 `None` 이 아니라 **빈 문자열**이 온다 | 선택 인자를 `int`/`float` 로만 선언하면 본문에 닿기 전에 죽는다 |

### 호출 규약 — Accept 헤더가 계약이다

```
POST {GENOS_URL}/api/gateway/mcp/{서빙 id}/mcp
Accept: application/json, text/event-stream     ← **둘 다** 열거해야 한다
Content-Type: application/json

{"jsonrpc":"2.0","method":"tools/call","params":{"name":"…","arguments":{…}}}
```

MCP 스트리머블 HTTP 서버는 **POST 본문을 읽기 전에** Accept 를 본다. 둘 다 없으면 도구를
부르지도 않고 `406` 으로 끊는다(`httpx` 기본값 `*/*` 는 통과하지 못한다). 응답이 SSE
프레임으로 올 수 있어 `_decode_body` 가 두 모양을 다 받는다.

### PII 감사는 다른 자리에 있다

```
적재 전처리기 ── 민감정보 마스킹(가드레일 #315)      ← 여기서 가려야 한다
      │
      │  이 층이 빠지거나 꺼져 있으면 **조용하다**
      │  (적재 성공 · 검색 성공 · 네 기능이 원문 그대로 답변에 싣는다)
      ▼
genon_pii_audit ── 산출물 쪽에서 미마스킹 건수를 센다   ← 짝이지 경쟁이 아니다
```

- **비율이 아니라 절대 건수다.** 허용치가 0인 값에 비율 기준을 걸면 200문장 문서의 1건이
  0.5% 라 통과한다 — **기준이 사고를 승인한다.**
- **검출한 값은 응답에 담지 않는다.** 자리와 유형만 — 담으면 감사 리포트가 유출 경로가 된다.
- **`leak=0` 은 "개인정보 없음" 이 아니다.** 이름·주소·계좌번호는 안 센다(NER 이 없고,
  계좌번호는 체크섬이 없어 일반 숫자열과 구분되지 않는다). 그 공백을 응답에 함께 싣는다.

## 8. 산출물

### 텍스트 파일 (018 셋)

```
UTF-8 BOM (EF BB BF)  +  CRLF 줄바꿈
```

| 왜 | |
|---|---|
| **BOM** | 없으면 옛 메모장이 ANSI(cp949)로 읽어 **한글이 깨진다** |
| **CRLF** | 1809 이전 메모장은 LF 만 있는 파일이 **전체 한 줄**로 붙어 보인다 |
| **인라인 강조 제거** | `**굵게**` 가 메모장에서는 별표로 보인다 |

폐쇄망 사내 PC 의 윈도우 빌드를 통제할 수 없으므로 가장 보수적인 쪽으로 맞춘다.

### hwpx 파일 (006)

원본 템플릿을 **되쓴다** — 새로 만들지 않는다. 슬롯 자리의 문자만 바꾸고 서식·표·머리말을
건드리지 않는다.

### 내려받기 링크 — 네 기능이 모두 `download_url`

```
결과 확정
   │
   ▼
file_store  (사본 4벌 — 배포 단위 간 import 금지)
   │  multipart: hostname + file
   ▼
MinIO ──▶ data.presigned_url ──▶ payload.download_url
```

- **`httpx` 로 올린다** — 참조 샘플의 동기 `urllib` 을 그대로 쓰면 async 라우트의 이벤트
  루프가 업로드 내내 멈춘다.
- **fail-open 이다.** 업로드 실패는 기능이 실패한 것과 **다른 사건**이라 결과는 그대로
  내고 링크만 비운다. 잘 만들어진 번역이 파일 하나 때문에 사라지면 안 된다.
- **예외 원문을 응답에 담지 않는다** — 내부 URL 이 실린다.
- 폴백: 018 셋 `POST /download`(화면이 텍스트를 되돌려 보낸다) · 006 `POST /generate`.

## 9. 같은 규칙이 여러 벌 있다 — **사본 지도**

**배포 단위 간 import 가 금지**라서 생긴 의도된 중복이다. 하나를 고치면 나머지를 함께
고쳐야 하고, **갈리면 같은 질문에 다른 답이 나오는데 오류로는 드러나지 않는다.**

| 규칙 | 사본 | 갈리면 |
|---|---|---|
| hwpx 파싱 코어 | **5벌** — 006 · 번역 · FAQ · 전처리기 2벌 | 같은 문서가 경로마다 다른 텍스트가 된다 |
| `file_store` (MinIO) | **4벌** — 네 단위 | 같은 업로드 실패가 단위마다 다르게 끝난다 |
| `prompt_library` | **4벌** — 네 단위 | 같은 관리자 실수가 단위마다 다르게 끝난다 |
| `txt_output` | **3벌** — 018 셋 | 파일 인코딩이 기능마다 달라진다 |
| 톤 프리셋 | **3벌** — MCP · 글다듬이 · eval | 고른 톤이 조용히 무시된다 |
| 언어 표·방향 판정 | **2벌** — MCP · 번역 서빙 | **직접 업로드 경로에 뒷문이 남는다** |
| 용어사전 매칭 | **2벌** — MCP · 번역 서빙 | 경로마다 다른 용어 목록을 쓴다 |
| 워크플로우 유틸 | **9벌** — 스텝마다 | 스텝이 자기완결이어야 캔버스에 붙는다 |

**점검 스크립트가 사본을 동작으로 대조한다** — 정적 diff 가 아니라 **같은 입력을 태워
같은 출력이 나오는지** 본다(`check_table_grid` · `check_tone_policy` · `check_mcp_tools`).

## 10. 오류·재시도 모델

### 오류 객체

```json
{ "error": { "error_code": "ERR-02-00020001",
             "msg": "…잠시 후 다시 시도해 주세요.",
             "retryable": true } }
```

| 자리 | |
|---|---|
| `ERR-` | 로그에서 눈으로 가려내기 위한 접두어. **분류 판정은 뒤 8자리**로 한다 |
| `02` / `03` | 영역 — 워크플로우 스텝 / 코드 서빙 |
| `msg` | **고정 한국어 안내문.** 내부 URL·예외 원문이 들어가지 않는다 |
| `retryable` | 화면이 분기할 값은 **이것 하나**다 |

### 네 갈래

| 상황 | 코드 | `retryable` | 사용자가 할 일 |
|---|---|---|---|
| 통신 실패·지연 | `…0001` | `true` | 잠시 후 다시 |
| 실행 실패 | `…0002` | `true` | 잠시 후 다시 |
| **설정 부재** (배포 실수) | `…0003` | **`false`** | 관리자 문의 |
| **최종 실패** | `…0003` | **`false`** | 관리자 문의 |

### 왜 설정 부재를 갈라 냈나

환경변수를 안 넣은 상태는 **몇 번을 눌러도 같은 자리에서 실패하는데**, 예전에는
"잠시 후 다시 시도해 주세요" 가 나가고 캔버스가 재시도를 걸었다. 원인이 화면에도 로그에도
드러나지 않았다.

> **경계에서 뒤집히지 않게 한다.** 스텝은 재시도 여부를 **상태코드가 아니라 응답 본문의
> `error_code` 분류**로 정한다. 상태코드로 보면 서빙이 `retryable=false` 로 갈라 둔 응답이
> 스텝 경계에서 통째로 뒤집힌다 — 실제로 그런 적이 있다.

## 11. 상태

| 단위 | 상태 | 어디에 |
|---|---|---|
| **006** | 대화 턴 상태 (채운 값·본문 블록·문서 표식) | **Redis** (`template_fill:session`, TTL 24h) |
| **006** | 템플릿 슬롯 색인 | **Redis** (`template_fill:index`, TTL 720h) |
| **FAQ** | 생성 결과 (다운로드가 찾아온다) | **Redis** |
| **글다듬이** | 없다 — **무상태** | 파일은 MinIO 가 들고 있다 |
| **번역** | 없다 — `finalize` 도 **무상태** | 프론트가 두 텍스트를 되돌려 보내면 대조를 다시 한다 |

> **전역 dict 를 쓰지 않는다.** 레플리카가 2개면 세션이 깨진다 — 요청이 어느 pod 으로
> 갈지 모른다.
>
> **`finalize` 가 무상태인 이유**: 용어 매칭은 결정적이라 같은 답이 나오고, 세션을 붙이면
> 이 무상태 단위에 상태가 생긴다. LLM 을 부르지 않으므로 재시도해도 안전하다.

## 12. 설정

### 게이트웨이 — 셋이 필수다

| 이름 | 누가 | 없으면 |
|---|---|---|
| `GENOS_URL` | 스텝 9 + 서빙 4 | `CONFIG_MISSING` (**재시도 불가**) |
| `GENOS_TOKEN` | 스텝 9 + 서빙 4 | 인증 실패 |
| `LLM_SERVING_ID` | 서빙 4 | `CONFIG_MISSING`. **모델도 이 값이 정한다** |

### 스텝이 읽는 등록 id — 여섯

`TEMPLATE_FILL_SERVING_ID` · `TEXT_POLISH_SERVING_ID` · `TRANSLATION_SERVING_ID` ·
`FAQ_SERVING_ID` · `LANG_POLICY_MCP_ID` · `TEXT_GUARD_MCP_ID`

→ **서빙을 먼저 등록해 id 를 얻은 뒤** 스텝 환경변수를 채운다.

### 알아 둘 손잡이

| 이름 | 기본 | 무엇 |
|---|---|---|
| `LLM_CONCURRENCY` | 15 | 번역 배치 동시 수 |
| `POLISH_LLM_CONCURRENCY` | 4 | 글다듬이 조각 동시 수 |
| `POLISH_MAX_CHUNK_CHARS` | 6,000 | 글다듬이 조각 크기 |
| `FAQ_LLM_CONCURRENCY` | 6 | FAQ 조각 동시 수 (**대기시간**) |
| `FAQ_MAX_CHUNK_CALLS` | 6 | FAQ 호출 수 상한 (**비용**) |
| `FAQ_MAX_CONTEXT_CHARS` | 12,000 | FAQ 조각 크기 |
| `FAQ_MAX_CONTEXT_CHUNKS` | 80 | ≈ 96만 자까지 덮는다 |
| `FAQ_MAX_COUNT` | 30 | 사용자가 고를 수 있는 상한 |
| `TEMPLATE_FILL_DOC_CHUNK_CHARS` | 12,000 | 006 자동 채움 조각 |
| `TRANSLATE_GLOSSARY_*` | — | **비우면 용어사전이 통째로 꺼진다** |
| `GENON_DEBUG` | **1 (켜짐)** | 디버그 에코. 테스트 기간 한정 |

### 프롬프트는 **배포 단위 밖**이다

```
<배포 단위 루트>/          ← 등록되는 저장소
prompt/<배포단위이름>/      ← 이미지에 함께 넣는다. **디렉토리 이름이 계약이다**
```

로더가 배포 단위에서 위로 올라가며 `prompt/<배포단위이름>` 을 찾는다. 이름이 어긋나면
**기동과 `/health` 는 통과하고 첫 요청에서 500** 이다.

**찾는 순서: 프롬프트 라이브러리(ID) → 파일.** `<단위>_PROMPT_IDS` 에 `이름=ID` 를 주면
그 이름만 덮어쓰고, 없거나 못 읽으면 파일로 돌아간다. `GET /prompts` 가 어느 쪽을 썼는지
말한다 — 이게 없으면 "ID 를 안 넣었다" 와 "넣었는데 못 읽었다" 가 화면에서 똑같이
옛 문구로 보인다.

## 13. 설계를 관통하는 원칙 넷

이 문서 곳곳에서 같은 판단이 반복된다. 그림을 그릴 때 이 넷을 축으로 잡으면 된다.

### ① 조용히 틀리지 않게 한다

예외를 던지지 않고 결과만 달라지는 실패가 제일 위험하다. **없어진 자리에 흔적이
남지 않기** 때문이다.

- 프롬프트 템플릿이 없으면 **빈 프롬프트로 넘어가지 않고 요청을 세운다** — 지시문 없는
  LLM 의 결과는 정상 응답처럼 내려간다.
- 늘 `null`·빈 배열인 필드를 두지 않는다 — 읽는 쪽이 **"확인했다" 고 믿게 만든다.**
- "안 쟀다" 를 "통과" 로 보이게 하지 않는다.

### ② 프롬프트 지시를 보장으로 보지 않는다

"표를 유지하라" 고 쓰는 것과 표가 유지되는 것은 다른 일이다.

- 번역 비스트리밍은 **구조를 코드가 쥔다**(스켈레톤 분해).
- 스트리밍은 그럴 수 없으므로 **감수한 것을 지문 대조로 알린다.**
- 006 자동 채움은 프롬프트에서 채워진 항목을 빼고, **그래도 온 값을 다시 버린다.**

### ③ 막지 않고 알린다 — 다시 할지는 사용자가 정한다

자동 재시도·재번역을 하지 않는다. 사용자가 고르지 않은 LLM 호출을 쓰면서 **결과가
나아진다는 보장이 없다.** 사실만 `notice` 로 낸다.

단, **되돌릴 수 없는 것이 나가기 전에는 막는다** — 오류 경로에서 018 셋은 토큰을
한 개도 흘리지 않고, FAQ 는 기각될 항목을 화면에 내보내지 않는다.

### ④ 화면에 그릴 값만 내보낸다

내부 판정·지표(준수율·폴백률·기각 건수)는 **로그가 갖는다.** payload 에 실으면 쓰지 않는
값이 아무도 안 읽는 채로 계약에 남아 나중에 바꿀 때 발이 묶인다.

## 14. 아직 실환경에서 확인되지 않은 것

그림에 **점선으로 그려야 할 자리**다. 넷 다 "오류 없이 조용히 다르게 동작" 한다.

| | 깨지면 어떻게 보이나 | 고칠 자리 |
|---|---|---|
| **`<mark>` raw HTML 렌더** | 형광 대신 태그 글자가 보인다 — 018 두 기능의 핵심 표시가 통째로 | 백엔드 상수 2곳 |
| **스트리밍 4경로** | 중간 프록시가 SSE 를 모으면 "한방에" 와 **구분되지 않고 오류도 없다** | 각 `llm.py` |
| **MCP 상태 유지 모드** | `400 Missing session ID` | `_mcp_call` 하나 |
| **MinIO `download_url`** | 링크가 늘 `null` → 폴백으로 떨어진다 | `file_store.py` 4벌 |

**설계상 남겨 둔 공백 셋** (전부 "두 사건이 한 값으로 나간다"):

- 용어사전 — "안 쓰기로 했다" 와 "설정을 빠뜨렸다" 가 둘 다 `not_configured`
- 006 `download_url: null` — "아직 다 안 채웠다" 와 "업로드 실패" 를 구분할 수 없다
- `polish_title`/`translate_title` — 읽는 코드는 있는데 **채우는 자리가 없어** 파일 이름이
  언제나 기본값이다
