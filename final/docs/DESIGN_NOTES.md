자동 로드되지 않는다. 기능을 고칠 때 해당 절을 찾아 읽는다.

## 공통·SFR-018

### hwpx 표 — 병합·중첩은 HTML 로 낸다

**마크다운 표에는 병합 문법이 없다.** 그래서 `rowSpan`/`colSpan` 이 빈 칸이 되고 중첩 표는
한 덩어리 텍스트로 뭉개진다:

```
| 구분 | 2025년 실적 |   | 비고 |   ← colSpan 사라짐 → 3열이 빈칸
|   | 상반기 | 하반기 | - |        ← rowSpan 사라짐 → 1열이 빈칸
| 세부 | 소분류<br>값 |   |   |     ← 중첩표가 텍스트로 뭉개짐
```

**수치는 남는데 그 수치가 무엇의 값인지가 사라진다.** 요구사항 §5 의 "표 깨짐" 이 이것이고,
렌더러 버그가 아니라 **형식의 한계**라 마크다운으로는 못 고친다.

- **손실이 있을 때만 HTML.** 병합·중첩이 있으면 `<table><tbody><tr><td rowspan="2">…`,
  없으면 마크다운 그대로. 잃을 게 없는 표까지 바꾸면 토큰만 늘고 읽기 나빠진다.
- **새 형식이 아니다.** 지능형 전처리기도 한 줄 HTML 표를 내고, 번역 스켈레톤
  분해기(`markdown_units`)에 그 경로(`_HTML_TABLE_REGION_RE`·`_split_html_table`)가
  있다. **이미 지원하는 형식**으로 내므로 하위 경로를 건드리지 않는다.
- **적용 범위는 LLM 입력 경로 둘**: 번역 `office/hwpx_text.py` ·
  FAQ `faq/hwpx_text.py`. **006 `hwpx_markdown.py` 는 제외** — 그쪽 출력은 채팅 화면
  미리보기용이라 마크다운이 맞다. 첨부 문서는 전처리기가 읽으므로 이 둘은 **직접 업로드
  경로**(`POST /translate/hwpx`·FAQ `POST /generate/upload`) 전용이다.
- **전처리기(area 05)는 이 규칙과 다르다** — `final_preprocessor.py` PART 2 는 병합이 없는
  표도 **언제나 HTML** 로 낸다. RAG 검색 결과가 프롬프트로 조립될 때 개행이 뭉개져
  마크다운 표가 통째로 무너지기 때문이다. 위 코드서빙 사본들은 그 경로를 지나지 않으므로
  마크다운을 유지한다.
- **셀 텍스트는 소유 셀 기준으로 뽑는다**(`_owning_cell`). `tc.iter(hp:p)` 로 뽑으면 중첩 표
  안 문단까지 딸려온다.
- **덮인 자리에 `<td>` 를 내지 않는다.** 내면 그 행만 열이 하나 늘어난다.

**그물**: 무손실 왕복(항등 번역 시 문자 단위 동일)·태그열 불변·숫자 셀이 번역 단위가
되지 않음·엔티티 왕복을 `Test/SFR-018/tests/test_hwpx_tables.py` 가 지킨다.
`check_table_grid.py` 는 세 층이다 — 단순표, 병합표, **누락 방지**(코드서빙 사본 + 전처리기).

### MCP 는 서빙이 아니라 **파일 하나**다

GenOS MCP 등록은 **소스 파일 한 개**를 받아 실행하고 `mcp` 객체를 런타임이 전역으로
주입한다. 도구는 `@mcp.tool()` 로 등록하고 **JSON 문자열**을 돌려주며, 엔벨로프는
런타임이 씌운다. FastAPI 앱·`/health`·`$PORT`·`requirements.txt`·손으로 짠 `/mcp`
JSON-RPC 라우트는 전부 우리 몫이 아니다.

- **파일 4개**: `final/mcp/genon_{text_guard,lang_policy,glossary,pii_audit}.py`.
- **모든 최상위 심볼에 파일별 접두어**(`TG`/`LP`/`GL`/`PA`). 한 서버에 여러 도구 파일이
  함께 로드될 수 있고, 겹치면 나중 것이 앞엣것을 덮는다 — 그 실패는 "도구가 이상한 값을
  낸다" 로만 드러난다. **도구 함수 이름만 예외**(LLM 에 노출되는 계약이라 못 붙인다).
- **`""` 주입 대비.** GenOS 는 값이 없을 때 `None` 이 아니라 빈 문자열을 준다. 선택
  인자를 `int`/`float` 로만 선언하면 **본문에 닿기 전에 타입 검증에서 죽는다.**
- **`mcp` 미주입 대비 shim** 이 없으면 로컬에서 파일을 열어 볼 수조차 없다.
- **`requirements.txt` 가 없다.** 비표준 패키지는 파일 안에서 설치해야 하므로 표준
  라이브러리로 쓴다(용어사전 조회도 `urllib`).
- **기동 훅이 없다.** 용어사전 적재는 첫 도구 호출로 미룬다 — import 가 느리면 서빙이
  왜 안 뜨는지 드러나지 않지만, 첫 호출로 미루면 그 지연이 그 호출의 지연으로 보인다.

**접두어를 붙이거나 이름을 바꿀 때 걸리는 함정 셋:**

1. **정규식으로 이름을 바꾸면 문자열 리터럴까지 바뀐다.** `resolve_tone` 은 함수 이름이자
   도구 이름 문자열이라 `_HANDLERS` 의 키가 바뀌면 그 도구가 통째로 `UNKNOWN_TOOL` 이
   된다. → 토큰 단위로 바꾸고 문자열은 건드리지 않는다.
2. **별칭 import 를 놓치면 호출부만 옛 이름으로 남는다.**
   (`from .languages import supported_payload as supported_languages`) — 정의부는 접두어가
   붙는데 호출부는 그대로라 `NameError`. **import 는 통과하므로 도구를 실제로 불러야**
   드러난다.
3. **다른 파일이 같은 이름을 정의하면 뒤엣것이 앞엣것을 덮는다.** `languages.py` 와
   `registers.py` 가 둘 다 `supported_payload` 를 가지면, 합친 뒤 `list_languages` 가
   **문체 목록**을 돌려준다.

**`resolve_register` 는 `Register.key` 로 값을 꺼내고 `fell_back` 을 응답에 싣는다.**
없는 속성(`code`)을 `getattr` 기본값으로 읽으면 파이썬 repr 이 응답에 통째로 실리고,
`fell_back`(기본값으로 떨어졌다는 사실)이 없으면 사용자가 고른 문체가 조용히 무시된다.

**그물**: `check_mcp_tools.py` 가 네 파일을 **한 네임스페이스에 넣어** 덮이는지 보고, 도구를
직접 불러 결정적 판정과 빈 문자열 주입을 확인한다. `check_deploy_contract.check_mcp_files()`
가 접두어·`async … -> str`·shim·상대 import 금지를 정적으로 본다. 상세는 `final/mcp/README.md`.

### 선택지는 **도구 스키마로 강제한다**

언어·문체·문서유형·톤은 **백엔드가 표를 갖고 있는 값**이다. 노출되는 스키마에 "문자열"
이라고만 적히면 **선택지가 계약 어디에도 없어** 호출부(캔버스 화면·워크플로우 변수·도구를
고르는 LLM)가 자기 목록을 들고 있게 되고, 언어가 늘거나 빠질 때 한쪽만 고친다 — 예외는
나지 않고 빈 드롭다운이나 "지원하지 않는 언어입니다" 로만 드러나 **사용자에게는 백엔드가
막은 것처럼 보인다.**

표(`LPSUPPORTED_LANGUAGES`·`LPREGISTERS`·`LPDOC_TYPE_POLICIES`·`LPTONE_PRESETS`·
`_GLLANGUAGE_CODES`)에서 `enum` 을 **만들어서** 얹는다. `Literal[...]` 이 아니다 —
그러면 별칭(`"한국어"`·`"korean"`·`"문어체"`)이 타입 검증에서 죽고, `allowed=false`·
`tone_overridden`·`fell_back` 처럼 **"고른 값이 조용히 무시되지 않게" 하려고 만든 판정**이
전송 실패와 구분되지 않는 형태로 바뀐다. **스키마에는 선택지를 싣되 판정은 본문이 한다.**
근거와 적용 자리 표는 `final/mcp/README.md` §4-1.

- **`pydantic` 은 감싼 선택 의존이다.** FastMCP 가 스키마를 만들 때 이미 쓰는 패키지라
  따로 설치할 것이 아니고, 없으면 맨 `str` 로 떨어져 그냥 돈다.
  `check_deploy_contract._mcp_guarded_imports` 가 **다시 던지지 않는** try/except 만
  선택 의존으로 친다 — `except ImportError: raise` 는 감싸지 않은 것과 결과가 같다.
- **`genon_glossary` 는 언어를 정규화한다**(`glnormalize_lang`, 두 핸들러 입구). 정규화가
  없으면 `"KO"`·`"한국어"`·`"ko-KR"` 이 색인 키와 안 맞아 `language_missing` 으로 떨어지고,
  **용어사전만 조용히 빠진 번역**이 나간다 — 대조할 용어가 없으니 준수율은 늘 1.0 이라
  정상으로 보인다. 언어 표는 `genon_lang_policy` 와 같은 내용이다(사본 대조 대상).
- **그물**: `check_mcp_tools.py` 가 스키마를 **시그니처에서 실제로 만들어** 표와 대조하고
  (손으로 적은 기대값이 아니다), 사전을 하나 적재해 놓고 표기 5종으로 조회한다 — 미적재
  상태에서는 어떤 표기든 똑같이 `enabled=false` 라 **정규화를 되돌려도 통과**하기 때문이다.

### 원문 언어 — 감지는 폴백이 아니라 **교차검증**이다

**enum 이 강제하는 것은 "어떤 값이 칸에 들어올 수 있는가" 이고, 감지가 답하는 것은
"업로드한 문서가 무슨 언어인가" 다.** 후자는 드롭다운이 아니다.

`archive/data/translation_rule.md` §2 가 사용자에게 고르게 하는 것은 **대상 언어와 문체**다.
§6 은 "한국어가 아닌 쌍(`en→ru`)은 고려 X" 를 요구하는데, 이 축을 집행하려면 원문 언어를
알아야 하고 그것은 **선택으로 보장되지 않는다.** 감지가 §6 의 유일한 집행 수단이다.

화면에 원문 드롭다운이 있으므로 선언을 믿기만 하면 이렇게 된다:

> "한국어 → 러시아어" 를 고르고 **영어 문서**를 올린다 → 실제 방향은 `en→ru` →
> §6 이 막으려던 바로 그 쌍인데 **선언을 믿어 그대로 통과**한다.

그래서 **`source_lang` 이 와도 항상 감지하고 선언과 대조한다.** 다만 **정본은 선언값이다** —
감지가 사용자의 선택을 조용히 덮으면 이 코드가 없애려는 바로 그 실패 형태가 된다
(`fell_back`·`tone_overridden` 과 같은 취지). 감지는 **거부의 근거로만**, 그것도 §6 이
실제로 깨질 때만 쓴다.

- **거부 판정을 최빈값으로 하지 않는다.** `본 사업 KPI 는 ROI, TCO, SLA, API, SDK 로
  관리한다` 는 라틴 문자가 **62%** 라 최빈값으로는 영어이고, 60% 문턱이면 이 **멀쩡한
  한국어 문장이 거부된다** — 사용자에게는 우회할 방법이 없는 오차단이다. 판정 근거는
  **"선언한 언어의 문자가 문서에 사실상 없는가"**(`declared_share < 10%`)다 — 영어 문서에
  한글은 0% 이고, 영문 용어가 많은 한국어 문서도 한글은 20% 밑으로 잘 안 내려간다.
- **통과하는 충돌은 막지 않고 보고한다.** 대상이 한국어면(`th`선언 + 한국어 문서 →
  `ko`) 어느 쪽으로 읽어도 §6 을 어기지 않으므로 진행하고, `source_mismatch` 로 알린다.
- **사본이 2벌이다** — MCP `genon_lang_policy.py`(워크플로우 경로)와 번역 코드서빙
  `office/languages.py`(직접 업로드 `POST /translate/*` 경로). **직접 업로드는 MCP 를
  지나지 않으므로** 한쪽만 고치면 그 경로에 뒷문이 남는다. 둘을 같은 코드로 두고
  점검도 각각 태운다(`check_mcp_tools`·`check_unit_endpoints`).
- `resolve_direction` 은 `(source, target)` 튜플 대신 **`DirectionVerdict`** 를 돌려준다.
  "원문 언어를 어디서 얻었나"(선언인가 감지인가·어긋나지는 않았나)가 튜플로는 경계를
  넘지 못한다.

### 근거 대조는 MCP 에 두지 않는다

근거 대조는 FAQ 코드서빙이 자기 안에서 한다(`faq/evidence.py`). MCP 에 같은 판정부를 두면
**운영 호출부가 없는데 갈릴 수 있는 사본**이 된다 — 근거 규칙(n-gram 크기·min_ratio)을
고치면 MCP 쪽만 옛 판정을 계속 내고, 그걸 부른 LLM 은 서빙과 **다른 답**을 받는다.
오류로는 드러나지 않는다.

- **점검은 정본을 태운다** — `Test/SFR-018/tests/test_faq_evidence.py`(`faq/evidence.py`
  직접 import). 사본을 태우는 점검은 운영 코드를 한 번도 검증하지 않는다.
- 다시 필요해지면 `faq/evidence.py` 에서 **옮겨 적는다**(그쪽이 정본이다).
- **`detect_language` 는 같은 경우가 아니다.** 운영 호출부는 없지만 감지 판정 자체를
  `validate_direction` 이 쓰고 도구는 그 내부 판정을 밖에 내놓은 것뿐이라 **사본이 아니고
  유지 비용이 없다.** 남긴다.

### 변경 하이라이트 — `diff_changes` (MCP `genon_text_guard`)

> **글다듬이 스텝은 지금 이 도구를 부르지 않는다** — 다듬기가 문장을 크게 다시 쓰는 일이
> 흔해 낱말 단위 형광이 문서 전체를 뒤덮어 "무엇이 바뀌었나" 를 오히려 가린다. 그래서
> `original_text`·`polished_text` 는 `<mark>` 없이 나간다(`final/docs/FRONT.md` §1.4,
> `sfr018_polish_02_polish.py` 머리말). 도구는 MCP 에 남아 있고, 아래는 그 도구의 설계다.

**사본을 만드는 것과 화면에 쓰는 것은 다른 일이다.** 사본·좌표·겹침 병합 코드가 다 있어도
스텝이 정본을 화면에 흘리면 하이라이트는 한 번도 나타나지 않고, 값은 정상이므로 로그로도
드러나지 않는다.

#### 좌표가 없으면 인라인 하이라이트는 성립하지 않는다

`{before, after}` 문장 쌍만 내면 프론트가 `after` 문자열을 본문에서 **다시 찾아야** 하고,
같은 낱말이 두 번 나오면 어느 쪽을 칠할지 결정할 수 없다. 문장으로 쪼갠 뒤 `strip()` 을
걸면 위치가 복원 불가이므로 `_TGsplit_units_with_spans` 가 `(텍스트, start, end)` 를 낸다
(`re.split` 은 위치를 버리므로 `finditer` 로 자른다).

- **문장이 아니라 낱말 단위**다. 문장 쌍을 그대로 칠하면 문장 전체가 형광이 되어 **어느
  낱말을 손질했는지가 오히려 묻힌다.** 바뀐 단위 쌍을 낱말로 한 번 더 갈라
  (`_TGword_changes`) 그 안에서 달라진 낱말만 뽑는다.
- **좌표는 `source_span`/`target_span` 둘이다.** 삭제는 결과 쪽에 칠할 글자가 없지만
  좌우 비교에서는 **왼쪽에 자리가 있다** — "어느 쪽에 자리가 있느냐" 로 갈린다. 자리가
  없는 쪽은 `None` 이다(0 을 넣으면 문서 맨 앞이 칠해진다). 좌표가 둘인데 필드를 셋 두면
  남는 하나는 언제나 사본이라 단일 `span` 은 내지 않는다.
- **좌표와 표시를 한 함수에 두지 않는다.** `changes[]` 의 좌표를 그대로 내보내고(프론트가
  자기 방식으로 칠할 수 있어야 한다), `<mark>` 사본은 따로 만든다.
- **건수 상한을 두지 않는다.** 잘린 목록으로 `highlighted` 를 만들면 그 상한이 곧
  하이라이트 상한이 되어 그 뒤 변경에는 `<mark>` 가 아예 붙지 않는다. 크기의 실제 상한은
  **입력 길이**(`_TGMAX_TEXT_CHARS`)가 잡고, 넘으면 자르지 않고 요청을 세운다. 언제나
  false 인 `truncated` 같은 필드는 읽는 쪽이 "확인했다" 고 믿게 만들므로 두지 않는다.

#### 태그는 `<mark>` 다 — `<strong>` 은 원문 강조와 구분되지 않는다

`**`/`<strong>` 은 **원문에도 나오는 표기**다(전처리기가 HTML 을 낸다). 굵게 보여도 그것이
사전 용어인지 원문 강조인지 화면에서 가릴 수 없고, **가리는 것이 요구사항 §2 의 요점**
이다. `<mark>` 는 본문에 쓰이지 않고 기본 렌더가 형광이다. 태그는 상수 두 개
(`glossary_report._OPEN_TAG`·`genon_text_guard._TGMARK_OPEN`)에만 있어 렌더러가 raw HTML 을
막으면 그 둘만 고친다 — **그 허용 여부는 미확인이다.**

#### 정본은 손대지 않는다

다운로드 파일은 정본으로 만든다. 태그가 섞이면 사용자가 메모장에서 지워야 하고, 파일
단계에서 **지우는** 방식은 원문에 원래 있던 태그까지 지운다. 그래서 "정본 + 표시용 사본"
두 갈래로 둔다.

#### 칠하면 손상이 되는 두 구간

- **코드펜스 안** — `<mark>` 가 화면에 글자 그대로 나온다.
- **HTML 태그** — `<td rowspan="2">` 가운데를 가르면 표가 통째로 깨진다.

**피하는 것만으로는 반대 결함이 생긴다.** 낱말을 공백으로만 끊으면 전처리기가 낸 한 줄
HTML 표가 **통째로 낱말 하나**가 되고, 그 구간은 태그에 걸치므로 버려진다 — **HTML 표 안
변경을 영영 칠하지 못한다.** 그래서 낱말을 끊을 때 HTML 태그를 따로 끊는다(`_TGWORD_RE`).
보호 구간은 **각 텍스트에서 따로 계산한다** — 원문과 결과에서 태그 위치가 다르므로 한쪽
좌표를 다른 쪽에 쓰면 태그 한가운데를 가른다.

#### 1:1 정렬 — 프롬프트가 요청하고 **코드가 검증한다**

`difflib` 의 성질에서 나오는 결함이 둘이다:

| 증상 | 원인 |
|---|---|
| 형광이 **줄바꿈을 넘어** 칠해진다 | 문장 레벨 diff 가 여러 문장을 한 덩어리 `replace` 로 묶으면, 그 안의 낱말 LCS 가 **경계를 넘어** `("임. 자료", "입니다.")` 같은 항목을 만든다 |
| 문장이 **자리를 옮기면** 양쪽이 통째로 형광 | `SequenceMatcher` 는 **순서 보존(LCS)** 이라 교차하는 짝을 못 만든다 — 이동이 **삭제 + 삽입** 두 사건으로 쪼개진다 |

삽입·삭제 자체는 LCS 라 밀리지 않고 한 건으로 정확히 잡힌다.

문장을 1:1 로 되쓰게 하면 짝이 이미 정해져 **이동·경계 넘김이 원천적으로 불가능**해진다.
그런데 **프롬프트 지시를 보장으로 보지 않는다**(§5)가 이 저장소의 규약이라, 요청해
놓고 `diff_changes` 가 **센다**:

- 단위 수가 같고, 각 짝이 서로 닮았으면 → **`i↔i` 고정**, 문장 레벨 diff 를 아예 안 돈다.
- 아니면 → `difflib` 경로.

검증이 없으면 모델이 문장 하나를 더 쓴 순간 **뒤가 전부 한 칸씩 밀려** 문서 전체가
형광이 된다 — 예외는 나지 않고 화면만 무의미해진다.

- **문턱이 둘인 이유.** 짝 하나가 크게 다시 쓰였다고 문서 전체를 폴백시키면 이 경로가
  거의 안 탄다. 반면 이동·밀림은 **거의 모든 짝**을 어긋나게 한다 — 그래서 짝별 문턱은
  낮게(`_TGMIN_PAIR_SIM` 0.2), 몇 개까지 봐줄지는 따로 둔다(`_TGMAX_MISALIGNED_RATIO` 0.2).
- **`max(1, …)` 로 한 칸은 언제나 봐준다.** 비율만 쓰면 **다섯 문장 미만 문서에서
  허용치가 1 밑으로 떨어져 무관용**이 되고, 한 문장만 크게 다시 써도 전체가 폴백한다.
- **유사도는 문자 3-gram 다중집합 자카드**다. `SequenceMatcher.ratio()` 는 짝마다
  O(len²) 이고 문서 하나에 문장이 수백 개다.
- **크게 다시 쓰인 짝은 통째로 한 항목.** 한 짝 안에서 크게 다시 쓰이면 조사·흔한 낱말만
  `equal` 로 남고 나머지가 흩어져 **형광이 누더기**가 된다. 바뀐 낱말이
  `_TGMAX_WORD_CHANGE_RATIO`(0.6)를 넘으면 접는다. **항목이 둘 이상일 때만** 접는다 — 한
  건짜리는 이미 통째 표시라 접으면 앞뒤 안 바뀐 낱말까지 형광에 들어간다.
- **`clear` 톤은 이 규칙에서 뺀다.** "명확·간결" 의 지시문이 **"한 문장에 한 가지만 담고"**
  라 **문장을 나누라는 지시**이고 1:1 과 정면으로 충돌한다. 그 톤에서는 문장 수가 달라져
  자연히 폴백으로 흐른다.
- **규칙 문장은 프롬프트 디렉토리에 있다** (`sentence_rule.txt`) — §10.5 가 코드 안 프롬프트
  인라인을 금지하고, 이 경로면 라이브러리(`sentence_rule=ID`)로도 덮는다. **렌더 실패는
  요청을 세우지 않는다** — 그 줄이 빠지면 1:1 요청 없이 돌 뿐이라, 없어도 되는 지시 하나가
  기능을 막으면 안 된다(톤 프롬프트 폴백과 같은 규약).
- **`diff_changes` 는 톤을 모른다.** 정렬 판정은 **결과를 보고** 하므로 도구 인자가 늘지
  않는다 — 톤을 넘기면 MCP 계약이 넓어지고 호출부가 그 값을 들고 다녀야 한다.

**그물**: `Test/SFR-018/tests/test_diff_highlight.py` — 좌표가 실제로 그 낱말을 가리키는가
(`revised[start:end] == after` 등식이 하이라이트의 전부다), 같은 낱말이 두 번 나올 때 뒤쪽을
가리키는가, 태그를 떼면 정본으로 돌아오는가, HTML 표 셀·코드펜스·겹침·어긋난 좌표, 1:1 분기.
**손으로 지은 예제로는 두 경로가 갈리지 않는다** — 짧은 존댓말 변환 예제에서는 1:1 을 꺼도
같은 답이 나온다. 무작위 대조로 두 경로가 **다른 답을 내는 입력**을 찾아 픽스처로 박았고,
접기 판정도 **공통 낱말이 흩어진** 입력을 쓴다. `check_workflow_run` 은 `diff_changes`
대역 응답을 **실제 MCP 도구로 만든다**(`_load_mcp`) — 손으로 적으면 도구가 키를 바꿔도
사본이 그대로라 스텝이 엉뚱한 키를 읽어도 통과한다.

### 한국어 조사는 **조회할 때** 뗀다 — 프롬프트·지표·표시가 함께 걸린다

토큰이 `[가-힣]+` 라 `가맹점을` 이 한 덩어리다. 떼지 않으면 사전의 `가맹점` 과 매칭되지
않고, 그 실패가 **방향마다 다른 얼굴**로 나타난다:

| 방향 | 어디서 깨지나 | 증상 |
|---|---|---|
| ko→en | `match_occurrences` 0건 | **그 용어가 프롬프트에 실리지 않는다** — LLM 은 "가맹점 → merchant" 를 들은 적이 없다. 준수율은 `matched_count=0` 이라 **1.0** |
| en→ko | `contains_phrase` False | `신용회복위원회를` 로 제대로 옮겼는데 **준수율 0.0** 이고 양쪽 하이라이트가 안 붙는다 |

**두 증상이 반대 방향(1.0 / 0.0)이라 지표만 보면 서로를 가린다.**

- **형태소 분석기는 필요 없다.** 사전 용어는 대부분 명사이고 뒤에 붙는 조사는 **닫힌
  목록**이라 영어 `_EN_SUFFIX_RULES` 와 같은 구조로 끝난다.
- **색인이 아니라 조회할 때 뗀다.** 색인 키에 절단을 걸면 사전 표제어가 함께 깎여
  `신용도` 가 `신용` 으로 굳고 **원래 용어가 사라진다.** 문서 쪽 토큰만, 그것도 **정확
  일치를 먼저 찾아보고 없을 때만** 뗀다 — 사전에 `신용도`·`신용` 이 둘 다 있으면
  앞엣것이 이긴다.
- **세 함수가 같은 규칙이다.** `match_occurrences`(매칭·프롬프트 선정·원문 좌표)
  ·`contains_phrase`(준수율)·`phrase_positions`(번역문 좌표)가 **같은 토큰화·정규화**를
  공유한다. 뒤의 둘이 갈리면 "썼다는데 위치는 못 찾는" 상태가 된다.
- **칠하는 구간은 문서에 실제로 적힌 글자다** — `<mark>신용회복위원회를</mark>` 처럼
  조사까지 덮는다. `invoice` 가 `invoices` 를 덮는 규약과 같다.
- **남는 한계**: 3자 이상이면서 조사 글자로 끝나는 표제어(`신용도`)가 사전에 없고
  절단형만 있으면 그쪽으로 걸린다. 과절단은 **떼고 2자 이상** 가드가 막는다(`추가`→`추`).
- **사본 2벌** — 번역 `glossary_exact.py` · MCP `genon_glossary.py`. 한쪽만 고치면
  워크플로우 경로와 직접 업로드 경로가 **다른 용어 목록**을 쓴다.
- **그물**: `check_mcp_tools`(조사 폴백 3갈래 + 과절단 가드), `test_glossary_policy`
  (방향별 증상·과절단·정확 일치 우선·여러 낱말 용어).

### eval 가드레일은 **재지 않고 통과하지 않는다**

`Test/eval` 은 네 기능의 합불을 정하는 코드다. 여기가 조용히 틀리면 **틀린 기준으로 합격
도장을 찍는다** — 그래서 `check_eval_metrics.py` 가 회귀 점검을 맡는다. 아래는 그 점검이
지키는 결함 유형이다. 전부 예외를 던지지 않고 리포트는 정상으로 보인다.

| 결함 유형 | 어떻게 보이나 |
|---|---|
| **미측정인데 0.0** | 화이트리스트(템플릿 스키마)를 안 주면 환각률 `rate: 0.0` → 기준 `< 0.05` 를 **한 번도 재지 않고 늘 통과** |
| **빈 비교로 만점** | `pairs` 키를 다른 별칭으로 주면 `structure_pass_rate` 가 `""` 와 `""` 를 비교해 **1.0** |
| **평범한 낱말을 조사 오류로** | `평가`·`증가`·`국가`·`가을`·`사과` 를 오류로 내면 그런 낱말이 든 문서가 **톤 불합격** |
| **슬롯 잔여 표기를 값으로** | 안 채운 `{'제목', 16pt}` 를 `filled` 로 세면 부분 초안에서 `agreement_rate`·`guide_state_kept` 가 **정확히 반대**로 나온다 |
| **자카드가 문서 길이에 반비례** | 같은 답변이 짧은 원천 1.0 → 200문장 원천 0.2. 길이에 따라 값이 달라지면 **임계를 걸 수 없다** |
| **한 문장짜리 문서는 늘 어미 불일치** | 뒤 절반이 비어 우세 유형이 `other` → 짧은 문서만 모으면 이 지표가 0 이 된다 |
| **카탈로그 밖 운영 지표** | "표에 없는 도구는 운영 지표가 아니다" 가 규약인데 그 도구가 합불 기준이면 규약이 무너진다 |

**대부분 "재지 않고 통과" 쪽으로 틀린다.** 가드레일에서 이 방향의 오류가 제일 나쁘다
(불합격 쪽으로 틀리면 사람이 바로 알아챈다).

- **입력 쌍의 키 해석은 `pairs.py` 한 곳이다.** 원문이 없으면 **예외**이고
  (빈 비교로 만점을 주지 않는다), 결과가 없으면 **불합격**이다(측정 불가가 아니다 —
  다듬기·번역이 아무것도 못 내놓은 것은 실제 실패다).
- **조사 검사는 앞말이 명사임을 아는 자리에서만 한다.** 받침 판정 자체는 정확하지만
  **무엇이 조사인지**를 형태소 없이 알 수 없다. `으로/로` 만 보는 절충도 안 된다
  (`진로`·`선로`·`항로`). `nouns`(사내 용어사전 표제어)를 준 자리에서만 재고, 검사
  여부를 `particle_check.scope` 로 낸다 — **미검사를 통과로 보이게 하지 않는다.**
- **집계는 항목 하나 때문에 죽지 않는다.** 원천 없는 FAQ 항목·빈 결과물이 예외를 내면
  나머지 99건의 채점이 통째로 사라진다. 단건 도구는 엄격하게 두고(쓰레기가 들어오면
  오류) **집계가 감싸서** `unmeasurable` 로 드러낸다.
- **`chrF` 는 `Counter` 다중집합 교집합으로 센다.** `list.remove` 반복은 O(n²) 라 문서가
  열 배면 백 배다.
- **점검의 네 번째 층이 제일 값어치 있다**: `SUITES[…]["targets"]` 의 경로가 실제
  산출물에 도달하는지 **완전한 입력을 주고** 본다. 지표 키를 한 번 바꾸면 그 기준은
  **영원히 `not_measured`** 가 되는데, 그 상태는 리포트에서 "아직 안 쟀네" 로만 보인다.

### PII 마스킹 누락을 **네 기능 출구에서** 잡는다 — eval

민감정보 마스킹(#315)은 적재 전처리기(첨부용 `guardrail`)의 몫인데 **그 층이 없어도
조용하다.** 사이트 설치본에 모듈이 없거나 설정이 꺼져 있으면 적재는 성공하고 검색도 되며,
네 기능이 그 텍스트를 최종 답변에 **원문 그대로** 싣는다. 오류가 없으니 로그에도 안
남는다 — 사용자가 화면에서 주민등록번호를 발견할 때까지 아무도 모른다. `pii_leak_count`
가 그 출구를 본다.

- **비율이 아니라 절대 건수다.** 허용치가 0인 값에 비율 기준을 걸면 200문장 문서의
  1건이 0.5% 라 임계를 통과한다 — **기준이 사고를 승인한다.**
- **네 기능이 같은 지표를 같은 방식으로** 돈다(`suites._run_pii`). 마스킹 누락은 기능
  고유의 실패가 아니라 그 텍스트가 넷을 모두 통과하는 것이라, 기능마다 다르게 재면 안 된다.
- **`leak_count == 0` 은 "개인정보 없음" 이 아니다.** `detectors` 에 적힌 유형만 본다 —
  이름·주소·계좌번호는 안 센다(NER 이 없고, 계좌번호는 체크섬이 없어 일반 숫자열과
  구분되지 않는다). 그 공백을 응답에 싣는다. `masked_count` 도 함께 낸다 —
  `leak=0 · masked=0` 은 "개인정보가 없던 문서" 와 "아무것도 안 돌았다" 가 구분되지 않는다.
- **체크섬으로 오탐을 거른다**(주민·사업자·카드). **오탐은 결국 미탐으로 간다** —
  가드레일이 상시 빨간불이면 사람이 임계를 올리거나 지표를 끈다.
- **검출한 값은 응답에 담지 않는다**(3.8절). 자리와 유형만 낸다 — 담으면 평가 리포트가
  유출 경로가 된다.
- **채점 전에 `<mark>` 를 벗긴다.** payload 의 텍스트는 하이라이트 사본이다. 태그째
  채점하면 어미가 `…습니다</mark>` 로 끝나 종결어미 판정이 전부 `other` 로 떨어지고
  `ending_consistency` 가 **불합격이 아니라 미측정으로 조용히 빠진다.** `pairs.pair_texts`
  한 곳에서 벗긴다(집계기가 전부 거기를 지난다). **`<mark>` 만** 벗기고 `<table>` 은 남긴다.

### 긴 문서는 **끝까지** 처리한다 — 조용한 절단을 두지 않는다

상한을 잘못 다루면 예외 없이 결과가 멀쩡해 보이고 **없어진 자리에 흔적이 남지 않는다**:

| 단위 | 한 번에 부르거나 잘라 부르면 | 사용자에게 어떻게 보이나 |
|---|---|---|
| FAQ | 상한을 넘는 문서를 `source[:상한]` 으로 자르고 한 번만 호출 | 뒷부분 내용으로는 **FAQ 가 나올 수 없다.** 기각 건수에도 안 잡힌다 — LLM 이 본 적이 없으니 `ungrounded` 도 `duplicate` 도 아니다 |
| 글다듬이 | 문서 전체를 한 번에 호출 | 상한에 닿기 한참 전에 **`RES_TIMEOUT`(90초)이 먼저** 난다. 재시도 가능으로 분류돼 같은 자리에서 또 걸린다 — "긴 문서는 그냥 안 되는 기능" |

**실질 상한은 업로드 용량이다** (요구 확정). 그 안쪽 문서는 끝까지 처리한다.

- **FAQ 는 조각마다 자기 몫을 만든다.** 호출 수는 **호출 수 상한**(`FAQ_MAX_CHUNK_CALLS`,
  기본 6)이 정하고, 태울 조각을 **고르게 표집한다**(`plan_quota`). 앞에서부터 채우면
  잘라 쓰는 것과 결과가 같아진다.
  - **사용자는 총 개수만 고르고 배분은 코드가 한다** (요구 확정). 고른 숫자가 곧 받는
    개수다. 구간당 개수를 고르게 하면 **고른 숫자와 받는 개수가 달라진다**(구간이
    여섯이면 5를 골라도 30개). 긴 문서에서 조각당 몫이 0 에 가까워져 그 구간 내용이
    후보에서 빠지는 것은 호출 수 상한이 막는다 — 태울 구간 수가 묶여 있어 조각이 많아도
    몫이 1 밑으로 내려가지 않는다. **개수는 사용자가, 비용은 배포가** 정한다: 한 손잡이에
    묶으면 둘 중 하나를 못 지킨다. `FAQ_MAX_COUNT` 기본값은 30 이다.
  - **상한에 걸려 못 태운 구간은 `coverage_capped` 로 알린다.** `source_truncated`
    (조각 수 상한)와 **다른 사건**이다 — 그쪽은 문서 뒤를 아예 안 본 것이고 이쪽은 전체를
    나눴지만 일부만 태운 것이다. 조용히 건너뛰면 사용자는 문서 전체에서 뽑은 결과로 읽고,
    **안 나온 내용이 문서에 없는 것으로 보인다.**
  - **`requested_count` 는 사용자 선택 그대로다**(상한으로 깎인 값만 반영). 호출 수 상한은
    `call_cap` 으로 나간다.
  - **번역·글다듬이에는 이 배분이 없다** — 개수를 뽑는 것이 아니라 **모든 유닛·조각을
    처리**하므로 나눌 몫 자체가 없다.
  - **근거 대조는 조각이 아니라 문서 전체로** 한다. 조각 경계가 문장 가운데를 지나면
    그 문장을 든 항목이 오탐 기각된다.
  - **중복 판정도 조각을 가로질러 공유**한다. 같은 주제가 여러 절에 나오면 조각마다
    같은 질문이 나오는데, 조각별로 따로 세면 그게 전부 통과한다.
  - `FAQ_MAX_CONTEXT_CHARS` 는 문서 상한이 아니라 **호출 한 번의 예산**이다(기본 12,000).
    `source_truncated` 는 "조각 수 상한(`FAQ_MAX_CONTEXT_CHUNKS`, 기본 80 ≈ 96만 자)에
    걸릴 만큼 길다" 를 뜻한다.
- **번역은 모든 유닛을 번역한다.** 네 경로(텍스트·마크다운·hwpx·스트리밍)가 상한 초과를
  **같은 방식으로**(오류) 다룬다. 파서에 `max_chars` 를 넘겨 넘는 만큼 버리면 번역 쪽
  `HwpxDocument` 에는 `truncated` 필드가 없어 **응답에도 로그에도 흔적이 없고**, 같은 문서를
  어느 경로로 넣었는지에 따라 결과가 달라진다.
- **글다듬이를 나눠도 되는 근거는 이 기능이 하는 일이다.** 내용을 다시 쓰는 것이
  아니라 **문체에 맞게 낱말·어미를 손질**한다 — 판단 단위가 문장이라 조각 경계 너머의
  문맥이 필요하지 않다(번역이 유닛 단위로 도는 것과 같은 근거).
  - **꼬리 공백을 코드가 되꽂는다.** LLM 은 응답 끝 공백을 지운다 — 다듬은 조각을 그냥
    이어붙이면 **문단 경계가 사라져** 제목과 본문이 한 줄이 된다. 조각을 (본문, 꼬리)로
    갈라 본문만 보내고 꼬리는 코드가 붙인다. 무손실 왕복이 계약이다.
  - **코드펜스·여러 줄 HTML 표 안에서 끊지 않는다** — 그 둘은 **안에 빈 줄이 올 수
    있어** 경계 규칙만으로는 갈린다. 절반만 보내면 그 조각의 출력이 표·코드로 보이지
    않고, `markdown_structure_issues` 가 잡는 훼손을 **우리가 만들어 내는** 셈이 된다.
    마크다운 표는 안에 빈 줄이 없어 그 자체로 안전하고, 따로 떼는 것은 앞뒤 문단이 붙어
    덩어리가 커지는 것을 막기 위해서다.
  - **실패한 조각 자리에는 원문이 들어간다.** 빈 문자열로 두면 그 구간이 통째로 사라진
    결과가 정상 응답처럼 나간다. **전량 실패만 오류**이고 부분 실패는 건수로 낸다
    (번역의 전량 폴백 규약과 같다).
  - **설정 부재는 첫 조각에서 끝낸다** — 재시도로 풀리지 않는 배포 문제라 조각 수만큼
    두드릴 이유가 없다.

### FAQ 조각을 **병렬로 부른다**

**조각 사이에 순서 의존이 없다** — 앞 조각의 결과가 뒤 조각의 프롬프트에 들어가지 않으므로
순차로 돌면 대기시간만 조각 수에 그대로 비례한다(기본 호출 상한 6조각이면 한 번 호출
시간의 여섯 배다). 번역은 배치를 `LLM_CONCURRENCY`(15)로, 글다듬이는 조각을
`POLISH_LLM_CONCURRENCY`(4)로 겹쳐 돈다.

- **호출만 겹치고 채택은 조각 순서대로 한다.** `_request_chunk` 는 공유 상태를 건드리지
  않는 순수 호출이고(프롬프트 렌더 + LLM), 판정·채택은 `generate_faqs` 가 `gather` 결과를
  받아 **조각 순서대로** 흘린다. 도착 순서대로 채택하면 중복 판정(`seen_questions`)·
  기각 건수·**조각별 채택 상한**(`현재 + 몫`)이 전부 누적 상태라 **같은 문서가 실행마다
  다른 분포를 낸다** — 오류로는 드러나지 않고 "어느 구간에서 몇 개가 나왔나" 만 흔들린다.
- **첫 실패에서 멈추지 않는다.** 호출이 이미 전부 나갔으므로 성공한 조각의 결과를 버리는
  것은 손해다. 실패는 **조각 순서 기준 첫 건**을 기록하고(전량 실패면 그것이 사용자에게
  나가는 분류다), 건진 항목이 있으면 부분 실패 규약대로 `chunks_used < chunks_planned` 로
  남는다.
- **동시 수는 별도 손잡이다** — `FAQ_LLM_CONCURRENCY`(기본 6). `FAQ_MAX_CHUNK_CALLS` 는
  "몇 번 부르나"(비용)이고 이쪽은 "동시에 몇 개가 도나"(대기시간)다. 기본값을 그 상한과
  같게 둬서 **기본 설정에서는 배정된 조각이 한 번에 다 뜬다** — 상한을 올린 배포에서만
  둘이 갈리고, 그때 게이트웨이에 실리는 부하는 이 값이 잡는다. 429 가 나면 여기부터 내린다.
- **조각 크기 기본값은 12,000자다** (요구). 겹쳐 도는 구조에서는 **조각 하나의 크기가 곧
  전체 대기시간**이다. 덮는 문서 길이가 줄지 않게 `FAQ_MAX_CONTEXT_CHUNKS` 를 80 으로 둔다
  (80 × 12,000 ≈ 96만 자) — 예산만 줄이고 조각 수 상한을 안 올리면 `source_truncated`
  문턱이 조용히 내려가고, 그 상태는 "왜 뒤쪽에서 FAQ 가 안 나오나" 로만 드러난다.
- **부족분 재요청(`_fill_shortfall`)은 순차로 둔다.** **이미 채택된 항목 목록을 프롬프트에
  실어** 다시 부르는 호출이라 앞 호출의 결과가 뒤 호출의 입력이다 — 겹쳐 돌리면 같은
  질문을 다시 받는다. 호출도 총 2회 상한이라 얻을 것이 없다.
- **그물**: `test_faq_chunking` 의 `ParallelChunkCallTest`. 동시 호출 여부는 **타이밍이
  아니라 `peak`(동시에 떠 있던 수)** 로 본다 — 순차 코드에서는 어떤 타이밍에도 1 을 넘을
  수 없어 흔들리지 않는다.

### 미준수는 **알리고, 다시 할지는 사용자가 정한다** — `notice`

판정을 만들어 놓고 내보내지 않으면 사용자는 어떤 용어가 빠졌는지 알 수 없다
(`term_map_unapplied`·부분 실패·숫자 드리프트 전부). 세 기능이 `notice` 채널을 쓴다.

- **자동 재번역을 하지 않는 것이 결정이다** (요구 확정). 미준수 유닛만 골라 한 번 더
  부를 수도 있지만, 사용자가 고르지 않은 LLM 호출을 쓰면서 **결과가 나아진다는 보장이
  없다.** 사실을 말하고 다시 번역할지는 사용자가 정한다.
- **안내문은 건수만 말한다.** 어느 용어·어느 문장인지는 문서 내용이고(3.8절), **자리는
  이미 화면에 있다** — 원문 사본은 매칭된 용어를 칠하므로 오른쪽 짝이 비어 있는 형광이
  곧 "사전 용어인데 번역이 그 말을 안 썼다" 다.
- **서빙은 숫자만 낸다**: 번역 `glossary.term_map_unapplied`·`stats.failed_unit_count`,
  글다듬이 `failed_chunk_count`, FAQ `chunks_planned`/`chunks_used`·`source_truncated`.
  서빙에서 이 값들을 지우면 **안내문이 조용히 사라진다.**
- **`notice` 는 있을 때만 실린다** (`error` 와 같은 규약). 늘 있는 빈 배열은 읽는 쪽이
  "확인했다" 고 믿게 만든다.
- **문구는 스텝 파일 안 고정 한국어 문장**이다 — 서빙의 안내문을 옮겨 오지 않는다
  (§3.8). 옮기면 같은 문장이 두 곳에 살고 한쪽만 고쳐진다.
- 세 기능의 내용: 번역(용어 미준수·부분 실패·숫자) · 글다듬이(조각 실패·구조 훼손·숫자) ·
  FAQ(조각 실패·문서 절단·근거 확보 부족).

### 번역 유닛에 **절 제목을 문맥으로** 단다

구조 보존을 스켈레톤 분해로 하는 대가다 — 표 파이프·제목 마커는 코드가 쥐고 **LLM 에는
셀·문장 텍스트만** 들어간다. 그래서 표 셀 하나짜리 유닛(`대상`·`금액`·`해당 없음`)은
그것이 무엇에 관한 값인지 알 방법이 없고, 주어가 생략된 한국어 문장은 더 그렇다.
`TranslationUnit.context_scope` 를 마크다운 경로에서도 채우고 프롬프트에 싣는다.

- **번역 대상이 아니다.** 출력 스키마는 `{id, t}` 그대로이고 시스템 프롬프트가
  "`c` 는 배경이며 번역하지도 출력하지도 말라" 를 못박는다. 이 지시가 없으면 모델이
  문맥을 번역문에 섞고, **구조는 코드가 지키므로 그 결과가 정상 응답으로 내려간다.**
- **문맥이 없으면 키 자체를 넣지 않는다** — 빈 문자열을 실으면 모델이 그것도 번역해야
  할 무엇으로 읽을 여지가 생기고 토큰만 는다.
- **제목 자신에게는 달지 않는다** (자기가 그 문맥이다).
- **단건 폴백에도 같이 싣는다.** 폴백에만 빠뜨리면 배치가 실패한 유닛들만 문맥 없이
  번역되고, 그 차이는 **배치가 실패했을 때만** 드러나 알아채기 어렵다.
- **중복 제거 규약은 그대로다** — 같은 원문은 한 번만 부르므로 여러 절에 나오는 같은
  문구는 **처음 만난 절의 제목**을 문맥으로 쓴다. 절마다 따로 부르면 호출 수가 늘고
  같은 문구가 자리마다 다르게 번역되는 흔들림이 돌아온다.

### 스트리밍 — 서빙은 **진짜로 흘리고**, 하이라이트는 끝나고 **갈아 끼운다**

결과를 다 만든 뒤 스텝이 조각내 흘리는 연출은 화면에서 **"한방에" 와 구분되지 않는다** —
`emit` 뒤의 `await asyncio.sleep(0)` 은 지연이 아니라 스케줄러 양보라(가이드 5.2 의 write
buffer flush) 조각 전부가 수 ms 안에 나가고 브라우저는 한 프레임에 그린다. 그 전 수십 초
동안 화면은 비어 있다. 그래서 서빙이 LLM 출력을 SSE 로 흘리고 스텝이 그것을 받아 흘린다.

| 단위 | 서빙 SSE 경로 | 흘리는 것 |
|---|---|---|
| 글다듬이 | `POST /polish/stream` | 다듬은 마크다운 본문 그대로 |
| 번역 | `POST /translate/stream` → `POST /translate/finalize` | 번역 마크다운 본문(정본) |
| FAQ | `POST /generate/stream` | 근거·중복 검증을 지난 항목 |
| 006 | `POST /chat/prefill/stream` | 자동 채움 진행 상황(`✔ 항목: 값`) |

**공통 규약:**

- **흘리는 것은 정본이다.** 사본(`<mark>`)을 흘리면 ① 하이라이트가 스트리밍 중에 먼저
  나타나 요구가 말한 순서와 어긋나고 ② 태그가 조각 경계에서 갈려 `<ma` 같은 부스러기가
  남는다. **원시 마크다운·태그가 스트리밍 중에 보이는 것은 허용된 동작이다**(요구 확정).
  최종 `result` 가 하이라이트 사본으로 갈아 끼운다.
- **비스트리밍 경로는 폴백으로 남는다** (`POST /polish`·`/translate/markdown`·`/generate`).
  폐쇄망에서 게이트웨이가 `stream: True` 를 받는지 **실물로 확인되지 않았고**, 안 받는
  배포에서 기능이 통째로 죽으면 안 된다. 게이트웨이가 스트리밍을 거절하면
  (`STREAM_UNSUPPORTED` — 400·415·422·501) 서빙이 그 자리에서 비스트리밍으로 되돌아가 결과를
  한 덩어리로 흘린다 — **스텝은 SSE 하나만 알면 된다.** 스텝에도 한 겹 폴백이 있다: SSE 가
  아닌 응답이 오면 비스트리밍 경로로 간다(서빙 판본이 어긋난 배포용).
- **순서 버퍼** — 조각은 세마포어 상한 안에서 함께 도므로 조각 3이 조각 1보다 먼저 끝난다.
  끝난 순서대로 흘리면 문단이 뒤섞이는데 **`result` 가 갈아 끼우므로 최종 결과는 멀쩡하다**
  — 스트리밍 중에만 틀리고 로그에는 아무것도 안 남는다. 그래서 병렬은 유지하고 흘리는
  순서만 묶는다: **머리 조각**은 델타가 오는 대로 라이브로, **뒤 조각**은 자기 버퍼에 모아
  두고 차례가 오면 **한 번에** 붙인다(요구 확정).
- **흘린 것 == 정본이 계약이다.** `polish_stream_async`·`translate_stream_async` 는 델타를
  이어 붙인 것을 그대로 `content` 로 내고 **`strip()` 을 걸지 않는다**(조각 사이 공백은
  `rebuild` 가 `suffix` 로 되꽂는다). 어긋나면 화면이 순간 다른 글을 보여주고 오류로는 안
  드러난다.
- **첫 델타 뒤에는 재시도하지 않는다.** 다시 부르면 그 출력이 화면에 **이어붙어** 같은
  문장이 두 번 나온다. 흘린 뒤의 실패는 그 조각의 실패로 확정하고, 화면과 정본이 어긋난
  사실을 `stream_diverged` → 안내문으로 낸다.
- **전량 실패에서는 한 글자도 흘리지 않는다.** 실패 조각의 원문은 최종 판정 뒤에만
  흘린다 — 실패하는 즉시 흘리면 전량 실패에서 원문이 통째로 화면에 나간 뒤 오류로
  갈아엎어 **답이 나왔다가 사라진다.** 한 글자도 안 흘린 실패 조각을 만나면 그 자리에서
  멈추고, `gather` 가 끝나 `ok` 면 풀어 흘린다.
- **폴백 사실을 잃지 않는다** — 폴백 결과로 `outcome` 을 덮으면 그 객체의
  `stream_unsupported` 는 거짓이라 "되돌아갔다" 는 사실(`stream_fallback`)이 사라진다.
- **`X-Accel-Buffering: no` 를 싣는다.** 중간 프록시가 SSE 를 모아 보내면 "한방에" 로만
  보이고 오류가 없다.

**번역 스트리밍은 구조 보장과 맞바꾸는 것이다.** 배치 경로는 유닛이 JSON(`{id, t}`)으로
오가므로 흘릴 것이 없고 배치 순서도 문서 순서가 아니다. 흘리려면 **LLM 이 마크다운 본문을
그대로 내야** 하고, 그러면 스켈레톤 분해가 성립하지 않는다 — **구조를 지키는 주체가 코드에서
프롬프트로 넘어간다.**

- **감수한 것을 감추지 않는다.** 조각을 코드펜스·표 가운데에서 끊지 않고, 끝나면 **지문을
  대조해 알린다**(`stream_pipeline.structure_diff` — 표 행·셀·펜스·제목 개수). 글다듬이
  `markdown_guard` 와 같은 취지다. **표가 많은 문서는 `POST /translate/markdown` 이 맞다.**
- **두 번 부른다** — 흘리고(`/translate/stream`), 끝나면 `/translate/finalize` 가 하이라이트
  사본(`markdown_highlighted`·`source_markdown_highlighted`, **`/translate/markdown` 과 같은
  키 이름**)·구조 대조·링크를 준다. 준수 판정은 번역문 전체를 봐야 하고 좌표는 최종 문자열
  기준이라 흐르는 도중에는 없다. 좌표만 주면 태그를 끼우는 쪽이 스텝이 되고 겹침 병합·역순
  삽입 규칙이 워크플로우에 한 벌 더 생기므로 조립은 서빙의 `highlight_units` 가 한다.
- **finalize 는 무상태다.** 프론트(스텝)가 방금 받은 두 텍스트를 되돌려 보내면 서빙이
  대조를 다시 한다 — 용어 매칭은 결정적이라 같은 답이 나오고, 세션을 붙이면 이 무상태
  단위에 상태가 생긴다. LLM 을 부르지 않으므로 재시도해도 안전하다. **`done` 이 준
  `translated_text` 를 그대로 보내야 한다** — 델타를 이어 붙인 값과 한 글자라도 다르면
  좌표가 밀리고, 그 어긋남은 **하이라이트가 한 칸 밀린 화면**으로만 드러난다.
- **finalize 실패는 fail-open** 이다 — 번역문은 이미 흘렀으므로 되돌릴 수 없고,
  하이라이트가 없다고 결과를 버리면 **사용자가 방금 본 글이 오류로 바뀐다.**
- **번역이 배치 경로와 갈리는 자리 둘.** ① **`max_tokens` 를 싣는다** — 조각 응답이
  잘리면 그 구간이 조용히 원문으로 남는다. ② **세마포어를 `llm.py` 함수 안에서 잡지
  않는다.** 배치 `llm_call_async` 는 안에서 잡지만(단건 폴백이 그 제한을 우회하지 못하게)
  스트리밍은 조각 순서를 `stream_pipeline` 이 쥐므로, 여기서 잠그면 "머리 조각은 라이브로,
  뒤 조각은 버퍼로" 를 `llm.py` 가 정하게 된다.
- **```json 펜스 제거는 하지 않는다.** 배치는 출력이 JSON 이라 펜스가 붙으면 파싱이
  죽지만, 스트리밍 출력은 마크다운 본문이다 — 걷어내면 원문에 있던 코드펜스가 사라진다.
- `translate_stream_async`·`_delta_from_frame`·`STREAM_UNSUPPORTED` 는 글다듬이와 **같은
  코드**다. 갈리면 같은 게이트웨이 거절이 두 단위에서 다르게 끝난다.

**FAQ 는 토큰을 그대로 흘리지 않는다.** 항목이 스키마·근거·중복을 지나야 화면에 나갈
자격이 생기므로, 프롬프트(`md_system.txt`)가 `근거 → 질문 → 답변` 순으로 쓰게 해서 검증을
**접두어 연산**으로 만든다 — 근거가 닫히면 대조하고(실패면 한 글자도 안 나간다), 질문이
닫히면 중복을 보고, **답변 첫 델타에서 항목을 연다.** 질문이 닫힐 때 열지 않는 이유는 답변이
끝내 안 오는 경우(형식 위반)에 **답 없는 질문이 화면에 남기** 때문이다.

- **비스트리밍도 같은 마크다운 형식이다**(`markdown_items.py`). 형식이 둘이면 증분 파서가
  스트리밍 요청에서만 돌아 **거의 검증되지 않는 갈래**가 된다.
- **payload 조립은 한 함수다**(`_store_and_payload`). 스트리밍·비스트리밍이 각자
  조립하면 `markdown`·`download_url`·세션 저장 중 하나가 한쪽에만 붙고, 그 어긋남은
  **다운로드 버튼이 한 경로에서만 켜지는** 형태로만 드러난다.
- **화면 조각은 서빙이 프레임에 실어 준다**(`_display_text`). 스텝이 제목 줄을 조립하면 FAQ
  화면 형식이 워크플로우에도 한 벌 생긴다. 서빙 안 두 곳(`_display_text` ·
  `formatting._render`)이 갈리지 않는 근거는 **등식**이다 — 흘린 조각을 이어 붙이면 최종
  마크다운과 같아야 한다.
- 조각이 겹쳐 도는 동안 화면에는 한 번에 한 항목만 연다(`_StreamCtx.stream_frame`) —
  근거는 `final/CLAUDE.md` "FAQ 스트리밍" 절.

**스텝 쪽 SSE 리더:**

- **`_stream_serving(env_name, path, payload, *, read_timeout)` 하나다** — `_post_serving`
  과 시그니처를 맞췄고 **스트리밍 스텝 넷이 같은 이름·같은 코드**로 든다.
  `check_deploy_contract` 의 "워크플로우 스텝 사본 일치" 가 **같은 이름의 함수는 같은
  본문**이라야 통과시키므로, 이름을 단위마다 다르게 두면 그 대조를 빠져나간다.
- **프레임 종류를 리더가 열거하지 않는다.** `done`·`error` 가 아니면서 `text` 를 든
  프레임은 무엇이든 흘린다 — FAQ 는 `item_open`·`item_close` 도 화면 조각을 들고 온다.
  종류를 리더에 적으면 단위가 프레임을 하나 더할 때 스텝을 모두 고쳐야 하고, 안 고치면
  그 조각이 조용히 화면에서 빠진다.
- **번역 스텝은 stream + finalize 를 비스트리밍 응답 모양으로 정규화한다**
  (`_finalize_stream`). 뒤 코드가 두 모양을 각각 분기하면 조립이 두 벌이 되고 한쪽만 고치는
  실수가 화면에서만 드러난다.
- **흘리는 시점은 "되돌릴 수 없게 된 뒤" 다.** 스트리밍 경로에서는 서빙이 전량 실패에
  한 글자도 흘리지 않는다는 보장이 그 근거이고, 비스트리밍 폴백에서는 **전량 폴백 판정이
  끝난 뒤에** 흘린다 — 그 앞에서 흘리면 원문을 번역문인 양 뿌린 뒤 오류로 갈아엎게 된다.
  **오류 경로에서는 토큰이 한 개도 나가지 않는다.**
- **폴백 연출의 조각 크기는 글 길이에 따라 늘린다.** 32자 고정이면 20만 자 문서가 emit
  6,250회다 — 소켓 메시지 수가 글 길이에 비례하면 긴 문서에서 그 자체가 부하다. 총 emit
  수에 상한(`_STREAM_MAX_EMITS` 400)을 두고 조각을 키운다(사본 4벌, 12,800자 미만에서는 32자).

**그물**: `test_polish_chunking`(순서 버퍼·실패 조각 보류·전송), `check_unit_endpoints`,
`check_workflow_run`. 뒤엣것은 **HTTP 경계에 대역을 꽂는다** — `_stub_gateway` 는
`_post_serving` 만 바꾸므로 그대로 두면 `_stream_serving` 이 실패해 **폴백으로 지나가고
스트리밍 경로를 한 줄도 태우지 않는다.** 흘린 토큰도 버리지 않고(`_drain_with_tokens`)
"무엇을 흘렸나" 를 본다 — `result` 만 보면 실시간 화면의 결함을 못 잡는다. 판정 순서도
의미가 있다: 무손실 판정을 앞에 두면 사본을 흘렸을 때 그쪽이 먼저 걸려 "사본을 흘렸다"
판정이 영영 FAIL 할 수 없으므로 사본 판정이 앞이다. `_NO_STREAM_ON_ERROR` 는 오류 경로에서
흘리지 않아야 하는 스텝 목록이다.

**미검증**: 게이트웨이가 `stream: True` + SSE 를 내주는지, 중간 프록시가 SSE 를 모아 보내지
않는지.

### 하이라이트는 **원문·결과 양쪽**, 내려받기는 **링크**다

화면이 원문과 결과를 **좌우로 놓고 비교**하므로 셋이 함께 움직인다.

#### 번역 하이라이트 — 계산한 좌표를 양쪽 다 쓴다

`hits[]` 는 좌표를 양쪽 다 들고 있다(`spans` 원문 / `target_spans` 번역문). 버리던 값을
내보내는 것이지 새로 계산할 것이 아니다.

- **조립기는 하나다.** `highlight_units(span_key=..., applied_only=...)` 를 두 번 부르고
  재조립도 **같은 `rebuild_markdown`** 을 탄다. 전용 경로를 두면 겹침 병합·보호 구간 규칙이
  두 벌이 되고, 한쪽만 고치는 실수는 **표가 깨지는 형태로만** 드러난다.
- **양쪽이 같은 기준이다** — **실제로 참고한 것만**(`applied_only=True`), 그리고 **사전에
  걸린 낱말만**. 요구사항 §2 가 요구하는 것이 "어떤 단어가 용어사전의 어떤 단어를
  참고하였는지" 라 참고하지 않은 자리는 칠할 관계가 없다. 원문에 나오기만 하면 칠하면
  미준수가 화면에 드러나지만 **형광이 두 가지를 뜻하게 된다** — 미준수는
  `term_map_unapplied`·준수율이 맡는 검수용 값이고, `term_map` 이 미적용을 담지 않는
  것과 같은 기준이다.
- **사본 이름에 `_highlighted` 를 붙이지 않는다**(payload 기준). 정본이 payload 에 없으므로
  `original_text`·`translated_text` 가 곧 사본이다.

#### 내려받기 — 미리 만든 파일 + 링크 (GenOS MinIO)

결과를 만들 때 서빙이 md 를 굳혀 CDN 에 올리고 `download_url` 만 싣는다. **정본이 payload
에서 빠진다** — 화면이 파일 본문을 들고 있을 이유가 없다.

- **`file_store.py` 사본 4벌** (`txt_output.py` 와 같은 규약, 006 포함). 운영 MCP 예제를
  그대로 옮기면 안 되는 것 셋: 동기 `urllib`(async 라우트의 이벤트 루프를 멈춘다) · 예외
  원문 반환(내부 URL 이 실린다, §3.8) · 임시 파일(`delete=False` 라 예외 경로에서 남는다).
- **fail-open.** 업로드 실패는 다듬기·번역이 실패한 것과 다른 사건이라 `download_url`
  을 비우고 결과는 그대로 낸다. 예외를 올리면 잘 만들어진 결과가 통째로 사라진다.
- **글다듬이·번역은 무상태다.** 파일을 CDN 이 들고 있어서 Redis 를 붙이지 않는다.
- **폐쇄망에서 되는지는 미검증**이라 `POST /download`(018 셋)·`POST /generate`(006)를
  폴백으로 남긴다. 업로드 URL·멀티파트 필드(`hostname`+`file`)·응답 경로
  (`data.presigned_url`)는 GenOS 참조 샘플(`archive/not/minio.py`)과 대조해 맞췄다.
  > **그 샘플을 등록하지 말 것** — `mcp` 전역을 shim 없이 쓰고, import 하는 순간
  > `ensure_packages()` 가 `pip install python-docx` 를 실행한다(가이드 p.19 금지사항).

#### payload 는 **F12 에 나와야 할 값만**

**payload 는 사용자가 눈으로 보는 값만 담는다.** 내부 판정·검증·진단은 **로그가**
갖는다 — 프론트에 실어 보내면 화면이 그 값을 어떻게 쓸지 각자 정하게 되고, 쓰지 않는
값은 아무도 안 읽는 채로 계약에 남아 나중에 바꿀 때 발이 묶인다. 정본은
`final/docs/FRONT.md` 요약 절이다(`pythonstep_result` data).

| 기능 | payload (정상) |
|---|---|
| 글다듬이 | `original_text` · `polished_text` · `download_url` |
| 번역 | `original_text` · `translated_text` · `download_url` |
| FAQ | `faq_items` · `download_url` |
| 006 | `text`(답변 + **미리보기**) · `download_url` (+ `session_id`·`template_id`) |

**`error` 는 오류일 때만** 실린다 — 정상 응답에 `error: null` 을 넣지 않는다(있으나
없으나 같은 뜻이라 읽는 쪽이 분기를 두 벌 갖게 된다).

빠진 것은 넷으로 갈린다 — **파일이 된 것**(정본), **안내문(`notice`)으로 가는 것**(구조·
사실·숫자 경고, 톤 안내, FAQ 기각·다운로드 불가 안내), **로그가 갖는 것**(기각 건수·준수율·
폴백률·원본 경로), **필요 없는 것**(`changes`).

- **`{**data}` 를 쓰지 않는다.** 마지막 스텝은 payload 뼈대를 새로 만든다 — 그대로
  펼치면 앞 스텝이 넣은 값과 캔버스 입력(`question`·`overrideConfig`·`field_names`·
  `polish_source_text` …)이 **전부 프론트로 간다**(사용자 질문 `text` 가 그렇게 샌다).
  남기는 것은 `genos_state` 하나(플랫폼 추적)이고 006 만 다운로드 폴백이 쓰는
  `session_id`·`template_id` 를 더 남긴다. **허용 키 밖이 실리면 점검이 FAIL** 한다.
- **018 은 `text` 를 싣지 않는다.** 전용 UI 가 결과를 한 번에 그리므로 채팅용 조립
  문자열이 필요 없다.
- **006 은 채팅이 곧 화면이다.** 전용 UI 가 없어 `text` 가 필수이고 토큰 스트리밍도 한다.
  턴 간 상태는 payload 가 아니라 **Redis** 에 있다(`session_store.py`) — 가이드 D.1 의
  "payload 로 흐른다" 는 **같은 실행 안의 다음 스텝**을 말한다. 그래서 같은 기준으로
  줄이고, 안내문이 이미 말하는 값(`이전 → 새 값`·기각 건수·본문 추가 번호·남은 항목)은
  문장으로만 낸다. **기각 항목 이름도 안내문에 넣는다** — 배열로 내지 않으므로 어느 항목이
  반려됐는지가 문장에 없으면 어디에도 남지 않는다.
  - `check_chat_turn` 은 값 누적·블록 순서를 payload 가 아니라 **세션을 직접 읽어** 본다 —
    보려는 것은 화면 표시가 아니라 **상태 전이**다. 스텝 사이 전달값(`block_styles`)은
    **중간 `data`** 에서 본다.
- **그물을 로그로 옮긴 자리가 있다.** FAQ 기각 건수는 "응답에 없는 키를 읽어 영원히
  0" 이라는 결함을 잡는 판정인데 payload 에 없다 — `check_workflow_run` 이 스텝 로그를
  붙잡아 대조한다.
- **번역 원문 사본은 엔드포인트 점검으로 못 잡는다** — 게이트웨이가 없는 점검 환경에서는
  전량 폴백돼 사본과 정본이 같아지므로 되돌려도 통과한다. 그래서 유닛 테스트가 본다.

### 프론트 계약은 네 기능이 같은 모양이다 — 006 도 링크다

**렌더링되지 않는 값은 싣지 않는다**는 기준을 006 에도 그대로 건다. 어기면 오류가 아니라
"화면에 아무것도 안 나타나는" 형태가 된다.

| 006 의 결정 | 왜 |
|---|---|
| 미리보기는 **`text` 안**에 | 별도 필드(`document_markdown`)면 **그릴 창이 없다.** 006 은 전용 UI 가 없고 채팅이 곧 화면이다 |
| `ready_for_download` 를 두지 않는다 | `download_url` 유무가 같은 것을 말한다. 두 값을 두면 어긋날 자리가 생기고, 그때 화면은 **버튼을 켜 놓고 받을 수 없는** 상태가 된다 |
| `error: null` 을 넣지 않는다 | 나머지 셋과 같은 규약 |
| **`download_url`** | 프론트가 네 기능을 같은 모양으로 받는다 |

- **다 채웠을 때만 굳힌다.** 부분 초안까지 매 턴 만들면 **대화 턴마다 zip+XML 조립과
  업로드가 붙는데 그 파일은 아무도 받지 않는다.** 그 전에는 `download_url` 이 `null` 이다.
- **`POST /generate` 는 폴백으로 남는다.** 업로드 실패는 대화 실패와 다른 사건이라 링크만
  비운다(018 셋의 fail-open 과 같다).
- `check_api_contract` 가 006 `file_store.py` 와 018 사본이 **코드가 같은지**(머리말 제외
  AST) 본다 — 갈리면 같은 업로드 실패가 단위마다 다르게 끝난다.
- `check_chat_turn` 의 미리보기 판정은 **미리보기 구간만** 본다 — `text` 전체에서 보면
  안내문의 `이전 → 새 값` 에 든 옛 값이 "옛 값이 남았다" 로 잘못 걸린다.

### 프롬프트를 **라이브러리에서 받는다** — 네 단위 전부

자주 바뀌는 프롬프트 문장은 프롬프트 라이브러리에서 받는다. 가이드 §10.5 가 "코드 PR 로
프롬프트 변경" 을 금지사항으로 든 자리다. 고정 골격(시스템 프롬프트)은 파일로 둬도 된다.

- **덮어쓰기지 이사가 아니다.** 프롬프트 파일(`final/<기능>/prompt/<배포단위이름>/*.txt`)은
  기본값이자 **폴백**으로 남고, ID 를 준 이름만 라이브러리가 이긴다. 파일을 지우고
  라이브러리만 두면 admin-api 장애가 곧 기능 정지가 되고, 이관(손으로 옮겨 적는다)에서
  프롬프트가 통째로 빠진다.
- **이름 → ID 매핑 하나로 배선한다** (`<단위>_PROMPT_IDS=extract_user=41,...`, JSON 도
  받는다). 이름은 **파일 이름에서 확장자를 뗀 것**이다 — 별도 이름표를 두면 "파일 이름
  ↔ 라이브러리 이름" 대조표가 하나 더 생기고, 어긋나면 **덮어쓰기가 조용히 일어나지
  않는다.** ID 는 코드에 적지 않는다(§10.5). 로더는 `.j2` 확장자로 적힌 이름도 같은
  프롬프트로 받아 준다.
- **세 갈래가 전부 파일로 떨어진다** — 미설정 · 조회 실패 · **본문 렌더 실패**(관리자가
  변수 이름을 틀리면 `StrictUndefined` 가 그 자리에서 죽는다). 여기서 요청을 세우면
  문구 오타 하나가 기능을 통째로 막는다. **파일도 없을 때만 요청을 세운다** — 지시문
  없는 프롬프트의 결과는 정상 응답처럼 내려간다.
- **조용히 옛 문구로 돌지 않게** `GET /prompts` 가 이름마다 `source`/`reason` 을 낸다.
  이게 없으면 "ID 를 안 넣었다" 와 "넣었는데 못 읽었다" 가 화면에서 **똑같이 옛 문구**로
  보인다. **본문은 싣지 않는다** — 담으면 그 경로가 지시문 유출 경로가 된다(3.8절).
- **사본이 4벌**(단위 간 import 금지)이고 **본문까지 같아야 한다.** 갈리면 같은 관리자
  실수가 단위마다 다르게 끝난다 — 한쪽은 파일로 폴백하고 한쪽은 요청이 죽는 식이다.
  `check_deploy_contract.check_prompt_library_copies()` 가 AST 로 대조한다(독스트링 제외).
- **지시문 언어는 전부 한국어다.** 시스템 프롬프트도 한국어로 쓴다 — 라이브러리에 올릴
  때도 같다(등록 절차: `final/docs/SERVING_REGISTRY.md` §2-3).
- **그물**: `Test/SFR-006/tests/test_prompt_library.py`(덮어쓰기·세 갈래 폴백·캐시·미설정과
  조회 실패 구분·본문 미노출), `check_api_contract`·`check_unit_endpoints`·
  `check_deploy_contract`.

### 톤·문서유형 프롬프트도 **이름=ID 로** 받는다

코드서빙 안에서 **JSON 을 해석하지 않는다**가 요구다. 그래서 톤·문서유형 지시문도
프롬프트 한 건씩, 본문은 **지시문 문장 그대로**다.

| | 지금 |
|---|---|
| 등록 | 톤·문서유형마다 프롬프트 한 건 |
| 배선 | `POLISH_PROMPT_IDS` 에 `system_<tone>=51,doc_type_<code>=62` |
| 본문 | 지시문 문장 그대로 |
| 파싱 | 없다 |

- **이름 규약은 `system_<tone>`·`doc_type_<code>` 다** (`config.TONE_PROMPT_NAME_FORMAT`·
  `DOC_TYPE_PROMPT_NAME_FORMAT`). 같은 일을 하는 자리를 둘 만들지 않으려고 톤 시스템
  프롬프트 이름 규약에 문서유형을 같은 모양으로 맞췄다.
- **환경변수를 새로 만들지 않는다.** `prompt_library.prompt_ids()` 의 이름은 임의 문자열이라
  그 모듈을 고치지 않고 얹힌다 — 그 파일은 **사본 4벌이고 본문까지 같아야** 한다.
  `GET /prompts` 가 톤 프롬프트의 출처도 답하고 `POST /prompts/reload` 하나가 함께 비운다.
  **캐시가 두 벌이면 한쪽만 부른 뒤 "톤만 옛 문구" 가 되고 오류로 드러나지 않는다.**
- **MCP `genon_lang_policy` 는 admin-api 를 부르지 않는다.** 그 파일이 하는 일은 표로 하는
  **강제 톤 판정** 하나이고, 프롬프트를 받는 것은 글다듬이다. 출처가 하나라 언제나 같은
  값이 될 `policy_source`/`policy_reason` 같은 필드는 두지 않는다 — 읽는 쪽이 "확인했다"
  고 믿게 만든다.
- **지시문을 덮어도 라벨·강제 톤은 표에서 물려받는다.** 프롬프트 본문은 문장 하나라 그런
  값을 담을 수 없다. 안 물려받으면 `debt_reason` 의 문구를 고친 순간 사실·객관 고정이
  풀리고, 그 실패는 오류가 아니라 **결과물의 문체로만** 드러난다(`tone_overridden` 이
  막으려는 바로 그것이다).
- **폴백이 요점이다.** 톤 넷 중 하나만 등록해도 나머지는 `system.txt` + 내장 지시문으로
  돈다 — 톤별 파일이 없다고 요청을 세우면 **톤 하나를 안 만들었다는 이유로 글다듬이가
  통째로 죽는다.**
- **ID 매칭의 대가** (요구 확정): 관리자가 **톤·문서유형을 새로 추가**할 수 없고(목록·
  라벨·강제 톤은 표에 있다), **내장 톤을 감출** 수 없다. 늘리는 것은 개발자 일이다 —
  `tone_presets.py` 에 준비된 `custom_doc_type_N` 자리를 풀고 MCP `LPDOC_TYPE_POLICIES`·
  `config.DOC_TYPE_PROMPT_IDS` 를 함께 고친다(톤은 eval `TONE_RULES` 도).

### 톤 4종·문서유형 5종

| | 값 |
|---|---|
| 톤 | **격식·정중**(`polite`) · **친절·안내**(`friendly`) · **명확·간결**(`clear`) · **사실·객관**(`objective`) |
| 자유 선택군 | 메일 · 게시글 · 고객발송문구 |
| 톤 고정군 | 채무 사유 · 심사역 의견 — **둘 다 사실·객관 고정** |

- **개조식 톤이 없다.** 넷은 전부 존댓말이고 "명확·간결" 은 **문장을 줄이는** 톤이지
  종결어미를 바꾸는 톤이 아니다. 그래서 eval `TONE_RULES` 의 `expected_endings` 가 셋에서
  겹치고, **톤을 가르는 것은 `forbidden`** 이다 — 종결어미만 보면 네 톤이 전부 통과해 그
  지표가 아무것도 거르지 못한다.
- **옛 코드를 별칭으로 받는다** (`LEGACY_TONE_ALIASES` = `{"report": "clear"}`). 없으면
  캔버스에 남은 `report` 가 "모르는 톤" 이 되어 **조용히 기본 톤(격식·정중)으로** 떨어진다 —
  `fell_back`·`tone_overridden` 이 막으려는 바로 그 실패다. 사본이 **2벌**(글다듬이 ·
  MCP)이라 한쪽만 고치면 같은 옛 값이 경로에 따라 다른 톤이 된다. 별칭이 가리키는 톤이
  실재하는지, **판정을 실제로 지나는지**까지 `check_tone_policy` 가 본다(표만 맞고
  `resolve_*` 가 안 쓰면 아무 일도 일어나지 않는다). **같은 이름의 톤이 표에 있으면 그쪽이
  이긴다** — 별칭은 "지금 표에 없을 때만" 탄다.
- **없어진 문서유형(보도자료·공문·재산 의견)은 별칭을 두지 않는다.** 기본값(메일)으로
  떨어진다 — 톤과 달리 **어느 유형으로 옮길지가 자명하지 않고**, 잘못 옮기면 그 문서의
  추가 지시문이 통째로 바뀐다.
- **프롬프트에는 목록을 적지 않는다.** `system.txt` 는 `tone_label`·`tone_instruction` 을
  받아 끼우기만 한다 — 베껴 두면 톤이 바뀔 때 프롬프트만 옛 목록을 들고 있게 되고 그
  어긋남은 결과물의 문체로만 드러난다.
- **사본은 셋**(MCP `genon_lang_policy` · 글다듬이 `tone_presets` · eval `tone_metrics`) +
  별칭표 2벌. `check_tone_policy` 가 대조한다.
- **`resolve_tone` 은 두 사본이 같은 모양이다.** 도달 불가 방어 코드(존재 확인 순회 등)가
  한쪽에만 있으면 두 사본이 갈렸는지 눈으로 못 본다. 같은 모양이라 표가 깨지면 조용히 다른
  톤으로 떨어지는 대신 `check_tone_policy` 가 그 자리에서 FAIL 한다.

### 첨부 문서는 **전처리기 산출물 하나**로 받는다 — `chunk_mode=raw`

**MCP 로 문서를 파싱하지 않는다.** 첨부 문서는 어차피 전처리기를 지나 `genosUploaded` 로
오므로, 첨부용 등록을 **파싱 전용**으로 두고 그 산출물을 원문으로 쓴다.
정본은 `final/preprocessor/README.md` "질의 시 첨부는 청킹하지 않는다".

- **첨부용은 별도 파일이 아니다.** `final_preprocessor.py` 를 한 번 더 등록하고 kwargs 로
  `chunk_mode=raw` 를 준다(적재용은 기본값 `search`). 파일을 따로 두면 파싱 코어 사본이
  하나 더 늘어 `check_table_grid` 가 대조할 것이 는다. 대가는 **kwargs 를 빠뜨린 첨부
  등록이 조용히 검색용 가공을 실어 보낸다**는 것이라, 등록할 때 `chunk_mode=raw` 를
  확인한다(`final/docs/SERVING_REGISTRY.md` §2-1).
- **적재용과 첨부용은 본문에 무엇이 들어가야 하는가가 반대다.** 검색은 조문 머리말
  (`제2장 총칙 > 제5조(목적)`)·표 조각 머리말이 **임베딩되는 문자열에 있어야** 걸리므로
  적재 경로에서는 옳다. 그런데 네 기능은 그 텍스트를 **LLM 에 그대로 던진다** — 번역은
  원문에 없던 머리말을 **번역해서 결과물에 싣고**, FAQ 는 그것을 원문 문장으로 보고 근거
  대조를 하며, 006 자동 채움은 문서 내용으로 읽는다. 셋 다 오류가 아니라 **결과물의
  내용으로만** 드러난다. 실측: 기술협상서 한 벌이 적재용 18레코드 13,460자 / 첨부용
  1레코드 9,901자 — **3,559자가 검색용 장식**이다.
- **MCP 파싱 배선을 두지 않는 이유는 셋이다.** ① 실패가 조용히 전처리기 산출물로
  폴백해서 **"표가 깨진 결과" 로만** 드러난다 ② 캔버스 변수가 업로드 원본 경로를 담아
  준다는 **미확인 가정**에 얹힌다 ③ 같은 문서를 **두 번 파싱**한다.
- **스텝에 `DOC_INVALID`("읽지 못함") 오류가 없다.** 파싱은 전처리기가 하고 그 실패는
  적재 층에서 예외로 드러나므로, 스텝에는 "첨부 없음" 과 "읽지 못함" 을 가를 근거가
  없다. **낼 수 없는 오류를 표에 남기지 않는다.**
- **계약은 무손실이다** — `"\n\n".join(레코드 text) == parse(bytes).to_markdown()`.
  번역이 문서 전체를 쥐어야 스켈레톤 분해·되조립이 성립한다. 그래서 블록을 쪼개지 않고
  (표 하나가 상한을 넘어도 통째로 둔다) 조각은 **플랫폼 레코드 크기 상한**(20만 자)에서만
  자른다(`split_blocks_raw`).
- **미검증**: 첨부용 등록의 산출물이 실제로 `genosUploaded` 로 실려 오는지, 그 형태가
  `<doc …>본문</doc>` 인지. 스텝은 그 형태를 전제한다(`_extract_uploaded_markdown`) —
  아니면 원문이 비고 "첨부를 안 했다"(`NO_INPUT`)로 드러난다.
- **코드서빙의 직접 업로드 경로는 따로 있다** (`POST /translate/hwpx`·FAQ
  `/generate/upload`·006 `/generate/upload`). 그쪽은 캔버스를 지나지 않으므로 전처리기
  산출물이 없고, 자기 파서(코드서빙 사본 셋)로 읽는다.

### MCP 호출에는 **Accept 헤더**가 필수다

MCP 경로는 `{GENOS_URL}/api/gateway/` + `mcp/<서빙 id>/mcp` 다(§H). 뒤의 `/mcp` 는 서빙 안
MCP 엔드포인트다.

**MCP 스트리머블 HTTP 서버는 POST 본문을 읽기 전에 Accept 를 본다.** `application/json` 과
`text/event-stream` 을 **둘 다** 열거하지 않으면 도구를 부르지도 않고 `406 Not Acceptable`
로 끊는다. httpx 기본값은 `Accept: */*` 라 그 검사를 통과하지 못한다 — **도구를 아무리
고쳐도 닿지 않는** 상태가 되고, 스텝은 그 406 을 다른 4xx 와 같은 칸(`upstream_final`)에
넣어 "요청을 처리하지 못했습니다" 로만 낸다. 사유는 응답 본문(`Client must accept both …`)
에만 있고 3.8절대로 로그에는 상태코드만 남는다(그래서 디버그 에코가 있다).

- **응답이 SSE 로 올 수 있다.** 서버가 JSON 응답 모드가 아니면 `tools/call` 결과를
  `text/event-stream` 프레임에 담아 준다. `response.json()` 만 쓰면 그때 `InvalidJson`
  으로 떨어지는데, 그 상태는 **통신도 되고 도구도 돌았는데 결과만 사라지는** 형태다.
  `_decode_body` 가 두 모양을 다 받는다.
- **진행 알림을 응답으로 읽지 않는다.** 프레임이 여럿 올 수 있고 앞쪽은 `method` 를 든
  알림이다 — 마지막 프레임을 집으면 알림을 결과로 읽는다. `result`/`error` 를 든 프레임이
  응답이다.
- **`_post_json` 은 스텝 9개에 같은 사본이다.** `check_deploy_contract` 의 "사본 일치" 가
  같은 이름의 함수가 두 가지가 되는 것을 잡는다. **`_MCP_HEADERS` 는 MCP 를 부르는 스텝
  넷**(글다듬이·번역 각 둘)에만 둔다 — 코드서빙 POST 에 Accept 를 실을 이유가 없고, 모듈
  상수는 대조 대상이 아니다.
- **상태 없는 모드를 전제한다.** `tools/call` 한 번만 보낸다. 서버가 상태 유지 모드로 떠
  있으면 `initialize` → `Mcp-Session-Id` 핸드셰이크가 필요하고 `400 Missing session ID` 로
  드러난다 — 미검증이고, 고칠 자리는 `_mcp_call` 하나다.
- **그물**: `_stub_gateway` 는 `_mcp_call` 을 통째로 대역으로 바꾸므로 그 아래(헤더·본문
  해석)를 안 본다. `check_workflow_run._check_mcp_transport` 가 **HTTP 경계에** 대역을 꽂아
  스텝이 실제로 내보내는 헤더를 받아 보고, 서버가 406 을 내는 판정까지 실물과 같게
  흉내낸다.

### 오류 코드에 `ERR-` 접두어

`ERR-02-00020003` 꼴이다. 로그·응답에서 오류 코드를 눈으로 바로 가려내기 위한 것이고
**분류 판정은 뒤 8자리**로 한다(`code.endswith("00020003")`) — 스텝의 `_upstream_kind` 도
접두어와 무관하게 돈다. 조립 자리는 전부 `f"ERR-{_AREA}-…"` 꼴이라 그렙으로 찾을 수 있다
(영역코드 상수는 로그 필드로도 쓰여 접두어를 붙이지 않는다).

### 디버그 에코 — `GENON_DEBUG=1`, **테스트 기간 한정**

3.8절 화이트리스트가 값을 버리기 때문에(허용 목록 밖은 **이름만** 남는다) 로그만으로는
무엇이 왜 실패했는지 알 수 없다 — MCP 406 처럼 사유가 응답 본문에만 있는 경우가 그렇다.
원인을 찾는 동안 표준 로그와 **별도로** 한 줄을 더 뿜는다.

- **`print` 가 아니라 `sys.stderr.write` 다.** 표준 로그와 섞이지 않게 하려는 것이다.
  MCP 는 stdout 이 전송 채널일 수 있어 한 줄만 섞여도 프로토콜이 깨진다 — 3.10절이
  print 를 금지하는 실제 이유이고 `check_deploy_contract` 가 그것을 본다. 플랫폼은
  stdout·stderr 를 둘 다 수집하므로 화면에서는 같다.
- **`GENON_DEBUG=1` 일 때만 낸다. 기본은 꺼짐** — 허용 필드 밖 값이 남으므로 원인을
  추적할 때만 켜고 운영에서 켜 두지 않는다.
- **값은 300자에서 자른다.** 문서 원문·프롬프트가 통째로 실리면 이 에코 자체가 유출
  경로가 된다(3.8절). 그래서 인자도 **키만** 싣는다(MCP 도구 호출·POST 페이로드).
- 붙은 자리: 워크플로우 스텝 9개(요청·전송 실패·**HTTP 오류 본문**), 코드서빙 4단위
  `logging_utils`(`log_warning`·`log_error` 에 물렸다), 네 `llm.py`(게이트웨이 응답 본문·
  예외 원문), MCP 파일 4개(도구 이름·인자 키·예외 원문).
- **걷어낼 때는 각 파일의 `디버그 에코` 블록과 그 호출만 지운다** — 로그 경로와 분리돼
  있으므로 지우면 표준 규약으로 정확히 돌아온다.

### LLM 호출은 **`httpx` 로 직접** 한다

게이트웨이는 **OpenAI 호환 경로**를 내주므로 SDK 가 하던 일은
`POST {base}/chat/completions` 한 번과 응답 dict 에서 본문을 꺼내는 것(`_extract_content`)
뿐이다. 네 단위 모두 `httpx` 이고 `requirements.txt` 에 `openai` 가 없다 — 사내 mirror 에
그 패키지가 없어도 빌드된다.

- **4xx 는 재시도하지 않는다.** 요청 자체가 잘못된 경우(400·401·404)를 `LLM_RETRY_COUNT`
  만큼 두드리면 같은 결과가 나오는 호출을 반복하며 대기시간만 늘고, 로그에서 일시적 장애와
  구분되지 않는다. **번역은 배치를 `LLM_CONCURRENCY`(15)로 동시에 돌리므로 그 낭비가 배치
  수만큼 곱해진다.**
- **전역 커넥션이 없다** (§D.2). 전역 클라이언트를 캐시하면 토큰이 회전돼도 옛 값을 쓰지
  않게 캐시 키를 설정값으로 묶는 방어가 따로 필요해진다. `check_unit_endpoints` 는 "전역이
  없는가" 를 본다.
- **요청 본문에 `model` 을 싣지 않는다** (요구 확정). 게이트웨이의 서빙 경로
  (`/rep/serving/{LLM_SERVING_ID}/v1/chat/completions`)가 이미 모델을 결정하므로
  `LLM_SERVING_ID` 가 모델 지정 역할을 함께 한다. 게이트웨이 필수 환경변수는 3종이다.
  게이트웨이가 OpenAI 규격대로 `model` 을 필수로 검증하는 배포를 만나면 400/422 로
  드러나고, 되살릴 자리는 네 단위의 `config.py` + `llm.py` 다.
- **`"stream": False` 를 네 단위가 명시한다**(비스트리밍 경로). 한 단위에만 없으면
  게이트웨이 기본값이 스트리밍일 때 그 단위만 응답 모양이 달라지는데, 오류로는 드러나지
  않는다. `check_unit_endpoints._check_llm_request_body` 가 **네 사본을 한 판정으로** AST
  대조한다.
- **`CONFIG_MISSING` 은 각 `llm.py` 의 상수다.** 호출부가 이 값으로 분기하므로 리터럴이 두
  곳에 있으면 한쪽만 고쳐도 예외 없이 조용히 분기가 죽는다.
- **`LLM_RETRY_COUNT` 는 import 시점에 굳는다** — 호출 시점 읽기는 게이트웨이 3종뿐이다.
  **운영에서 이 값을 바꾸려면 서빙을 재기동해야 한다.** 테스트 기대값은
  `Config.LLM_RETRY_COUNT` 에서 파생시킨다.
- **그물**: `test_polish_chunking.PolishLlmTransportTest`, `test_translation_llm.py`(번역
  고유 셋 — 세마포어를 함수 안에서 잡는가·`max_tokens`·코드펜스 제거), `check_unit_endpoints`.

### FAQ 의 운영 합불 기준 — eval

근거성에는 기준을 두지 않는다(재서술이 곧 오답은 아니다). 그러면 `pii_leak_count` 만
남아 **30개를 요청해 2개가 나와도 `verdict: pass`** 가 되므로 FAQ 스위트에 결정적 기준을
더 건다. 서빙의 `FaqResult.as_payload()` 가 내는 `count`·`requested_count`·
`rejected{schema,ungrounded,duplicate}`·`coverage_capped` 는 전부 **결정적 사실**이고 재서술
논쟁과 무관하다.

- **거는 것은 둘뿐이다.** `yield_rate`(고른 개수 대비 산출)와 **스키마** 기각률.
  스키마는 **우리가 프롬프트로 못박은 계약**이라 문서 성격과 무관하다.
- **`ungrounded`·`duplicate`·커버리지는 보고만 한다.** 앞의 둘은 원천 문서의 성격에
  달렸고, 커버리지 상한은 **비용 손잡이**(`FAQ_MAX_CHUNK_CALLS`)가 정하는 값이다 —
  배포 설정을 품질 불합격으로 세면 상시 빨간불이 되고 사람이 지표를 끈다.
- **후보가 0건이면 기각률은 `None`** 이다. 0.0 을 주면 아무것도 못 만든 실행이 스키마
  기준을 **만점으로 통과**한다. **요청 개수가 없는 통계는 예외**다(`pairs.pair_texts`
  의 원문 부재 규약과 같다) — 조용히 1.0 을 주면 이 지표를 붙인 이유가 사라진다.
- **임계 둘(0.8 · 0.1)은 실측 전 잠정값**이고 `payload.thresholds` 로 덮는다.
- **`chrf_score` 는 `role: operational` 인데 `targets` 에 없다** — 값이 아무리 낮아도
  verdict 에 안 잡힌다. 참조 번역이 있는 입력이 없어 임계를 정할 근거가 없다. 정본은
  `Test/eval/README.md`.

### 생성 문서 PII 감사는 **MCP 도구**로, 사람이 직접 돌린다

`pii_leak_count` 는 eval 스위트 안에 있어 **평가를 돌릴 때만** 돈다. 요구는 야간·주간
단위로 **생성 문서를 모아 미마스킹 건수를 집계**하는 것이라 MCP 파일
`final/mcp/genon_pii_audit.py` 가 맡는다.

- **스케줄러를 넣지 않는다** (요구 확정). 주기는 운영이 정하고 우리는 **집계만** 낸다.
  기능 응답 경로(payload)에도 붙이지 않는다 — 매 응답마다 도는 판정이 아니고, 응답에
  실으면 그 값이 화면 계약이 되어 나중에 바꿀 때 발이 묶인다.
- **LLM 을 쓰지 않는다.** ① 미마스킹 개인정보를 찾겠다고 그 텍스트를 모델 호출에
  실으면 **감사 자체가 유출 경로**가 된다. ② 주 단위 추세를 보는 값인데 판정이 흔들리면
  건수가 는 건지 모델이 달라진 건지 구분할 수 없다. ③ 허용치가 0이라 오탐 비용이 크고,
  **오탐은 결국 미탐으로 간다.** GenOS 가드레일(#315)과는 경쟁이 아니라 **짝**이다 —
  마스킹은 적재 층이 하고 이 도구는 그 층이 빠졌다는 사실을 **산출물 쪽에서** 잡는다.
- **본문 키가 없는 문서를 "유출 0건" 으로 세지 않는다.** 그렇게 세면 키 이름을 한 번
  잘못 준 감사가 **전건 통과**로 나오고, 그 상태는 오류도 경고도 없이 "이번 주도
  깨끗합니다" 로만 보인다. `unreadable` 로 드러내고 `scanned` 를 `documents` 와 따로 낸다.
- **유출 목록에 상한을 두지 않는다.** 상한 뒤의 유출은 리포트에서 사라지는데, 감사에서
  그건 미탐과 같다(변경 하이라이트에 건수 상한을 두지 않는 것과 같은 근거).
- **검출한 값은 응답에 담지 않는다** (3.8절) — 유형과 자리만. `not_detected`(이름·주소·
  계좌번호)를 이유와 함께 내서 `leak_count == 0` 을 "개인정보 없음" 으로 읽지 못하게 한다.
- **판정부는 `Test/eval/eval_mcp/pii_metrics.py` 의 사본이다** (배포 단위 간 import 금지).
  갈리면 같은 문서가 감사 도구와 평가지표에서 **다른 건수**로 나오고 오류로는 드러나지
  않는다 — `check_mcp_tools` 가 두 구현에 **같은 입력을 태워** 대조하고(정적 diff 가
  아니다) **검출기 목록**도 맞춘다. 표본에 없는 유형을 한쪽에만 더하면 동작 대조만으로는
  안 잡히기 때문이다.

### 용어사전 on/off — 배포 단위로만 끈다

**배포 단위로 끄는 수단이 이미 있다** — `TRANSLATE_GLOSSARY_API_URL`·`_ID`·`_TOKEN`·
`_TARGET_KEY` **중 하나라도 비우면** `glossary_store` 가 적재를 건너뛰고(`not_configured`)
프롬프트의 용어 절·준수율 판정·`<mark>` 하이라이트가 **전부 함께** 꺼진다. 요청 단위
on/off(화면 체크박스)는 요구가 아니라고 확정됐다.

> **남는 결함 하나**: **"안 쓰기로 했다" 와 "설정을 빠뜨렸다" 가 둘 다 `not_configured`**
> 로 나간다 — 이 저장소가 `fell_back`·`tone_overridden`·`not_applicable` 로 계속 갈라 온
> 그 실패 형태다. 가르려면 `TRANSLATE_GLOSSARY_ENABLED` 를 두고 사유를 `disabled_by_config`
> 로 낸다(고칠 자리는 `config.py`·`glossary_store.py`·`main._load_glossary` 셋).
> **안 만든 것은 의도한 공백이다.**

### 안 쓰는 줄은 곧 타이핑 비용이다

폐쇄망 이관은 **화면을 보며 손으로 친다.** 그래서 죽은 코드는 "언젠가 치우면 되는 것"이
아니라 **지금 사람이 치게 되는 줄**이다. 참조 0건인 정의와 미사용 import 를 두지 않는다.

- **`requirements.txt` 에 코드가 import 하지 않는 패키지를 두지 않는다.** mirror 에 없는
  패키지 하나가 `pip install -r` 을 세우면 **코드가 쓰지도 않는 이유로** 배포가 통째로
  막힌다(`jinja2` 가 그런 예다 — 프롬프트 렌더는 jinja 를 쓰지 않는다).
- **문서도 코드와 같이 본다.** 코드가 아니라 **문서만** 틀린 서술(예: 지운 함수를 누가
  쓴다고 적은 것)은 점검으로는 영영 안 잡힌다.

### 설정 부재는 **재시도 불가**다 — 서빙과 스텝 둘 다

**배포 환경변수(`GENOS_URL`/`LLM_SERVING_ID`)를 안 넣은 상태**는 몇 번을 다시 눌러도 같은
자리에서 실패하는 배포 실수다. "잠시 후 다시 시도해 주세요" 가 나가고 캔버스가 재시도를
걸면 원인이 화면에도 로그에도 드러나지 않는다. 네 단위가 같은 얼굴로 낸다:

| 단위 | 설정 부재 응답 |
|---|---|
| 번역 | 200 + `translation_error="CONFIG_MISSING"` |
| 글다듬이 | `ERR_CONFIG_MISSING` |
| FAQ | `FAILURE_CONFIG` → `ERR_API_CONFIG_UNAVAILABLE` |
| 006 | `ERR_CHAT_CONFIG_MISSING` |

`llm.py` 가 설정 부재를 예외로 빠져나가게 두면 최종 방어선에서 `ERR_INTERNAL` 이 되고,
`is_transport_error=False` 라는 이유로 실행 실패(재시도 가능)로 분류하면 같은 증상이 난다.

**서빙에서 갈라도 스텝이 되돌리면 소용없다.** 스텝이 재시도 여부를 **상태코드로만**
정하면(`_RETRY_STATUS` 502·503·504 외 4xx·5xx 전부 `UPSTREAM_EXECUTION`, retryable=True)
서빙이 `retryable=False` 로 갈라 둔 응답이 경계에서 통째로 뒤집힌다 — 서빙 쪽
`ErrorCode.retryable` 만 보는 점검은 통과하므로 아무도 못 잡는다.

- **상태코드가 아니라 응답 본문의 `error_code` 분류로 본다** (`_upstream_kind`).
  가이드 3.9.2 의 `00020003` 은 통신 실패도 실행 실패도 아닌 나머지 전부이고, 네 서빙이
  거기에 `retryable=False` 를 붙인다. **상태코드로는 이 판정을 복원할 수 없다** —
  006 은 `ERR_API_INTERNAL`(00020002, 재시도 가능)도 500 이라 500 ≠ 최종 실패다.
- **판정 못 한 응답은 실행 실패로 둔다** (본문이 JSON 이 아니거나 dict 가 아닐 때).
  모르는 것을 재시도 불가로 올리면 일시적 장애가 최종 실패가 된다.
- **특례가 먼저다.** 006 스텝 1의 404(`TEMPLATE_MISSING`)도 00020003 이라, `upstream_final`
  을 앞에 두면 "템플릿을 찾을 수 없습니다" 안내가 통째로 사라진다.
- 스텝은 서빙의 안내문을 옮기지 않는다(§3.8) — 자기 오류표의 `UPSTREAM_FINAL`
  ("요청을 처리하지 못했습니다. 관리자에게 문의해 주세요.", retryable=False)로 낸다.

**그물**: `check_workflow_run.py` 의 `_check_upstream_final`(스텝 9개 전부: 분류 4갈래 +
오류표)과 `_check_polish_upstream_final`(HTTP 응답 → 매핑 → `result` 이벤트까지 한 번에).
뒤엣것이 따로 필요한 이유는 **분류 함수와 오류표가 둘 다 맞아도 매핑 분기를 안 걸면
앞의 둘만으로는 통과하기 때문**이다. 서빙 쪽은 `check_unit_endpoints.py`·`check_chat_turn.py`.
FAQ 판정은 **`llm.py` 부터** 태운다 — `generate_faqs` 에 대역을 꽂으면 분류 **뒤**만 보게
돼 `_record_failure` 가 `CONFIG_MISSING` 을 실행 실패로 되돌려도 통과한다. 설정 부재
시뮬레이션은 **환경변수를 비우는** 모양이다(실제 배포 상황과 같은 모양). FAQ·번역의
`Config` 는 **import 시점에 값을 굳히므로**, 그 경우 점검이 import 이전에 환경을 세워야
의미가 있다.
