## SFR-006 모듈 배치

**설계·흐름의 정본은 `final/docs/SFR-006_architecture.md` 다.** 여기는 어느 파일을
고쳐야 하는지 찾는 지도다. 계층이 셋이고, 위층은 아래층을 알지만 아래는 위를 모른다.

```
진입   chat_api.py(/chat/*, 02 워크플로우 스텝이 부른다) · main.py(03 HTTP 라우팅만)
       api_requests.py 요청→검증된 값    api_download.py 값→파일 응답    api_errors.py ApiError→HTTP
조립   chat_state.py  한 턴의 상태 전이       session_view.py  세션+색인→화면 payload
       chat_reply.py  채팅 답변 문구          document.py      ★서식→채우기→블록
       doc_prefill.py 업로드 문서→빈 항목     template_store.py 템플릿 볼륨 I/O
       polish_client.py 본문 블록→글다듬이 서빙(+ value_guard.py 숫자·날짜 대조)
도메인 hwpx_fields.py(hwpx 판정의 정본) · hwpx_style.py · hwpx_blocks.py
       hwpx_markdown.py · field_judge.py
인프라 session_store.py · template_index.py · redis_client.py · llm.py · file_store.py
```

워크플로우 스텝은 `final/workflow/sfr006_0{1,2,3}_*.py` 셋이다. 스텝은 `httpx` 로
`/chat/*` 를 부를 뿐이고 계산은 전부 이 패키지에 있다(스텝 이미지에 `lxml`·`redis` 가 없다).

**`doc_prefill.py` 는 조립 계층이다.** 업로드 문서에서 빈 항목만 채우고, 판정은 대화
경로와 **같은 `field_judge.parse_updates`** 를 태운다 — 화이트리스트를 두 벌로 만들면
대화로는 막히는 항목명이 문서 경로로 들어온다. 이 디렉토리에서 걸리는 것:

- **프롬프트가 따로다** (`document_{system,user}.txt`). `build_extract_prompts` 를 쓰지
  말 것 — 그쪽은 "이번 턴 사용자가 말한 것" 지시문이다.
- **채워진 항목은 프롬프트에 넣지 않는다.** 넣으면 모델이 그 값을 문서 표현으로 고쳐
  다시 주고, 우리는 그것을 버리므로(덮어쓰기 금지) 토큰만 든다.
- **`_load_turn` 이 세션 dict 도 돌려준다** (3-튜플). `source_doc_hashes` 는 `TurnState`
  에 없고, 저장이 덮어쓰기라 커밋이 기존 목록을 다시 실어야 한다.
- **저장은 커밋 한 곳에서만** 한다. `/chat/prefill` 은 뽑아서 돌려주기만 한다 — 한 턴에
  두 곳에서 저장하면 순서에 따라 서로를 덮는다.
- **표식은 목록이고 커밋이 더한다.** `_merged_doc_hashes` 가 순서만 정하고, 중복 제거·
  상한은 `session_store.normalize_doc_hashes` 한 곳이 쥔다. 덮어쓰면 앞서 태운 문서를 잊는다.
- **세션을 저장하는 경로가 둘이다** — 커밋(`chat_api`)과 화면 편집(`session_view`).
  **둘 다 표식을 실어야 한다.** 빠뜨린 상태는 "화면에서 값을 지우면 다음 턴에
  되살아난다" 로만 드러난다(`EditingContext` 가 표식을 들고 다니는 이유).

지켜야 할 경계:
- **`hwpx_fields.py` 가 hwpx 판정의 정본이다.** `section_order`(무엇이 본문인가)·
  `own_nodes`(문단이 직접 가진 텍스트)·`slot_occurrences`(중괄호 슬롯인가)를 다른
  모듈이 다시 구현하지 않는다. 두 벌이 되면 채우는 자리와 서식 거는 자리가 어긋난다.
- **도메인 계층은 `Config` 를 읽지 않는다.** 배포 스위치는 `document.py` 가 한 번만 읽는다.
- **조립 순서는 `document.build` 한 곳에만 있다.** 코드서빙·미리보기·점검 스크립트가
  각자 적으면 점검이 자기가 검증할 순서를 스스로 복제해 무의미해진다.
- **오류는 `ApiError` 예외 하나로 올린다.** `(값, 오류응답)` 튜플 반환을 쓰지 않는다 —
  `if error: return` 을 한 번 빠뜨리면 조용히 엉뚱한 곳에서 터진다.
- **영역코드를 섞지 않는다.** 대화가 `template_store`(03 코드)를 쓸 때
  `chat_state.load_context` 가 02 코드로 바꿔 던진다.

## SFR-006 설계 결정 (요약 — 상세는 final/docs/SFR-006_architecture.md)

- **채울 자리는 슬롯이다.** 현장 템플릿은 누름틀이 아니라 본문에 그냥 텍스트로 적혀
  있고, **채울 자리는 중괄호 안뿐이다.**

  ```
  제 목 : {'제목', 16pt, 맑은 고딕, 볼드}   →   제 목 : hwpx 만들기 문서
  작성자 : {'작성자'}                        →   작성자 : 왕주영
  ```

  - **첫 인자는 따옴표 필수**이고, 그 문자열이 곧 항목명이자 "여기에 무엇을 쓰라"는
    LLM 안내문이다. 뒤 인자(0~3개)는 크기·글꼴·굵게이며 **순서·개수가 자유롭다** —
    토큰을 생김새로 판정한다(`16pt`=크기, `볼드`=굵게, 남은 것이 글꼴). 위치를 고정하면
    가운데를 건너뛸 때 `{'제목', , 고딕}` 처럼 빈 자리를 남겨야 한다.
  - **지정하지 않은 인자는 건드리지 않는다.** `{'작성자'}` 는 그 자리 run 의
    `charPrIDRef` 를 그대로 물려받는다 — 서식을 지어내지 않는 것이 원칙이다.
  - **중괄호 밖은 무조건 원문 그대로 남는다.** 줄을 재조립하지 않으므로 `제 목  : ` 의
    줄맞춤 공백도 그대로다.
  - 한 문단에 여러 개가 올 수 있다 (`담당자 : {'소속'} {'성명'}`).
  - 한/글 자동 고침이 `'제목'` 을 `‘제목’` 으로 바꿔 저장하므로 **굽은 따옴표도 받는다.**
    한쪽만 바뀐 문서(`‘제목'`)도 열어 준다 — 관리자가 눈으로 구분할 수 없는 차이로
    항목이 통째로 사라지는 편이 훨씬 나쁘다.
  - 표(hp:tbl)는 hp:p 안에 hp:p 가 중첩되므로 **문단 소유 텍스트 노드만** 모아
    판정한다. `para.iter()` 를 그대로 쓰면 표 전체가 한 줄로 붙어 깨진다.
  - `TEMPLATE_FILL_SLOT_FIELDS=0` 으로 끌 수 있다 (`..._LABEL_FIELDS` 이름도 읽는다 —
    그 이름으로 꺼 둔 배포가 이름 차이 때문에 켜져서는 안 된다).
- **누름틀(CLICK_HERE)은 폴백으로 유지**한다. 관리자가 한/글에서 필드를 심은 템플릿을
  올려도 그대로 동작한다. 필드 식별은 `fieldBegin` 의 `name`, 안내문은 첫 `stringParam`.
  begin/end 짝은 **문서 순서 스택 매칭** (문단/필드 id 는 신뢰 불가 — 규칙 문서 §3.2).
  `{{token}}` 은 프로토타입 호환용.
- **채워짐 판정은 코드가 결정적으로** 한다: 슬롯은 **언제나 미입력**이다 — 채우고 나면
  `{…}` 자체가 사라지므로, 문서에 남아 있다는 것이 곧 아직 안 채웠다는 뜻이다.
  누름틀은 begin~end 텍스트가 비어 있지 않고 안내문과 다르면 채워진 것.
  LLM 의 역할은 사용자 발화 → `{항목명: 값}` 추출까지.
- **서식은 LLM 없이 코드가 적용한다**: `charPr` 을 복제해 `height`(1pt=100)·폰트·굵게만
  바꾸고 그 id 를 **슬롯 run** 의 `charPrIDRef` 에 건다 (`STYLE_SCOPE` 기본 `slot`).
  문단 전체에 걸면 중괄호 밖 라벨까지 같이 커지고, 한 문단에 슬롯이 둘이면 뒤엣것이
  앞엣것을 덮는다. 같은 서식은 `charPr` 을 재사용하고, `itemCnt`/`fontCnt` 는 반드시
  다시 센다 (틀리면 한/글이 문서를 못 연다).
- **따옴표 없는 `{…}` 는 채울 자리가 아니다.** 현장 템플릿에는 `담당자 : {소속} {성명}`,
  `배포일 : {YYYY.MM.DD. (요일)}` 처럼 **값 안내**가 들어 있다. 원문 그대로 두고 등록 시
  경고로만 노출한다 — 지우면 값 안내가 조용히 사라지고, 등록을 거부하면 본문에 중괄호를
  쓴 정상 문서를 막는다. 따옴표 경계가 있으므로 **슬롯에서는 "글꼴 어휘로 근거를 따지는"
  휴리스틱이 필요 없다.** 그 판정(`require_evidence`)은 경계가 없는 **누름틀 안내문
  경로에만** 있다. 다만 자리 표시어(`글씨크기`·`폰트`·`볼드여부`)는 슬롯에서도 삼킨다 —
  문법 설명을 그대로 복사해 붙인 템플릿에서 '폰트' 라는 없는 글꼴을 거는 일을 막는다.
- **lxml 프록시 id 는 붙들어야 유효하다**: `{id(elem): 위치}` 맵을 만들 때 순회 결과를
  리스트로 살려두지 않으면 프록시가 회수되며 id 가 재사용돼 엉뚱한 노드를 가리킨다
  (항목 순서가 뒤섞이는 모양으로 드러난다).
- **본문 블록 — 템플릿 항목을 다 채운 뒤 내용을 더 이어 쓰는 경로** (`hwpx_blocks.py`).
  항목은 개수가 고정이라 다 채우면 더 쓸 자리가 없다.
  - **서식 명세를 다시 해석하지 않고 템플릿 문단을 통째로 `deepcopy` 한다.** 명세를 파싱해
    문단을 조립하면 charPr 만 재현되고 **paraPr(여백·줄간격·정렬)은 재현되지 않는다** —
    이 패키지엔 paraPr 을 만드는 코드가 없다. 복제하면 둘 다 따라오고 **새 서식 정의가
    0개**라 header.xml 을 건드리지 않는다 (= 이 경로는 문서를 깨뜨릴 수 없다).
  - 복제 시 **`hp:t` 만 남기는 화이트리스트**로 secPr·ctrl·tbl·그림을 버린다. 현장 템플릿은
    **첫 문단이 secPr 과 `제 목 :` 라벨을 함께 담고 있어** 이 방어가 실제로 필요하다.
    블랙리스트로 하면 모르는 제어 요소에서 뚫린다.
  - 서식 원본(`style_ref`)은 **최상위 문단만**. 표 셀 안 슬롯은 제외한다(셀 폭 기준 서식이
    본문에 나온다). 표 안 슬롯은 **채울 항목으로는 그대로 인식**된다 — LLM 이 표도 채운다.
  - 이름을 못 찾으면 **내용을 버리지 않고** 기본 서식으로 넣고 사유를 남긴다. 기본 서식은
    빈 문단을 쓰지 않는다 — 현장 템플릿의 빈 줄은 `여백: (5pt)` 같은 간격용이다.
  - 순서는 **서식 적용 → 채우기 → 블록** (`document.build` 한 곳에만 있다). 채우면
    `{…}` 가 사라져 어디에 무슨 서식을 걸지 알 수 없기 때문이다.
  - 검증 규율이 값과 다르다: **내용에는 화이트리스트가 없고**(그게 기능이다) 개수·길이
    상한만, **서식 이름에만** 화이트리스트. 대화는 `blocks`/`block_clears`, 화면은
    `PUT /blocks`(배열 통째 교체 — 인덱스 어긋남으로 엉뚱한 문단을 지우지 않게).
  - **세션 저장은 덮어쓰기라** 값만 저장하면 블록이 지워진다 → 저장 경로가 항상 블록을
    함께 넘긴다.
  - **`FieldSpec`/색인 구조를 바꾸면 `template_index.SCHEMA_VERSION` 을, 세션 모양을
    바꾸면 `session_store._STATE_VERSION` 을 올린다.** 낮은 버전 세션은 버리지 않고
    기본값으로 흡수한다 — 버리면 배포 시점 진행 중인 대화가 초기화된다.
- **본문 블록은 글다듬이 서빙을 불러 다듬는다** (`polish_client.py`, `/chat/commit` 안).
  006 안에 톤 변환을 따로 만들면 톤 프리셋 표가 한 벌 더 늘어 같은 톤이 기능마다 다른
  문체를 낸다. **항목 값은 다듬지 않는다**(사용자가 말한 그대로). 다듬기 실패는 오류가
  아니고 원문을 넣는다. **숫자·날짜가 바뀌면 원문을 쓴다**(`value_guard.fact_diff`) —
  hwpx 에 그대로 박히는 값이라 되돌릴 수 없다. 템플릿별 톤·문서유형은
  `TEMPLATE_FILL_POLISH_MAP`(`템플릿=톤/문서유형`), 템플릿별 문체 지시문은
  `polish_instruction__<템플릿>.txt`(없는 것이 정상)다.
- 멀티턴 상태는 **Redis 세션 저장소** (`session_store.py`) — GenOS 는 이전 대화를
  자동 주입하지 않는다. 대화·화면·다운로드 경로가 같은 `REDIS_URL` 을 보면 되고
  세션 전용 공유 볼륨은 필요 없다(템플릿 파일 볼륨은 공유해야 한다).
  Redis 클라이언트는 `redis_client.py` 하나를 공유한다 — 모듈마다 `from_url` 을 부르면
  연결 풀이 그만큼 늘어난다.
- **템플릿 파싱은 `template_index.py` 캐시를 경유한다** (등록 시점 1회 파싱).
  무효화는 캐시 값 대조로 한다 — 내용 해시·`SCHEMA_VERSION`·`SLOT_FIELDS`.
  **슬롯 인식 규칙이나 `FieldSpec` 을 고치면 `SCHEMA_VERSION` 을 올려야 한다.**
  Redis 장애 시엔 직접 파싱으로 degrade 한다 (캐시는 성능 장치일 뿐이다).
- **미리보기(`hwpx_markdown.py`, `GET /preview`)는 다운로드와 같은 채우기 경로**를 탄다.
  별도 렌더러를 두면 화면과 파일이 어긋난다. 표는 `cellAddr` 좌표로 격자를 만든다
  (병합 셀은 앵커만 존재 — 순서대로 채우면 열이 밀린다).
- **산출은 hwpx 하나다.** 그래서 이 단위는 기본 이미지에 아무것도 요구하지 않는다
  (`genon.preprocessor` 같은 pip 불가 의존이 없다). **다른 형식 이름(`format=pdf`)은
  400 이다** — 조용히 hwpx 를 내려주면 화면은 PDF 를 받았다고 믿는데 파일은 hwpx 인
  상태가 되고 그 어긋남은 아무 기록도 남기지 않는다(FAQ 의 형식 거절과 같은 판단).
  `check_api_contract.py` 가 그 판정을 본다.
- 대화(area 02, 워크플로우 스텝 → `/chat/*`)와 파일 생성(area 03, `main.py` `/generate`)은
  별개 영역이다. 다 채운 턴에는 커밋이 파일을 굳혀 `download_url` 을 내고, 못 올렸으면
  `POST /generate` 가 폴백이다.
- 관리자 등록(`POST /templates`)은 **파싱을 먼저, 파일 쓰기를 나중에** 한다 —
  순서를 바꾸면 해석 불가 파일이 볼륨에 남는다. `TEMPLATE_FILL_ADMIN_TOKEN` 미설정 시
  등록·삭제가 인증 없이 열리며, 그 사실을 기동 로그 경고로 노출한다.

## 업로드 문서 자동 채움

### 업로드 문서로 **알아서 채운다**

템플릿을 고르고 대화로 채우는 흐름에, **문서를 올리면 그 내용으로 빈 항목을 자동으로
채우는** 경로가 붙어 있다. 사용자가 이미 가진 문서(사업계획서·회의록)를 사내 양식에
옮겨 적는 것이 실제 업무이기 때문이다.

문서는 캔버스 변수 **`genosUploaded`**(전처리기 산출물)로 온다 — FAQ·번역 스텝 1 이 쓰는
그 경로다. 스텝 1 이 문서 원문을 뽑아 넘기고, **스텝 3 이 답변을 흘리기 전에
`POST /chat/prefill/stream` 을 부른다** — 소켓에 흘릴 수 있는 것은 마지막 스텝뿐이라
조각을 확인하는 동안 화면이 비지 않게 하려면 그 자리라야 한다. 스텝은 3개 그대로다
(넷으로 만들면 캔버스 등록을 다시 해야 하고, 문서 없는 대화에서는 아무 일도 하지 않는
스텝이 하나 늘어난다).

- **문서를 발화(`question`) 자리에 넣지 않는다.** 세 자리에서 깨진다: ① `chat_api` 가
  발화를 `MAX_MESSAGE_CHARS`(2만 자)에서 **조용히 자른다** — 사업계획서는 그 길이를 넘고
  뒷부분 값은 없는 것이 된다. ② `extract_system.txt` 는 "이번 턴 사용자가 말한 것" 만
  담으라는 지시문이라 문서를 그 자리에 넣으면 **지움 지시·본문 추가 의도를 문서
  문장에서 찾아내려 든다.** ③ 덮어쓰기 방향이 반대다(아래).
- **대화 도중 언제든, 여러 번 올릴 수 있다** (아래 "중간에 올려도 남은 자리만").
- **사용자 값을 덮지 않는다** (요구 확정). 빈 항목만 채운다. 두 층으로 막는다 —
  프롬프트에서 채워진 항목을 아예 빼고(`_pending_specs`), 그래도 온 값은 버리고 건수를
  센다(`conflicts`). 프롬프트 지시를 보장으로 보지 않는 §5 규약 그대로다.
  **커밋에서 한 번 더** 본다(값이 HTTP 경계를 건너왔다).
- **같은 턴 발화가 문서를 이긴다.** 커밋이 **문서분을 먼저, 발화분을 나중에** 병합한다.
  순서를 뒤집으면 "이 문서로 채우고 제목은 A 로" 가 문서의 제목으로 되돌아간다.
- **긴 문서는 조각으로 나눈다**(`DOC_CHUNK_CHARS` 12,000 · `DOC_MAX_CHUNKS` 20).
  **앞 조각이 이긴다** — 문서 앞쪽(표지·개요)이 값을 정면으로 적어 둔다. 그리고 **항목이
  다 채워지면 남은 조각을 부르지 않는다**: 조각 수가 곧 LLM 비용이 되지 않게 하는 유일한
  장치다(40조각 문서에서 항목이 첫 조각에 다 있으면 호출은 1회다).
- **실패는 오류가 아니다.** 자동 채움이 실패해도 예외를 올리지 않는다 — 사용자가 원래
  하려던 일(대화로 채우기)이 막히면 **템플릿 채우기 자체가 안 되는 것으로** 보인다.
  대신 `prefill_failed` 를 답변에 한 줄 싣는다(조용히 넘기면 "문서를 올렸는데 아무 일도
  일어나지 않았다" 가 된다).
- **값의 진위는 코드가 판정하지 않는다** (요구 확정 — FAQ 의 근거 대조 같은 층이 없다).
  항목명 화이트리스트는 이름만 막는다. 그래서 **채운 값을 답변에 전부 나열**한다 —
  006 은 전용 UI 가 없어 **대화가 곧 화면**이고, 그것이 사용자가 잘못된 값을 발견해 그
  자리에서 고칠 수 있는 유일한 수단이다. 건수만 말하면 문서를 열어 하나하나 대조해야 한다.
- **`TEMPLATE_FILL_DOC_PREFILL=0`** 으로 끌 수 있다.
- **그물**: `Test/SFR-006/tests/test_doc_prefill.py`(조각 분할 무손실·덮어쓰기 금지·앞
  조각 우선·조기 종료·화이트리스트·설정 부재·빈 응답은 실패가 아니다), `check_chat_turn`
  (스텝 3개 체인 — 채움·발화 우선·표식·재주입 금지).
  - **LLM 대역은 `from .llm import` 로 이름을 복사한 모든 모듈에 꽂아야 한다** —
    `chat_api.llm_call_async` 와 `doc_prefill.llm_call_async`/`llm_stream_async` 가 따로다.
    한쪽만 꽂으면 자동 채움 경로가 **진짜 게이트웨이를 부르려 들고**, 실패가 fail-open
    이라 점검이 통과해 버린다.

### 중간에 올려도 **남은 자리만** 채운다

**대화 도중 언제든 파일을 올릴 수 있고, 파일이 여러 번 올 수 있다.** 이미 채운 내용은
밀지 않고 **남아 있는 중괄호만** 그 파일로 채운다. "빈 항목만 채운다" 는 두 층
(`_pending_specs` 로 프롬프트에서 빼고, 그래도 오면 `conflicts` 로 버린다)이 지고,
게이트(`chat_api._prefill_gate`)에는 턴 번호 조건이 없다.

- **표식은 목록이다** (`source_doc_hashes`, 세션 `_STATE_VERSION` 3). 하나만 들면 **두
  번째 문서를 태운 순간 첫 문서를 잊고**, 캔버스가 둘을 계속 실어 올 때 번갈아 가며 다시
  태운다 — 지운 값이 되살아나는 결함이 **파일이 둘일 때만** 나타나는 형태로 남는다.
  커밋은 덮는 것이 아니라 **더한다**(`_merged_doc_hashes`).
  - **버전 2 세션(문자열 하나)은 버리지 않고 흡수한다** — 버리면 배포 시점에 진행 중이던
    대화가 다음 턴에 같은 문서를 다시 태운다(`blocks` 를 흡수하는 것과 같은 규율).
  - **상한 20, 오래된 것부터 버린다.** 없으면 긴 대화에서 세션 페이로드가 단조 증가한다.
    버려진 문서가 다시 오면 자동 채움이 한 번 더 돌 뿐이고 값은 안 밀린다.
  - **본문은 세션에 담지 않는다**(3.8절). 자동 채움은 그 턴에 끝나 뒤에서 볼 일이 없다.
- **빈 항목이 없으면 LLM 을 안 부르고, 그 사실을 답변이 말한다**(`no_pending_fields`).
  **항목을 다 채운 뒤 파일을 올리는 것도 정상 흐름**이라, 조용히 넘기면 "올렸는데
  아무 일도 일어나지 않았다" 가 된다(`prefill_failed` 를 안내하는 것과 같은 이유).
  이 안내가 **한 번만** 나가는 것은 그 턴에 해시를 기록하기 때문이다 — 판정 순서가
  `already_applied` **먼저**라야 성립한다.
- **경계를 건너는 것은 이번 턴 해시 하나**이고 목록은 세션에만 있다. 스텝이 목록을 들고
  다니면 그것이 곧 세션 사본이 되고 두 벌이 갈린다.
- **"무엇이 부족한가" 는 한 함수다** — `doc_prefill._pending_specs` 가
  `missing_field_names` 를 쓴다. 조건을 두 곳에 적으면 "채울 자리가 없다며 건너뛰는데
  정작 빈 항목이 남은" 상태가 생긴다.
- 게이트를 없애도 호출 수는 그대로다(`doc_prefill` 이 `pending` 이 비면 첫 조각에서
  멈춘다 — 층이 둘이다). 게이트가 실제로 지키는 것은 **안내문**이다.

### 항목이 **닫히는 대로** 흘린다 — `/chat/prefill/stream`

응답을 토큰으로 받아 `"항목명": 값` 쌍이 닫힐 때마다 `✔ 항목: 값` 한 줄을 흘린다.
**총 시간은 같다** — 기다리는 동안 화면이 비지 않을 뿐이다.

- **흘리는 판정과 채택하는 판정이 같다.** `_stream_chunk` 가 닫힌 쌍 하나를
  `{"updates": {…}}` 로 감싸 `parse_updates` 에 태우고, 사용자 값·앞 조각 값(`blocked`)은
  흘리지 않는다. 최종 채택은 **응답 전체로 한 번 더** 판정한다. 조건이 갈리면 화면에 나간
  줄과 실제로 채운 값이 어긋나고, 그 어긋남은 오류로 드러나지 않는다.
- **닫혔다는 것은 값 뒤에 `,` 나 `}` 가 왔다는 뜻이다**(`_UpdatesScanner`). 숫자 `12` 는
  다음 델타에서 `123` 이 될 수 있다. 모양이 어긋나면 더 꺼내지 않고 멈춘다 — 놓친 쌍은
  `done` 이 대신 말하므로 진행 줄만 늦게 나온다.
- **`done` 은 흘리지 못한 항목만 말한다**(`announced` 와 최종값이 같은 항목은 뺀다).
  비스트리밍으로 돌아간 배포에서는 `done` 이 전부를 말한다.
- **흘린 뒤 끊기면 반영하지 않았다고 밝힌다**(`failed` + `discarded`). 안 밝히면 사용자는
  화면에 나간 값이 채워졌다고 믿는다. 첫 델타 뒤에는 **재시도하지 않는다** — 다시 부르면
  같은 줄이 두 번 나온다.
- **스트리밍을 안 받는 배포**(400·415·422·501)는 `STREAM_UNSUPPORTED` 로 갈라 비스트리밍으로
  돌아가고, **남은 조각도 다시 묻지 않는다.** 200 인데 SSE 가 아니면 본문을 한 덩어리로 흘린다.
- 스트리밍은 `on_progress` 가 있을 때만 쓴다 — `/chat/prefill`(비스트리밍)은 그대로다.
- **조각별 소요 시간**을 남긴다(`event=prefill_chunk_done`, `duration_ms`·`item_count`=흘린
  항목 수·`status=chunk=i/n ok= stream=`). 느린 것이 입력 쪽인지 출력 쪽인지 가르는 값이다.

### "문서 내용으로 바꿔줘" — **명시할 때만** 덮는다

기본은 끝까지 빈 항목만이다. 사용자가 올린 문서의 내용으로 바꾸라고 **명시한 턴**에만 찬
항목도 문서 값으로 바꾼다. 같은 턴 발화 값이 문서를 이기는 순서는 그대로다.

- **판정은 추출 LLM 이 하고 경로는 플래그 하나다.** `extract_system` 이 `"use_document": true`
  를 내면 `ParsedIntent.use_document` → `/chat/extract` 응답 → 스텝 2 → 스텝 3 이
  `/chat/prefill(/stream)` 에 `overwrite`, `/chat/commit` 에 `prefill_overwrite` 로 싣는다.
  **불리언 `true` 만 참이다** — `"true"` 문자열을 읽으면 시키지 않은 덮어쓰기가 된다.
  "참고해줘" 는 덮어쓰기가 아니다(프롬프트가 가른다).
- **게이트 둘을 건너뛴다**(`chat_api._prefill_gate`). 캔버스는 같은 첨부를 매 턴 실어
  오므로 이 요청은 대개 **이미 태운 문서**(`already_applied`)·**다 찬 항목**
  (`no_pending_fields`) 위에서 나온다. 두 라우트가 이 함수 하나를 탄다.
- **보호 목록은 `doc_prefill` 의 `protected` 하나다.** 묻는 항목(`_pending_specs`)·흘리는
  항목(`blocked`)·버리는 값(`conflicts`)이 모두 그것을 본다 — 하나만 `existing` 을 보면
  흘린 줄과 채운 값이 갈린다. 앞 조각 우선은 덮어쓰기에서도 그대로다.
- **커밋도 한 번 더 본다.** `prefill_overwrite` 가 없으면 "이미 값이 있다" 며 서빙이
  뽑은 값을 버린다. 화이트리스트는 덮어쓰기에서도 그대로 건다.
- **답변은 무엇이 밀렸는지 말한다** — 새로 채운 것 / `이전 → 새` 로 바꾼 것을 가르고,
  값이 같았던 항목은 나열하지 않는다. 문서에서 값을 못 찾았어도 한 줄은 낸다.
- **문서 없이 바꾸라고 하면** 스텝 3 이 서빙을 부르지 않고 `prefill_skipped_reason=
  no_document` 를 커밋에 넘기고, 답변이 문서를 올려 달라고 말한다.
- 덮어쓰기 턴도 해시를 기록한다 — 바꾸라는 말이 없는 다음 턴에는 같은 문서를 다시 안 태운다.
- **그물**: `test_field_judge`·`test_doc_prefill`, `check_chat_turn`(같은 문서·다 찬
  항목에서 도는가 · 발화 우선 · `이전 → 새` · 다음 턴 재주입 금지 · 문서 없음 안내).
  게이트 우회를 빼면 앞의 넷이 FAIL 한다.
