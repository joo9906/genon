## 조사 결과
- **lxml 도달 경로는 좁았다.** FAQ·번역은 각각 **hwpx 업로드 라우트 하나**
  (`POST /generate/upload` · `POST /translate/hwpx`), 006 은 hwpx 모듈 넷,
  **글다듬이는 처음부터 lxml 을 안 쓴다**(마크다운 텍스트만 다룬다).
- **쓰는 lxml API 는 다섯뿐**(`fromstring`·`SubElement`·`XMLSyntaxError`·`tostring`·
  `getparent()`). 표준 `xml.etree.ElementTree` 에 없는 것은 **`getparent()` 하나**다.
- 그래서 **읽기는 통째로 표준 라이브러리로 옮길 수 있고**, `tostring`(되쓰기)만 포기하면 된다.

## 결정 사항 (되묻지 말 것)
- **`onprem/` 은 건드리지 않는다.** `not/` 은 한시 판본이고 정본은 계속 `onprem/` 이다.
- **006 의 hwpx 되쓰기는 포기한다.** 표준 ElementTree 로 재직렬화하면 네임스페이스
  접두어가 `ns0:` 로 나가 **한/글이 못 여는 파일**이 되고, 예외 없이 산출물만 깨진다.
- **`getparent()` 는 부모 맵(`xml_compat.py`)으로 바꾼다.** lxml 프록시 id 함정이
  여기서는 없어진다 — ElementTree 는 트리가 요소를 직접 들고 있다.
- **`format=hwpx` 를 400 으로 막지 않는다.** 캔버스가 그 값을 보내므로 막으면 다운로드가
  통째로 죽고, 파일이 확장자·헤더로 스스로를 밝히므로 오해가 생기지 않는다.
- **글다듬이도 `not/` 에 사본을 둔다** — 고칠 것이 없는데도 두는 이유는 **네 단위를 한
  자리에서 올리기 위해서**다. 점검이 정본과 바이트까지 대조한다(판본 표시 docstring 제외).

## 밟은 것 (같은 자리에서 또 헛걸음하지 않게)

1. **Bash 도구의 heredoc 이 백슬래시를 먹는다.** `<<'PY'` 로 따옴표를 씌워도
   `"\n\n"` 을 찾는 치환이 조용히 빗나갔다(파일에는 백슬래시+n, 검색어에는 진짜 개행).
   **정확한 문자열 치환은 heredoc 말고 Edit 로** 한다.
2. **점검이 슬롯 치환의 절반을 안 태우고 있었다.** 실물 `파워.hwpx` 는 슬롯 글자가
   `hp:t` **하나**에 다 들어 있어 "나머지 노드를 비운다"가 실행되지 않는다 — 그 줄을
   지워도 전부 통과했다. **슬롯이 노드 경계를 걸치는 픽스처**를 따로 만들어 해결
   (`_split_slot_text_nodes`). 되돌리면 이제
   `제 목 : 2026년 사업 계획HY헤드라인M, 16pt}` 로 FAIL 한다.
3. **starlette 는 `python_multipart` 를 `except ModuleNotFoundError` 로 흡수한다.**
   점검에서 `ImportError` 를 던지면 그 방어를 지나쳐 **우리 코드와 무관한 자리**에서
   실패한다. 막을 때는 반드시 `ModuleNotFoundError` 를 던진다.
4. **네 단위를 한 프로세스에서 태우면 모듈이 섞인다.** 번역·글다듬이는 진입점이 둘 다
   단위 루트의 `main.py` 라 `sys.modules["main"]` 을 놓고 다투고 `config`·`api_contract`
   도 겹친다. 안 비우면 **두 번째 단위가 첫 번째의 모듈을 그대로 쓰고 통과한다**
   (라우트 목록이 앞 단위 것이라 오히려 그럴듯해 보인다).

### `not/minio.py` — 참조본이지 우리 코드가 아니다

GenOS 에서 받은 **동작하는 MCP 예제**다. 이걸로 `download_url` 의 모양을 확인했다:
업로드 URL · 멀티파트 필드(`hostname`+`file`) · 응답 경로(`data.presigned_url`) —
**넷 다 우리 `file_store.py` 와 같다.** 즉 링크 모양은 이제 추측이 아니다.

**등록하지 말 것.** `mcp` 전역을 shim 없이 쓰고, import 하는 순간 `ensure_packages()` 가
`pip install python-docx` 를 실행한다(가이드 p.19 금지사항).

## 꾸러미로 묶었다 — `submit/` (2026-09-08, 이 작업의 현재 끝)

폐쇄망에는 **메일로 보낸다.** `python make_submit.py` 가 `submit/` 을 다시 만든다 —
**저장소 배치를 그대로 옮기므로** 받은 쪽에서 `python onprem/test/check_*.py` 가 경로
손질 없이 그대로 돈다. 옮겨 놓고 점검을 못 돌리면 무엇이 빠졌는지 알 방법이 없다.

- **손으로 쓴 문서 둘은 스크립트가 만들지 않는다** — `submit/README.md`(반입 절차 정본:
  등록 10번·환경변수·점검 실행)와 `submit/IO_FORMAT.md`(네 경계의 입출력 JSON).
  재생성할 때 살려 두고 나머지만 덮는다.
- **`not/README.md` 는 이 꾸러미 안에서 `submit/not/README.md` 로 실린다.** 그래서 §4 에
  "절차의 정본은 위 안내서" 라는 줄을 넣었다 — 안 넣으면 받은 사람이 이 파일만 보고
  등록 순서를 여기서 찾는다.
- **빠진 경로가 있으면 종료 코드 1 로 세운다.** 그전에는 `없음(건너뜀)` 한 줄로 넘기고
  성공으로 끝냈고, 그래서 `_TREE` 의 **쉼표 하나가 빠져** 두 경로가 한 문자열로 붙었을 때
  **MCP 디렉토리가 통째로 빠진 채 "완성"** 됐다. 메일을 보내고 나서야 드러난다.
- **`_FILES` 에 루트 `README.md` 를 넣지 말 것** — 한 번 그렇게 해서 366줄짜리 꾸러미
  안내서를 덮었다. 살리는 코드와 덮는 코드가 같은 함수 안에 있어 눈에 안 띈다.
