# `not/` — **반입 판본** 작업 진행 기록

> 세션이 끊기면 **이 파일부터 읽는다.** 결과물 설명은 `not/README.md` 가 정본이고,
> 여기는 "무엇을 왜 그렇게 했나 / 어디까지 했나 / 어디서 헛걸음했나" 만 남긴다.

최종 갱신: 2026-09-09

---

## 0. 지금 이 판본이 무엇인가 (2026-09-09 요구 변경으로 성격이 바뀌었다)

**`not/` 은 폐쇄망에 실제로 반입하는 판본이다.** 그전에는 "`lxml` 이 없어 깎아낸 한시
판본" 이었는데, **`lxml`·`openai` 가 사내 mirror 에 들어와** 깎아낼 이유가 없어졌다.
그래서 방향이 뒤집혔다 — **가장 고도화된 판본**으로 올린다.

| | 그전 (2026-09-08) | 지금 |
|---|---|---|
| 성격 | lxml 없이 깎아낸 한시 판본 | **반입 판본. 기능 최대** |
| LLM 전송 | `httpx` 직접 (정본과 같다) | **`openai` SDK** (`AsyncOpenAI`) |
| hwpx 되쓰기(006) | 안 한다 → 산출물 `.txt` | **한다** → `.hwpx` |
| hwpx 직접 업로드 | 006 만 | **번역·FAQ·006 셋 다** |
| 번역 스트리밍 | 없다 | **있다** (`/translate/stream` + `/translate/finalize`) |
| FAQ 스트리밍 | 없다 | **있다** (`/generate/stream`) |
| 글다듬이 스트리밍 | 있다 | 있다 (`/polish/stream`) |

**정본은 계속 `onprem/codeserving/` 이다.** 기능 설계를 여기서 새로 정하지 않는다 —
이 판본은 정본 + 전송 계층 교체 + 스트리밍 셋이다.

## 요구 (2026-09-09)

1. `lxml` 이 가능해졌으니 **lxml 관련 기능 전부 복원**한다.
2. LLM 호출은 **`openai` SDK** 로 간다 (mirror 에 `openai` 도 들어왔다).
3. **스트리밍을 다 넣는다** — 글다듬이·번역·FAQ.
4. 반입 대상은 `not/` 이다. **`submit/` 재생성은 하지 않는다** (요구에서 제외).
5. 문서를 최신화한다.

## 결정 사항 (되묻지 말 것)

- **`not/openai/` 를 `not/` 으로 흡수한다.** 그 판본이 이미 "정본 + SDK + lxml + 번역
  스트리밍" 이었으므로, `not/` 의 네 단위를 그것으로 **교체**하는 것이 가장 짧고 안전한
  경로다. 깎아낸 코드를 되살려 붙이면 정본과 갈릴 자리가 새로 생긴다.
- **`not/openai/` 는 지우지 않고 `archive/not_openai_absorbed/` 로 옮겼다.** `not/` 전체가
  **git 미추적**이라 지우면 복구할 수 없고, 그렇다고 `not/` 안에 near-duplicate 를 남기면
  **반입 표면이 헷갈린다**(손으로 타이핑해 옮기는 판본이다). 보관본 README 에 무슨 일이
  있었는지 적어 뒀다. (교체 전 백업: 세션 스크래치패드의 `not_before_merge.tgz`)
- **FAQ 스트리밍 라우트 이름은 `POST /generate/stream`** 이다. `not/openai/PROGRESS.md`
  가 계획할 때 적어 둔 `POST /faq/stream` 이 아니다 — 이 단위의 기존 라우트가
  `/generate`·`/generate/upload` 라 거기에 붙인다.
- **비스트리밍 경로를 지우지 않는다.** 게이트웨이가 `stream=True` 를 받는지 폐쇄망에서
  확인되지 않았다. 스트리밍이 막히면 서빙이 그 자리에서 비스트리밍으로 되돌아간다.
- **payload 조립을 한 함수로 모은다.** 스트리밍·비스트리밍이 각자 조립하면 `markdown`·
  `download_url`·세션 저장이 한쪽에만 붙는 드리프트가 생긴다.

## 밟은 것 (같은 자리에서 또 헛걸음하지 않게)

1. **`not/openai/` 의 FAQ 스트리밍은 엔진만 있었다.** `markdown_items.py`(증분 파서)·
   `faq_stream_async`·`generate_faqs_stream` 이 다 있는데 **`main.py` 가 import 조차
   하지 않아 호출부 0건**이었다 — 즉 HTTP 로 도달 불가. 그 판본의 점검은 오히려
   "FAQ 는 스트리밍이 없다" 를 기대해 **FAIL 1건**으로 남아 있었다(점검 14:38, 기능
   14:51~14:55 — **그물이 기능보다 먼저 굳은** 자리다).
2. **`not/` 전체가 git 미추적이다.** `git status --short` 의 `??` 41건 중 하나가
   `not/` 이라, 교체 전에 백업하지 않으면 lxml 없는 판본이 영구 소실된다.
3. **payload 를 두 곳에서 조립하면 갈린다.** 비스트리밍 `_generate_and_store` 가
   `markdown`·`download_url`·`download_ready`·세션 저장을 하는데, 스트리밍 라우트를
   따로 조립하게 두면 그 넷 중 하나가 빠져도 **오류 없이 화면에서만** 드러난다.
   `_store_and_payload(result, ...)` 하나로 모았다.
4. **`heredoc` 으로 코드를 쓰면 백슬래시를 먹는다** (이 파일에 이미 적혀 있던 함정을
   그대로 다시 밟았다). 그물에 절을 끼우는 변환 스크립트를 heredoc 으로 넘겼더니
   `\\n` 이 어긋나 셸이 EOF 로 죽었다 — **파일로 쓰고 실행**하면 된다.
5. **파서와 채택 층을 헷갈렸다.** 처음 판정을 "미완성 묶음은 `_parse_faq_payload` 가
   버린다" 로 썼는데 FAIL 했다 — 그 파서는 **일부러 관용적**이고(모델이 `>>>` 를
   빠뜨리는 일이 흔하다) 버리는 판정은 `_adopt_one` 에 있다. 판정을 그 자리로 옮겼고,
   헷갈리기 쉬운 자리라 `markdown_items.py` 머리말에도 절을 하나 넣었다.

## 남은 것 / 폐쇄망에서 확인할 것

- **게이트웨이가 `stream=True` 를 받는지** — 안 받으면 세 스트리밍 경로가 각자
  비스트리밍으로 되돌아간다(설계된 폴백). 되돌아간 사실은 응답의 `stream_fallback` ·
  로그 `*_stream_fallback` 으로 드러난다.
- **중간 프록시가 SSE 를 모아 보내지 않는지** — 모으면 "한방에" 로만 보이고 오류가
  없다. 그래서 세 경로 모두 `X-Accel-Buffering: no` 를 실어 둔다.
- **`openai` SDK 경로가 실제로 뜨는지** — 정본이 2026-09-07 에 SDK 를 걷어낸 이유가
  "실환경에서 SDK 때문에 호출이 실패했다" 였다. 그 실패가 SDK 자체 문제였는지 그때의
  배선 문제였는지는 **가려지지 않았다.** 되돌릴 자리는 **네 `llm.py` 뿐**이다
  (`onprem/codeserving/*/llm.py` 를 옮겨 적고 `requirements.txt` 에서 `openai` 를 뺀다).
- **`model` 값을 게이트웨이가 어떻게 다루는지** — SDK 는 `model` 없이 요청을 만들지
  않아 `LLM_MODEL_ID`(기본 `"default"`)를 싣는다. 정본은 싣지 않는다.
- **006 다운로드가 hwpx 로 나가는 것** — 이제 정본과 같다(그전 이 판본만 txt 였다).
- **MinIO 링크**(`file_store.py` 사본 4벌) — 폐쇄망에서 업로드가 되는지. 안 되면
  `download_url` 이 빈 값이고 옛 `POST /download` 폴백이 그대로 산다.
- **MCP 넷·전처리기 2벌·워크플로우 스텝 9개는 이 판본과 무관하다** — 표준 라이브러리만
  쓴다. 바꾸는 것은 **코드 서빙 네 단위**뿐이다.
